# 语迹 V0.23 开源前工程结构整理与目录分离

状态：已实施

日期：2026-06-22

## 1. 修改目标

V0.23 的目标不是增加新功能，而是把当前 V0.22 整理成更适合开源、也更适合后续 Git 管理的目录结构。

需要实现：

```text
CodexChatIndex 目录只放技术源码。
本机运行数据和外部聊天记录放到 CodexChatIndex 目录外。
CodexChatIndex.html 改为构建产物，放到 temp 目录。
Open-CodexChatIndex.cmd 负责首次启动时自动准备必要目录。
目录结构调整后，软件仍然可以直接运行，不影响当前使用。
CodexChatIndex 目录自身拷出去后应尽可能能独立使用。
CodexChatIndex 目录内不放任何敏感信息。
CodexChatIndex 目录内加入版本信息文件，文件名直接体现版本号。
```

本版本重点是工程结构治理，不改业务功能，不改界面语义，不改搜索、备注、刷新、导出等既有行为。

## 2. 当前 V0.22 基础

V0.22 目前已经具备以下特点：

```text
Build-CodexChatIndex.ps1 负责生成 CodexChatIndex.html。
Open-CodexChatIndex.cmd 负责启动 CodexChatIndexServer.py。
CodexChatIndexServer.py 启动时会检查 HTML 和运行数据是否存在，缺失则触发构建。
运行数据和外部聊天记录已经在路径设计上有分离倾向。
HTML 仍放在版本目录中。
测试与脚本里仍有部分本机路径和版本目录路径约束。
```

V0.23 要在这个基础上把目录边界收紧，让源码目录更清晰，更适合后续开源和 Git 仓库化。

## 3. 目标目录结构

建议结构：

```text
软件/
  CodexChatIndex/
    Build-CodexChatIndex.ps1
    Build-CodexChatIndex.cmd
    Open-CodexChatIndex.cmd
    CodexChatIndexServer.py
    templates/
    tests/
    VERSION_V0.23.txt
    temp/

  运行数据/
  外部聊天记录/
  文档/
```

其中：

```text
CodexChatIndex/ 只放源码和版本信息。
temp/ 只放构建产物，例如 CodexChatIndex.html。
运行数据/ 放本机运行时生成的数据。
外部聊天记录/ 放用户手工导入的外部记录。
```

### 3.1 本次 V0.22 到 V0.23 的迁移方式

本次是第一次从旧的版本目录结构切到新的开源源码目录结构。

建议按下面方式处理：

```text
保留 软件版本_V0.22 作为历史版本和回滚点。
新建 CodexChatIndex 目录作为 V0.23 之后的主源码目录。
从 软件版本_V0.22 迁移源码文件到 CodexChatIndex。
不要把旧的 CodexChatIndex.html 作为源码迁移到 CodexChatIndex 根目录。
V0.23 验证通过后，日常使用入口切换到 CodexChatIndex/Open-CodexChatIndex.cmd。
```

本次迁移的源码范围：

```text
Build-CodexChatIndex.ps1
Build-CodexChatIndex.cmd
Open-CodexChatIndex.cmd
CodexChatIndexServer.py
templates/
tests/
```

本次不迁移到 CodexChatIndex 的内容：

```text
CodexChatIndex.html
运行数据/
外部聊天记录/
任何本机路径、缓存、索引、导入聊天记录、临时文件
```

### 3.2 命名规则变化

V0.23 是目录命名规则的分界点。

V0.22 以及更早版本主要使用：

```text
软件版本_V0.XX
```

V0.23 之后主源码目录固定使用：

```text
CodexChatIndex
```

这样做是为了让未来 Git 仓库目录保持固定，不因为每次升版改变仓库根目录。

需要注意：

```text
旧的 软件版本_V0.XX 目录保留为历史版本。
Archieve/ 里已有的旧归档结构继续保留，不在本次统一重命名。
V0.23 之后不要再把当前主程序目录命名为 软件版本_V0.23。
V0.23 之后的当前工作目录始终叫 CodexChatIndex。
以后升版时，先把旧的 CodexChatIndex 归档成带版本号的目录，再新建新的 CodexChatIndex。
```

也就是说，新旧命名会并存一段时间。看目录时要以“是否是当前主源码目录”为准，不要只看是否带版本号。

## 4. 目录职责

### 4.1 CodexChatIndex

职责：

```text
作为开源源码目录。
可独立复制使用。
不放本机运行数据。
不放外部聊天记录。
不放任何敏感信息。
```

### 4.2 temp

职责：

```text
只放构建产物。
例如 CodexChatIndex.html。
不放业务数据。
不放聊天记录。
不放版本仓库文件。
```

### 4.3 运行数据

职责：

```text
保存本机运行时生成的数据。
例如索引、缓存、详情、状态、备注等。
```

### 4.4 外部聊天记录

职责：

```text
保存外部导入的聊天记录源文件。
只作为数据输入，不作为源码。
```

## 5. 启动与构建规则

### 5.1 首次启动

Open-CodexChatIndex.cmd 启动时应先检查必要目录。

如果 temp 里的 HTML 不存在，则自动触发构建。

Open-CodexChatIndex.cmd 至少要保证这些目录存在：

```text
CodexChatIndex/temp
软件/运行数据
软件/外部聊天记录
```

这里有一个必须同步处理的路径关系：

```text
CodexChatIndexServer.py 里的 HTML_FILE 要指向 temp/CodexChatIndex.html。
CodexChatIndexServer.py 里的 run_build 调用 Build-CodexChatIndex.ps1 时，也要确保 -OutputPath 指向同一个 temp/CodexChatIndex.html。
Build-CodexChatIndex.ps1 自身的默认 OutputPath 也不能继续默认到源码目录下的 CodexChatIndex.html。
Build-CodexChatIndex.cmd 作为 ps1 的包装入口，也要确认直接运行时输出到 temp/CodexChatIndex.html。
```

建议实现方式：

```text
run_build 显式传入 -OutputPath HTML_FILE。
Build-CodexChatIndex.ps1 的默认 OutputPath 也同步改为 temp/CodexChatIndex.html，避免单独运行脚本时仍生成到源码目录。
Build-CodexChatIndex.cmd 要么显式传入 -OutputPath temp/CodexChatIndex.html，要么确认它依赖的 ps1 默认值已经改为 temp/CodexChatIndex.html。
```

### 5.2 后续启动

如果产物已存在，则可直接复用，不必每次都重新构建。

### 5.3 刷新行为

刷新时继续走构建流程，但输出位置仍然保持在 temp。

### 5.4 页面入口与静态文件路由

CodexChatIndex.html 移到 temp 后，服务端入口路径和静态文件路由也要一起确认。

需要确认：

```text
浏览器打开根路径时，仍然能进入 temp/CodexChatIndex.html。
旧的 /CodexChatIndex.html 访问方式如果继续保留，也要正确转到新的 temp 路径。
服务器复用检测、首次启动检测、刷新后的打开地址，都要使用同一份 HTML_FILE。
```

## 6. 具体修改清单

本节不是最终代码，只记录实施时必须覆盖的修改点。

### 6.1 Build-CodexChatIndex.ps1

当前 V0.22 默认输出位置是：

```powershell
$OutputPath = Join-Path $PSScriptRoot 'CodexChatIndex.html'
```

V0.23 应改为默认输出到 temp：

```powershell
$OutputPath = Join-Path (Join-Path $PSScriptRoot 'temp') 'CodexChatIndex.html'
```

这样直接运行 ps1 时，不会把构建产物生成到源码根目录。

### 6.2 Build-CodexChatIndex.cmd

当前 V0.22 的 cmd 包装脚本只传了 DataRoot：

```bat
pwsh -NoProfile -ExecutionPolicy Bypass -File "%~dp0Build-CodexChatIndex.ps1" -DataRoot "%~dp0..\运行数据" %*
```

V0.23 要确认直接运行 cmd 时，输出仍然进入 temp。

可选方式一，依赖 ps1 的默认 OutputPath：

```bat
pwsh -NoProfile -ExecutionPolicy Bypass -File "%~dp0Build-CodexChatIndex.ps1" -DataRoot "%~dp0..\运行数据" %*
```

可选方式二，cmd 显式指定 OutputPath：

```bat
pwsh -NoProfile -ExecutionPolicy Bypass -File "%~dp0Build-CodexChatIndex.ps1" -DataRoot "%~dp0..\运行数据" -OutputPath "%~dp0temp\CodexChatIndex.html" %*
```

如果选择方式二，以后通过 cmd 再额外传入自定义 -OutputPath 时，要注意不要重复传同一个参数。

### 6.3 CodexChatIndexServer.py 顶部路径

当前 V0.22：

```python
HTML_FILE = ROOT / "CodexChatIndex.html"
ENTRY_PATH = f"/{ROOT.name}/{HTML_FILE.name}"
```

V0.23 应改为类似：

```python
TEMP_DIR = ROOT / "temp"
HTML_FILE = TEMP_DIR / "CodexChatIndex.html"
ENTRY_PATH = f"/{ROOT.name}/temp/{HTML_FILE.name}"
```

这样浏览器入口、首次启动检测、刷新后打开地址都指向同一个 HTML 产物。

### 6.4 CodexChatIndexServer.py 的 run_build

当前 V0.22 的 run_build 调用 ps1 时没有传 -OutputPath。

V0.23 应在 cmd 参数里加入：

```python
"-OutputPath",
str(HTML_FILE),
```

这样 server 触发构建时，不依赖 ps1 默认值，也不会生成到旧位置。

### 6.5 CodexChatIndexServer.py 的页面路由

CodexChatIndex.html 移到 temp 后，需要确认以下逻辑仍然正确：

```text
访问 / 时跳转到 /CodexChatIndex/temp/CodexChatIndex.html。
访问旧的 /CodexChatIndex.html 时，如果保留兼容，应跳转到新的 temp 路径。
has_existing_startup_index 使用新的 HTML_FILE。
main 里打开浏览器的 url 使用新的 ENTRY_PATH。
```

### 6.6 Open-CodexChatIndex.cmd

V0.23 的打开入口要继续启动 server，同时先保证必要目录存在。

需要覆盖：

```text
创建 temp 目录。
创建 ../运行数据 目录。
创建 ../外部聊天记录 目录。
标题版本从 V0.22 更新为 V0.23。
启动 CodexChatIndexServer.py 的路径仍然使用 %~dp0。
```

### 6.7 tests

测试里有多处旧路径假设，需要跟着改。

重点包括：

```text
默认 HTML 输出位置从 projectRoot/CodexChatIndex.html 改成 projectRoot/temp/CodexChatIndex.html。
模拟版本目录名从 软件版本_V0.22 改成 CodexChatIndex。
HTML_FILE 断言改成 ROOT / "temp" / "CodexChatIndex.html"。
ENTRY_PATH 断言改成 /CodexChatIndex/temp/CodexChatIndex.html。
Build-CodexChatIndex.cmd 的断言要覆盖 temp 输出规则或确认 ps1 默认值规则。
```

还要注意相对路径层级变化。

V0.22 时 HTML 位于：

```text
软件版本_V0.22/CodexChatIndex.html
```

V0.23 时 HTML 位于：

```text
CodexChatIndex/temp/CodexChatIndex.html
```

因为 HTML 多了一层 temp，所以从 HTML 指向运行数据的相对路径会多一层 `../`。

测试里需要同步确认：

```text
测试用例 writes default runtime data to the local-codex source directory outside the version directory 要更新。
$versionHtmlPath 从 versionRoot/CodexChatIndex.html 改成 versionRoot/temp/CodexChatIndex.html。
INDEX_URL 断言从 '../运行数据/...' 改成 '../../运行数据/...'。
detailHref 断言从 '^../运行数据/...' 改成 '^../../运行数据/...'。
$sharedDetailPath 也要从 HTML 所在目录计算，而不是继续从 versionRoot 直接拼。
```

这个变化不是手写字符串风格变化，而是 `Build-CodexChatIndex.ps1` 会根据实际 OutputPath 动态计算相对路径。HTML 输出目录变深后，`INDEX_URL`、`detailHref`、详情文件链接等相对引用都会一起变深。

## 10. 升版约定

从 V0.23 开始，如果以后再升版，规则固定为：

```text
当前主源码目录始终叫 CodexChatIndex。
升版前，先把旧的 CodexChatIndex 归档成带版本号的目录。
再新建一个新的 CodexChatIndex 目录。
把升级后的文件放进新的 CodexChatIndex。
```

示例：

```text
当前工作目录：CodexChatIndex
升级到 V0.24 前：把旧的 CodexChatIndex 归档为 CodexChatIndex_V0.23 或放入归档目录。
升级后：新建 CodexChatIndex 作为当前 V0.24 主源码目录。
```
