# 语迹 V0.20 侧栏收起按钮贴近标题与顶部一键收起展开

状态：已实施

日期：2026-06-18

## 1. 修改目标

V0.20 基于 V0.19，做三项小范围交互优化：

```text
目录和标题旁边的单独收起按钮分别紧挨着“目录”和“标题”。
顶部“全量重建”按钮改为“全量”。
顶部“全量”按钮右边新增一个全局“收起/展开”按钮，一键收起目录区和标题区，再一键展开目录区和标题区。
```

本版本定位：

```text
纯界面布局和交互微调。
不改变刷新无变化快速返回逻辑。
不改变来源、搜索、解析、备注、复制、导出、回复框等功能。
```

## 2. 当前 V0.19 基础

V0.19 已实现：

```text
“第一层：目录”已改为“目录”。
“第二层：标题”已改为“标题”。
目录区和标题区可分别收起/展开。
收起后 pane 彻底消失，不保留窄栏。
顶部生成时间已去掉可见“时间：”前缀。
搜索工具栏顺序已调整为：搜索框、搜索范围、显示模式、工具按钮。
普通刷新 Incremental 已支持无变化快速返回。
```

```text
软件\软件版本_V0.19
```

正式实施时复制为：

```text
软件\软件版本_V0.20
```

## 3. 单独收起按钮贴近标题

### 3.1 当前问题

V0.19 中目录区/标题区的收起按钮已经存在，但按钮位置更接近右侧操作区。

用户希望：

```text
目录旁边的收起按钮紧挨着“目录”。
标题旁边的收起按钮紧挨着“标题”。
```

这样按钮语义更直接：

```text
这个按钮就是收起当前这个区。
不是筛选/排序的一部分。
```

### 3.2 V0.20 布局

目录区标题行建议变为：

```text
目录 [收起]                     筛选 排序
```

标题区标题行建议变为：

```text
标题 [收起]                     排序
```

结构建议：

```text
pane-header-row
  pane-title-group
    pane-title
    pane-collapse-btn
  header-actions
    筛选/排序
```

也就是：

```text
收起按钮属于标题组。
筛选/排序仍属于右侧操作组。
```

### 3.3 样式建议

收起按钮保持轻量：

```text
字号略小于标题。
高度不要撑大标题行。
与“目录/标题”的间距控制在 6-8px。
不挤压筛选/排序。
```

推荐文案：

```text
收起
展开
```

原因：

```text
含义清楚。
和顶部全局“收起/展开”保持一致。
不需要用户理解箭头方向。
```

## 4. 顶部“全量重建”改“全量”

### 4.1 修改

将顶部按钮：

```text
全量重建
```

改为：

```text
全量
```

目的：

```text
节省顶部横向空间。
和“刷新”按钮形成更短的操作组。
```

### 4.2 保留完整含义

虽然可见文字改为“全量”，但需要保留：

```text
title="重新扫描和解析全部聊天记录，耗时可能较长"
aria-label="全量重建"
```

这样：

```text
悬停仍能看到完整含义。
辅助技术仍能读出完整含义。
不会让“全量”变得过于含糊。
```

## 5. 顶部新增全局收起/展开按钮

### 5.1 按钮位置

在顶部：

```text
来源  刷新  全量
```

右边新增按钮：

```text
收起 / 展开
```

最终顺序建议：

```text
来源：[本机 Codex]  刷新  全量  收起
来源：[本机 Codex]  刷新  全量  展开
```

### 5.2 按钮语义

按钮只做简单的“一键全部收起/全部展开”。

当目录区和标题区不是全部收起时：

```text
按钮显示：收起
点击后：目录区和标题区都收起。
```

当目录区和标题区都已收起时：

```text
按钮显示：展开
点击后：目录区和标题区都展开。
```

明确不做：

```text
不使用“还原”文案。
不记录点击全局收起之前的历史状态。
不恢复到某个旧的局部收起组合。
```

### 5.3 与单独收起按钮的关系

单独按钮仍然保留：

```text
目录旁边的收起/展开控制目录区。
标题旁边的收起/展开控制标题区。
```

顶部按钮是快捷操作：

```text
一键收起目录和标题。
一键展开目录和标题。
```

如果当前状态是：

```text
目录已收起，标题展开。
```

顶部按钮仍显示：

```text
收起
```

点击后：

```text
目录和标题都收起。
```

如果当前状态是：

```text
目录收起，标题收起。
```

顶部按钮显示：

```text
展开
```

点击后：

```text
目录和标题都展开。
```

### 5.4 保持当前会话位置

点击顶部“展开”时：

```text
只改变目录区和标题区的显示状态。
不切换当前来源。
不切换当前工作目录。
不切换当前标题。
不重新选择会话。
不重置搜索词。
不重置只看提问/全部显示模式。
不改变当前会话正文的滚动位置。
```

实现建议：

```text
展开前记录 transcript.scrollTop。
更新 shell/pane class 后，在 requestAnimationFrame 中恢复 transcript.scrollTop。
```

这样展开目录和标题后：

```text
当前会话仍停留在原来的阅读位置。
```

### 5.5 状态持久化

顶部一键收起/展开应复用 V0.19 的 localStorage 状态：

```text
收起：写入目录=true，标题=true。
展开：写入目录=false，标题=false。
```

不新增历史状态字段。

## 6. 不改变的行为


## 7. 副作用与风险

### 7.1 标题行更拥挤

风险：

```text
收起按钮紧挨“目录/标题”后，标题行左侧会多一个按钮。
目录区右侧还有筛选/排序，横向空间可能变紧。
```

应对：

```text
将“目录/标题 + 收起按钮”作为左侧 title group。
右侧筛选/排序保持原位置。
按钮使用紧凑 padding。
必要时允许筛选/排序保持右对齐，title group 不换行。
```

### 7.2 “全量”含义比“全量重建”弱

风险：

```text
用户可能不知道“全量”就是“全量重建”。
```

应对：

```text
保留 title 和 aria-label。
按钮位置仍在刷新旁边，语义上下文清楚。
```

### 7.3 顶部“收起”和单独“收起”可能混淆

风险：

```text
页面上会同时存在顶部全局收起和侧栏单独收起。
```

应对：

```text
顶部按钮只在顶栏，表示全局操作。
侧栏按钮紧挨“目录/标题”，表示局部操作。
文案一致但位置表达作用范围。
如果后续仍觉得混淆，可将顶部按钮 title 写为“一键收起目录和标题”。
```

### 7.4 展开后布局变化可能导致阅读位置跳动

风险：

```text
展开目录和标题后，会话区宽度变窄，正文重排，scrollTop 相同但视觉位置可能略有变化。
```

应对：

```text
展开前后尽量恢复 transcript.scrollTop。
当前会话、当前提问选中状态、搜索状态都不变。
如果正文因宽度变化导致行高重排，允许极小视觉偏移，但不能跳到顶部或切换会话。
```

### 7.5 localStorage 状态更容易被频繁改写

风险：

```text
顶部按钮一次写两个状态，单独按钮一次写一个状态。
如果实现不统一，可能造成 UI 状态和 localStorage 不一致。
```

应对：

```text
统一使用一个 applySidebarCollapseState 函数。
所有按钮只修改同一个状态对象。
渲染按钮文案时从同一个状态对象读取。
```
