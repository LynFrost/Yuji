# Open-CodexChatIndex V0.17 语迹品牌搜索上下文与本机 Claude 来源优化

状态：已实施

日期：2026-06-15

## 1. 修改目标

V0.17 的目标是在 V0.16 多来源架构基础上，完成四类优化：

```text
将可见软件名改为“语迹”，副标题为“AI 对话记录浏览器”。
优化搜索结果显示：回答、过程、工具命中时，同时展示对应的上一个提问作为上下文。
新增搜索范围切换：搜索当前来源下全部会话，或只搜索当前打开会话。
新增来源“本机 Claude”，把 Claude Code CLI 和 Claude Code Desktop 的本机聊天记录纳入浏览。
解决偶发 Markdown 加粗渲染失败问题。
```

本版本仍然保持：

```text
来源切换影响显示范围。
不同来源的数据、缓存、搜索索引、详情文件、备注互相隔离。
不提供跨来源合并显示。
不提供跨来源搜索。
不改运行数据目录的共享原则。
文档确认前不执行实现。
```

## 2. 当前 V0.16 基础

V0.16 已实现：

```text
来源下拉菜单。
本机 Codex 来源 local-codex。
外部 Codex JSONL 来源 external-codex-jsonl。
按 sourceId 隔离 data/search/cache/detail/notes。
搜索接口 /api/search?sourceId=...&q=...
刷新、全量重建、快刷按 sourceId 执行。
外部来源禁用 SESSION 和回复框复制发送。
过程和工具内容懒渲染。
```

V0.17 应基于：

```text
软件\软件版本_V0.16
```

正式实施时建议复制为：

```text
软件\软件版本_V0.17
```

```text

原因：

```

## 4. 搜索结果展示对应提问

### 4.1 当前问题

当前会话搜索只按事件本身过滤：

```text
提问命中时显示提问。
回答命中时只显示回答。
过程或工具命中时只显示对应过程或工具摘要。
```

这样会出现一个阅读问题：

```text
用户看到某段回答，但不知道它是在回答哪个问题。
```

### 4.2 V0.17 规则

搜索结果渲染时增加“上下文提问补齐”：

```text
如果命中的是用户提问：显示该提问本身。
如果命中的是最终回答：额外显示它前面最近的用户提问。
如果命中的是过程、工具、系统事件：额外显示它前面最近的用户提问。
如果同一个提问已经因为自身命中而显示，不重复显示。
```

这里的“对应提问”定义为：

```text
在当前 detail.events 顺序中，命中事件之前最近的一条 kind=user 事件。
```

### 4.3 显示建议

补出来的提问建议保持正常提问框样式，但可以增加轻量上下文提示：

```text
上下文提问
```

是否显示该提示可以在实现时根据视觉效果决定。核心要求是：

```text
用户能看到回答对应的提问。
不要让补出来的提问被误判为搜索命中本身。
不要破坏上下键切换提问、只看提问、回到顶部聚焦等现有功能。
```

## 5. 搜索按钮组调整

### 5.1 按钮语义

现有：

```text
全部
提问
```

这组按钮本质是“显示模式”，不是搜索范围。

V0.17 建议改成两组按钮：

```text
显示：[全部] [提问]
搜索：[全部] [当前]
```

### 5.2 显示组

```text
显示：全部
```

含义：

```text
当前会话中显示提问、回答、过程摘要、工具摘要、系统摘要。
```

```text
显示：提问
```

含义：

```text
当前会话中只显示用户提问。
```

此行为沿用 V0.10 以后已有能力。

### 5.3 搜索组

```text
搜索：全部
```

含义：

```text
搜索当前来源下的全部会话。
通过 /api/search?sourceId=...&q=... 使用当前来源的搜索索引。
命中后过滤目录区、标题区、会话区显示范围。
这是 V0.16 的默认行为。
```

注意：

```text
这里的“全部”是当前来源内全部会话，不跨来源。
```

```text
搜索：当前
```

含义：

```text
只搜索当前打开的会话详情。
不请求 /api/search。
不筛选左侧目录区和标题区。
只在当前会话渲染结果中做过滤。
```

优势：

```text
大幅提高当前会话内搜索速度。
减少全局搜索索引读取和左侧列表重渲染。
```

### 5.4 默认状态

默认建议：

```text
显示：全部
搜索：全部
```

这样能最大限度保持 V0.16 用户习惯。

## 6. 新增来源：本机 Claude

### 6.1 来源定义

新增来源名称：

```text
本机 Claude
```

建议 sourceId：

```text
local-claude
```

建议 sourceType：

```text
local-claude
```

扫描根目录：

```text
C:\Users\Administrator\.claude\projects\
```

辅助元信息目录：

```text
C:\Users\Administrator\.claude\sessions\
```

### 6.2 扫描规则

本机 Claude 扫描：

```text
递归读取 C:\Users\Administrator\.claude\projects\ 下的 *.jsonl。
读取 C:\Users\Administrator\.claude\sessions\*.json 作为补充元信息。
把 Claude Code CLI 和 Claude Code Desktop 的聊天记录统一解析为本软件会话数据。
来源层面统一显示为“本机 Claude”。
内部可以通过 entrypoint 区分 cli / claude-desktop-3p。
```

不扫描：

```text
全电脑。
非 .claude 默认路径。
外部来源里的 Claude 文件。
ChatGPT、Cursor、Gemini 等其他格式。
```

### 6.3 entrypoint 识别

优先级建议：

```text
JSONL 行内 entrypoint。
.claude\sessions\*.json 中同 sessionId 的 entrypoint。
无法识别时标记为 unknown。
```

常见值：

```text
cli
claude-desktop-3p
```

在界面中：

```text
来源下拉仍只显示“本机 Claude”。
会话标签或筛选项中可以显示 cli / claude-desktop-3p。
```

### 6.4 Claude JSONL 到本软件事件模型的映射

建议映射：

```text
type=user 或 message.role=user -> kind=user。
message.role=assistant 且 content[].type=text -> kind=assistant_final。
content[].type=thinking -> kind=assistant_commentary，默认折叠到过程摘要。
content[].type=tool_use -> kind=tool，显示工具名称、状态、简短摘要。
content[].type=tool_result -> kind=tool，显示执行结果摘要，原文懒渲染。
type=system 或低价值事件 -> kind=system，默认合并或摘要显示。
custom-title -> 优先作为会话标题。
queue-operation -> 低价值系统事件，默认跳过或合并。
attachment -> 附件摘要或系统事件，不默认渲染大段原始内容。
```

### 6.5 会话字段建议

本机 Claude 会话建议填充：

```text
id: sessionId。
key: 稳定 sourceId + sessionId 或 jsonl 路径 hash。
path: jsonl 文件路径。
cwd: JSONL cwd 优先，其次 sessions 元信息 cwd。
title: custom-title 优先，其次第一条用户提问首行。
created/updated: 优先使用 JSONL timestamp，按本地时间显示。
source: Claude entrypoint 或 Claude。
modelProvider: Claude。
```

如果缺少 `cwd`：

```text
仍可浏览会话。
SESSION 和回复框复制发送应禁用，并提示缺少工作目录。
```

## 7. Claude SESSION 和回复框复制发送

### 7.1 目标

当来源为：

```text
本机 Claude
```

SESSION 和回复框复制发送要实现类似 Claude CLI 的继续会话体验。

当来源为：

```text
本机 Codex
```

保持现有 Codex 命令行为。

当来源为：

```text
外部 Codex JSONL 来源
```

保持 V0.16 策略：作为浏览来源，禁用 SESSION 和回复框复制发送。

### 7.2 PowerShell 命令风格

用户主要在 PowerShell 中使用，因此 Claude 命令直接使用 PowerShell 风格。

路径和文本建议使用 PowerShell 单引号：

```powershell
'文本'
```

单引号内部如果出现单引号，需要转义为两个单引号：

```powershell
'it''s ok'
```

建议实现一个前端转义函数：

```javascript
function quotePowerShellSingle(value) {
  return "'" + String(value || "").replace(/'/g, "''") + "'";
}
```

### 7.3 SESSION 按钮命令

本机 Claude 的 SESSION 按钮复制：

```powershell
Set-Location -LiteralPath 'C:\path\to\cwd'; claude --resume 'session-id'
```

示例：

```powershell
Set-Location -LiteralPath 'M:\WORK\Project'; claude --resume '019e003a-0448-7963-b92a-7c3aba7499c9'
```

说明：

```text
Set-Location -LiteralPath 负责切到会话原工作目录。
claude --resume 负责恢复对应 Claude session。
不使用 cmd /c。
不生成 Bash 风格命令。
```

### 7.4 回复框复制发送命令

本机 Claude 的回复框“复制发送”复制：

```powershell
Set-Location -LiteralPath 'C:\path\to\cwd'; claude -p --resume 'session-id' '回复内容'
```

示例：

```powershell
Set-Location -LiteralPath 'M:\WORK\Project'; claude -p --resume '019e003a-0448-7963-b92a-7c3aba7499c9' '回复'
```

说明：

```text
-p / --print 用于发送这一轮消息并输出结果后退出。
--resume 指定已有 Claude session。
最后一个参数是用户在回复框输入的内容。
回复内容同样按 PowerShell 单引号转义。
```

### 7.5 禁用条件

以下情况应禁用 SESSION 或复制发送，并给出 toast：

```text
没有 sessionId。
没有 cwd。
当前来源不是本机 Codex 或本机 Claude。
回复框内容为空。
```

Claude Desktop 会话如果缺少 CLI 可恢复所需信息：

```text
仍允许浏览。
禁用命令复制。
提示“当前 Claude 会话缺少可恢复命令所需信息”。
```

## 8. 偶发 Markdown 渲染失败修复

### 8.1 现象

V0.16 偶发出现 Markdown 加粗语法没有被渲染，页面直接显示：

```markdown
**3. 你没在 class CTaskCounter 下面看到那些函数，是因为它们藏在宏里**
```

证据截图：

```text
软件\文档\BUG_V0.16\Snipaste_2026-06-11_13-53-42.png
```

预期：

```text
显示为加粗文字，不显示两侧 **。
```

### 8.2 可能原因

当前内联加粗解析使用较窄的正则规则。

可能失败场景：

```text
加粗内容中包含数字编号和标点。
加粗内容中包含中文、英文类名、符号混排。
段落前后存在不可见字符或特殊空白。
事件文本经过切块后未按预期进入 renderInlineText。
```

### 8.3 修复方向

V0.17 应强化确定性 Markdown 内联解析：

```text
继续保护 fenced code block。
继续保护 inline code。
继续保护表格、列表、引用。
只在普通文本段落、表格单元格、列表项中解析 **strong**。
允许 strong 内容包含中文、数字、空格、常见标点和单个 *。
避免跨行贪婪匹配。
避免把未闭合 ** 误解析。
```

可采用更稳妥的两阶段处理：

```text
先拆 inline code。
对非 code 片段做 strong 扫描。
匹配到成对 ** 后再 escape 内容并包 strong。
匹配不到成对 ** 时保留原文。
```

### 8.4 回归要求

必须增加覆盖：

```markdown
**3. 你没在 class CTaskCounter 下面看到那些函数，是因为它们藏在宏里**
```

并确认：

```text
页面中不显示两侧 **。
内容在 <strong> 中。
代码块里的 ** 不被解析。
行内代码里的 ** 不被解析。
未闭合 ** 保持原样。
表格和列表中的加粗仍正常。
```

## 10. 副作用和风险

### 10.1 搜索控件变多

风险：

```text
用户可能混淆“显示：全部”和“搜索：全部”。
```

应对：

```text
按钮组必须有短标签。
建议显示为“显示：全部 提问”和“搜索：全部 当前”。
两个按钮组之间留出间距，视觉上分组明确。
```

### 10.2 回答命中时补出提问会增加结果数量

风险：

```text
搜索结果中会出现没有直接命中关键词的提问。
用户可能以为这个提问也命中了。
```

应对：

```text
补出的提问只作为上下文。
必要时增加“上下文提问”小提示。
不要把补出的提问写入全局搜索命中 key。
```

### 10.3 搜索全部会话仍可能较慢

风险：

```text
当前来源会话很多时，搜索：全部仍需要读取搜索索引并重渲染左侧列表。
```

应对：

```text
保留 240ms 防抖。
继续使用 search index，不读取所有 detail。
新增“搜索：当前”作为高频快速路径。
搜索：当前不触发左侧目录和标题重渲染。
```

### 10.4 Claude JSONL 格式可能变化

风险：

```text
Claude Code CLI 和 Claude Desktop 的 JSONL 字段可能存在差异。
部分行可能不是标准 message 结构。
附件、工具结果、thinking 内容可能很大。
```

应对：

```text
解析器按行容错。
单行失败只记录失败，不中断整个来源。
未知事件降级为 system 摘要或跳过。
大段内容继续摘要 + 懒渲染，不默认展开。
```

### 10.5 本机 Claude 首次扫描可能增加构建时间

风险：

```text
C:\Users\Administrator\.claude\projects\ 下 jsonl 数量可能很多。
首次刷新本机 Claude 可能耗时。
```

应对：

```text
来源切换不自动全量扫描。
只刷新当前选中的来源。
本机 Claude 使用独立缓存。
后续按文件 mtime/size 做增量扫描。
```

### 10.6 Claude 命令可能产生真实对话费用和副作用

风险：

```text
回复框复制发送后，用户粘贴运行会真正向 Claude session 发送消息。
可能消耗额度。
可能修改 Claude 会话历史。
```

应对：

```text
按钮名称继续使用“复制发送”，不自动执行。
toast 展示复制的完整命令。
不在网页里直接调用 Claude。
```

### 10.7 Claude Desktop 会话不一定能被 CLI 完整恢复

风险：

```text
entrypoint 为 claude-desktop-3p 的会话可能与 CLI 权限、cwd、上下文存在差异。
```

应对：

```text
只在 sessionId 和 cwd 都存在时生成命令。
必要时在标签中显示 claude-desktop-3p。
如果命令信息不足，禁用按钮并提示原因。
```

### 10.8 PowerShell 转义如果不严格可能导致命令错误

风险：

```text
路径或回复内容包含单引号时，命令可能断裂。
```

应对：

```text
统一使用 PowerShell 单引号。
单引号替换为两个单引号。
为路径、sessionId、回复内容都走同一转义函数。
```

### 10.9 Markdown 加粗修复可能误伤星号文本

风险：

```text
普通数学表达、通配符、未闭合 ** 可能被误解析。
```

应对：

```text
只解析成对 **。
不跨行解析。
代码块和行内代码不解析。
增加回归测试保护 literal asterisks。
```
