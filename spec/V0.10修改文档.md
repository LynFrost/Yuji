# Open-CodexChatIndex V0.10 修改文档

状态：待实施

日期：2026-05-07

## 1. 修改目标

V0.10 的目标是在不改变 V0.09 持续对话工作流的前提下，进一步压缩顶部信息占用空间，并补齐回复框长文本编辑与高频快刷操作的可用性问题。

本版本重点优化：

```text
将顶部统计标签进一步缩短为：会话、目录、归档、含图、时间。
修复回复框在文本超过高度上限后既没有滚动条也无法用鼠标滚轮滚动的问题。
为“快刷”增加键盘快捷键，在焦点位于会话区时可通过 k / K 触发。
```

本版本不改变以下既有能力：

```text
智能增量刷新。
当前会话快刷。
全量重建。
SESSION 复制。
复制发送命令。
清空回复框。
草稿按会话保留。
Enter / Shift + Enter 的回复框行为。
提问定位。
上下键切换提问。
只看提问。
过程懒渲染。
滚动整体流畅性。
```

## 2. 顶部统计区文案压缩

V0.10 建议将顶部统计区从：

```text
会话：1915
工作目录：67
归档：32
含图片引用：40
生成时间：2026-05-07 16:42:51
```

调整为：

```text
会话：1915
目录：67
归档：32
含图：40
时间：2026-05-07 16:42:51
```

规则：

```text
仅缩短标签，不缩短数值。
仅缩短标签，不缩短时间字符串。
不增加额外悬停提示。
```

目的：

```text
进一步节省顶部横向空间。
减少在窄窗口下顶部统计区换行概率。
不给用户增加新的交互学习成本。
```

## 3. 回复框超长文本滚动修复

### 3.1 当前问题

V0.09 设计中，回复框在达到 20 行上限后需要进入内部滚动。

但当前存在的问题是：

```text
文本高度超过上限后，没有明显滚动能力。
用户看不到滚动条。
鼠标停留在输入框中时，滚轮也不能上下滚动输入框内容。
```

这会导致长回复难以继续编辑。

### 3.2 V0.10 目标行为

V0.10 建议将回复框滚动行为明确为：

```text
20 行以内：输入框继续自动增高。
超过 20 行：输入框停止继续增高。
超过 20 行后：输入框内部允许纵向滚动。
鼠标滚轮可以直接滚动输入框内部内容。
触控板滚动也应能驱动输入框内部滚动。
键盘方向键、Page Up、Page Down、Home、End 仍应作用于输入框内部内容。
不出现横向滚动条。
继续保持自动换行。
```

### 3.3 实现建议

实现方向建议明确为：

```text
输入框保持 overflow-y 可滚动。
不再把滚动条完全隐藏到“看不见且滚不动”的状态。
允许显示细滚动条，优先保证可用性。
超过 20 行后，滚轮事件优先滚动输入框内部内容。
```

V0.10 不建议再坚持“绝对无滚动条视觉痕迹”的处理，因为这会继续造成可滚动性不可感知。

## 4. 快刷快捷键

### 4.1 目标行为

由于“快刷”会被频繁使用，V0.10 建议增加键盘快捷键：

```text
当焦点位于会话区时：
按 k 可触发“快刷”。
按 K 也可触发“快刷”。
不区分大小写。
```

### 4.2 生效范围

必须明确：

```text
只有当焦点位于会话正文区时，k / K 才生效。
当焦点位于输入框、搜索框、筛选框、下拉框、按钮等可编辑或可输入控件中时，k / K 不生效。
当焦点位于回复框中时，k / K 不生效。
当快刷正在执行中时，k / K 不生效。
```

### 4.3 实现建议

实现方式建议：

```text
k / K 不单独复制一套刷新逻辑。
k / K 直接复用现有“快刷”按钮对应的刷新函数。
快捷键触发后应保持现有 loading、toast 和防重复点击逻辑一致。
```

这样可以减少逻辑分叉，降低维护成本。

## 5. 副作用和风险

### 5.1 顶部统计标签压缩

副作用较小。

可能影响：

```text
“含图”比“含图片引用”更短。
“时间”比“生成时间”更短。
```

但由于语义仍然足够直观，因此不建议为此增加悬停说明或额外文案。

### 5.2 回复框滚动行为变化

修复后，鼠标停留在输入框上时，滚轮会优先滚动输入框内部内容，而不是滚动外层会话正文。

影响：

```text
用户在长回复编辑场景下，滚轮行为会更多地服务输入框自身。
需要先把输入框滚到边界，用户才会继续滚到外层正文。
```

这是可接受副作用，因为长回复可编辑性优先级更高。

### 5.3 快刷快捷键误触发

增加 k / K 快捷键后，会带来一定误触发风险。

缓解方式：

```text
严格限制生效范围，只在会话区焦点下生效。
排除所有输入类控件和按钮焦点状态。
快刷进行中不重复触发。
```

由于“快刷”本身是轻量操作，不是破坏性操作，因此误触发风险可接受。
