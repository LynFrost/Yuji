# Open-CodexChatIndex V0.18 搜索多关键词高亮与渲染流畅度优化

状态：已实施并验收

日期：2026-06-16

## 1. 修改目标

V0.18 在 V0.17 多来源 + 确定性渲染基础上，聚焦“搜索体验”与“长会话流畅度”，共七项：

```text
搜索支持空格分词，多关键词按 AND（全部命中）匹配。
搜索命中的文字在会话正文中高亮显示。
搜索结果浏览时，上下键仍可在“当前结果中可见的提问框”之间跳转。
搜索：当前 增加输入防抖，消除长会话逐字输入卡顿。
长会话正文使用 content-visibility 降低打开与滚动成本（谨慎尝试，测不过则回退）。
会话正文内联显示引用图片（懒加载缩略图、点击放大）。
服务端搜索索引缓存增加体积上限/LRU 回收，降低大来源常驻内存。
```

本版本仍然保持：

```text
来源切换影响显示范围，不同来源数据/缓存/搜索/详情/备注隔离。
不提供跨来源合并显示，不提供跨来源搜索。
显示：全部/提问 与 搜索：全部/当前 两组按钮语义不变。
文档确认前不执行实现。
```

## 3. 关键工程约束（必须先知道）

```text
CodexChatIndex.html 有两份相同副本：被服务的独立文件，以及 Build-CodexChatIndex.ps1 内的 here-string。
构建时 PS1 的 here-string 会写回 CodexChatIndex.html，所以 PS1 是真正源头。
```

## 4. 空格分词多关键词搜索（AND）

### 4.1 当前问题

```text
查询整段当作一个子串匹配。
输入“exit code”只能命中连续出现的“exit code”，命中不了“code ... exit”。
```

### 4.2 V0.18 规则

```text
按空白把查询切成多个关键词（连续空白合并，忽略首尾空白）。
多关键词之间为 AND：每个关键词都要命中，才算命中。
单个关键词内部仍是子串匹配，不做正则、不做模糊。
大小写不敏感（沿用现有 casefold/toLowerCase）。
切词后若为空（纯空白），视为无查询。
```

### 4.3 服务端（搜索：全部）

```text
位置：CodexChatIndexServer.py 的 search_sessions。
把 query.casefold() 改为 terms = [t for t in query.casefold().split() if t]。
命中条件：all(term in text for term in terms)。
terms 为空时返回空结果（与现状一致）。
其余返回结构（sessionKeys/hits）不变。
```

### 4.4 前端（搜索：当前）

```text
位置：CodexChatIndex.html 的 eventMatchesSearch。
把单一 includes 改为：先把 query 按空白切词，再要求每个词都 includes。
haystack 仍为 [summary, rawText, toolName, status] 拼接后 toLowerCase。
getVisibleDetailEvents 中“上下文提问补齐”逻辑保持不变。
```

### 4.5 行为变更说明

```text
这是搜索语义变更：含空格的查询从“短语匹配”变为“多词 AND”。
对中文连续词无影响（无空格不分词）。
对“exit code”这类英文短语，匹配会更宽（顺序无关、可不相邻）。
在文档与验收中明确记录此变更，避免误判为 bug。
```

## 5. 匹配文字高亮（仅正文）

### 5.1 范围与原则

```text
只在右侧会话正文高亮，不动左侧目录/标题列表（与你确认一致）。
高亮发生在确定性渲染“之后”，对已生成的 DOM 文本节点包裹 <mark>。
绝不在 renderInlineText/字符串阶段插入 <mark>，避免破坏标签与 ** 解析。
绝不跨 HTML 标签匹配，杜绝边界误判。
代码块、行内代码内的命中也高亮（按文本节点包裹，不影响代码语义）。
```

### 5.2 实现方式（DOM 后处理，确定性）

```text
新增 highlightMatchesInElement(root, terms)：
  遍历 root 下的文本节点（TreeWalker，SHOW_TEXT）。
  跳过 <mark> 内、<script>/<style> 内的文本节点。
  对每个文本节点，按 terms（AND 的每个词）大小写不敏感查找。
  命中片段用 <mark class="search-hit"> 包裹，重建该文本节点。
  一个文本节点内多处命中、多个词命中都要处理。
  不修改 messageCopyTexts 注册的原文（复制全文仍是无标记原文）。
```

### 5.3 触发时机

```text
renderViewer 渲染完正文后，若有查询则调用一次高亮。
懒渲染的过程/工具展开后（hydrateLazyDetail 渲染完 body），对该 body 再高亮一次。
搜索词变化、清空时，重渲染后重新高亮或不高亮。
```

### 5.4 高亮样式

```text
.search-hit { background: rgba(255, 214, 102, .55); border-radius: 3px; padding: 0 1px; }
深色代码块内可用更克制的描边或半透明底色，保证可读。
高亮不改变字号、行高、布局，避免引起回流抖动。
```

### 5.5 性能与边界

```text
仅对“当前已渲染”的 DOM 高亮，配合懒渲染，不会一次扫描全部过程/工具。
TreeWalker 单次线性遍历，长会话正文（提问+回答）规模可控。
terms 为空不进入高亮逻辑。
复制全文、导出 MD 使用原始 rawText，不包含 <mark>。
```

## 6. 上下键在搜索结果中跳提问框

### 6.1 当前问题

```text
jumpQuestion 基于 getQuestionEvents（会话全部提问）。
搜索：当前 时正文只渲染过滤后的子集（含补出的“上下文提问”）。
上下键可能跳到未渲染的提问，导致定位失败或跳转无效。
```

### 6.2 V0.18 规则

```text
有搜索查询时，上下键导航集合 = 当前正文中“实际渲染出来的提问框”。
即以 transcript 内 [data-question-key] 元素顺序为准，而非全量 getQuestionEvents。
补出的“上下文提问”也可被导航命中（它在 DOM 中存在）。
无搜索查询时，行为与 V0.17 完全一致。
```

### 6.3 实现方式

```text
新增 getNavigableQuestionKeys()：
  无查询时返回 getQuestionEvents() 的 questionKey 顺序（同现状）。
  有查询时返回 transcript.querySelectorAll('[data-question-key]') 的顺序去重。
jumpQuestion / updateQuestionNavState 基于该集合计算 index、边界禁用。
向上/向下到边界时按集合首尾禁用按钮（与现状一致）。
设置选中后仍调用 scrollToQuestion 滚动定位。
```

### 6.4 一致性要求

```text
“只看提问”视图下上下键仍正常。
搜索 + 只看提问组合下，集合为“渲染出的提问框”，逻辑统一。
回到顶部聚焦、点击提问框选中等现有交互不回退。
```

## 7. 搜索：当前 输入防抖

### 7.1 当前问题

```text
搜索：当前 时，viewerSearch 每次 input 立即 renderViewer，重建整段正文 innerHTML。
长会话逐字输入会卡顿；而 搜索：全部 已有 240ms 防抖。
```

### 7.2 V0.18 规则

```text
搜索：当前 的正文过滤增加约 160ms 防抖。
连续输入只在停顿后渲染一次，减少长会话重排。
搜索：全部 保持原有 240ms 全局搜索防抖不变。
切换搜索范围、清空输入时立即生效，不等防抖。
```

### 7.3 实现方式

```text
scheduleViewerSearch 在 scope=current 分支增加 setTimeout 防抖。
新增 currentScopeSearchTimer，输入时 clear 后重设。
渲染前同步 viewerSearchQuery，确保高亮/导航集合一致。
中文输入法 compositionend 后再触发（沿用 isComposing 保护）。
```

## 8. 长会话 content-visibility（谨慎尝试）

### 8.1 目标

```text
降低超长会话首屏渲染与滚动成本，离屏消息卡片不参与布局/绘制。
```

### 8.2 方案

```text
给正文消息卡片（.message / .collapsed-group）加：
  content-visibility: auto;
  contain-intrinsic-size: 估算高度（如 0 160px），按类型给不同估值。
仅对正文容器内的消息生效，不影响左侧列表与头部。
```

### 8.3 风险与红线（重点）

```text
风险1：contain-intrinsic-size 估不准会导致滚动条高度跳动——触碰你“零滚动抖动”红线。
风险2：离屏卡片 offsetTop 测量受影响，可能让“跳到提问框并置顶”定位不准。
风险3：与高亮 TreeWalker 叠加时，离屏内容仍在 DOM，可正常高亮，但需验证。
```

### 8.4 验收门槛（测不过就回退）

```text
打开长会话 < 5 秒。
快速滚动无可见抖动/跳动。
上下键跳提问框、回到顶部聚焦定位准确。
任一不达标，则本项回退，不强行保留。
```

## 9. 图片内联显示（本版最高风险项）

### 9.1 数据现状

```text
Codex：图片为 base64 data URL，存于 response_item 的 message.content[] 的 input_image。
当前解析器只从 event_msg/user_message 取纯文本，图片未进入 events。
Claude：本版先不强制，按是否存在等价 image content part 决定，缺失则不显示。
```

### 9.2 解析策略

```text
解析 user 轮时，额外收集 input_image 的 data URL。
在对应 user 事件上新增 images 字段（数组，元素为 data URL 或占位信息）。
base64 不写入 SearchText、不写入用于复制的 rawText。
detail.json 体积会增大；仅在 detail 中保留，不进 search.json / data.json。
```

### 9.3 前端显示

```text
user 事件渲染时，正文下方渲染图片缩略图区。
缩略图 loading="lazy"、限制最大高度，点击放大（模态或新标签）。
无图片时不渲染任何额外节点。
导出 MD 时图片以占位或链接形式体现，避免巨大 base64 注入文本。
```

### 9.4 风险与缓解（红线相关）

```text
风险1：base64 内联使 detail.json 与内存上升，可能拖慢打开（>5s）。
缓解：仅当前会话 detail 懒加载；缩略图懒加载；不把 base64 进搜索/列表数据。
风险2：含大量大图的会话首屏偏重。
缓解：缩略图限尺寸、点击才加载原图（如可行）。
风险3：解析器改动影响既有 Codex 纯文本路径。
缓解：先写测试锁定无图会话解析结果不变，再加图片采集。
若验收发现明显拖慢或抖动，本项可降级为“仅标记有图、不内联”。
```

## 10. 搜索索引内存上限（附带项）

### 10.1 现状

```text
load_search_index 把每个来源整份 search.json 读入 _search_index_cache。
按 sourceId 累加、不回收，大来源或多来源切换后常驻内存偏高。
```

### 10.2 V0.18 规则

```text
为 _search_index_cache 增加条目数或总体积上限。
超限时按最近最少使用（LRU）淘汰最旧来源的索引。
被淘汰来源下次搜索按 mtime 重新读取（已有 mtime 校验逻辑）。
不改变搜索结果，仅影响内存与极少数重读。
```

## 11. 不改变的行为

```text
来源发现、切换、隔离规则。
本机 Codex/Claude/外部来源的扫描路径与刷新/重建/快刷逻辑。
显示：全部/提问 与 搜索：全部/当前 的按钮语义与默认值。
上下文提问补齐规则（命中回答/过程/工具/系统时补出上一条提问）。
确定性 Markdown 渲染规则与 ** 加粗修复。
备注、标题区选中、回复框 20 行上限与 Enter/Shift+Enter。
SESSION 与复制发送命令（Codex codex resume / Claude PowerShell）。
```

## 12. 副作用与风险汇总

```text
多关键词 AND：含空格查询语义变更（短语→多词），需文档与验收记录。
正文高亮：DOM 后处理，若实现不当可能误标——以文本节点包裹、跳过 mark/script/style 规避。
上下键集合改为“可见提问框”：需保证无查询时与 V0.17 完全一致。
搜索：当前 防抖：结果延迟约 160ms，属预期。
content-visibility：可能引起滚动抖动/定位不准，设硬验收门槛，测不过回退。
图片内联：detail 体积与内存上升，可能拖慢打开；用懒加载与“不进搜索数据”缓解，必要时降级。
搜索索引 LRU：极少数大来源偶发重读，无结果影响。
HTML 双副本未重构：前端两处需同步修改，遗漏会被构建覆盖——实现时同改 PS1 与独立 HTML。
```
