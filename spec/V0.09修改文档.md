# Open-CodexChatIndex V0.09 修改文档

状态：待实施

日期：2026-05-07

## 1. 修改目标

V0.09 的目标是进一步降低“网页查看 + CLI 对话”之间的切换成本，让用户可以直接在会话页面中准备下一条回复命令，再复制到终端执行，然后回到网页快刷查看结果。

本版本重点优化：

```text
将“快刷当前”简写为“快刷”，节省按钮区空间。
调整会话区顶部操作按钮顺序，让“快刷”和“SESSION”更贴近持续对话流程。
在会话区底部增加常驻回复框，用于直接生成下一条 codex resume 命令。
新增“复制发送”按钮，一键复制带路径、SESSION 和回复内容的完整命令。
新增“清空”按钮，允许用户手动清空回复框内容。
补齐输入法、换行、长文本、多行文本和命令转义规则。
```

本版本不改变 V0.08 已确认的刷新架构，不影响：

```text
智能增量刷新。
当前会话快刷。
全量重建。
提问定位。
上下键切换提问。
只看提问。
搜索当前会话。
复制全文。
复制路径。
复制 SESSION。
导出 MD。
过程懒渲染。
滚动流畅性。
```

## 2. 顶部操作区调整

V0.09 建议将会话区顶部按钮调整为：

```text
路径
导出 MD
SESSION
快刷
```

其中：

```text
“快刷”是原“快刷当前”的简写。
“快刷”放到“SESSION”的右边。
“快刷”使用主动作样式。
“路径 / 导出 MD / SESSION”继续保持次级操作样式。
```

这样做的目的：

```text
节省横向空间。
强化“SESSION -> 快刷 -> 查看结果”的连续对话路径。
避免“快刷”和复制类按钮在视觉上完全一样而造成误点。
```

## 3. 会话区底部回复框

### 3.1 基本形态

V0.09 建议在会话区最底部增加一个常驻回复区。

结构：

```text
一个多行输入框容器。
输入框右下角内嵌两个按钮：清空、复制发送。
按钮在输入框内部，不额外占一整行工具栏。
```

### 3.2 高度规则

回复框高度规则建议如下：

```text
默认显示为较低高度，约 2 行。
随着输入内容自动增高。
最大高度上限为 20 行。
20 行以内必须保证文字全显，不出现内部滚动条。
超过 20 行后才允许输入框内部滚动。
```

这样可以兼顾：

```text
短回复时不占太多垂直空间。
长回复时仍可在网页中直接编辑。
避免输入框无限增高把正文挤得过窄。
```

### 3.3 布局规则

按钮内嵌在输入框内部时，必须保证输入文字不会被按钮压住。

实现规则建议明确为：

```text
输入框主体仍然占满可用宽度。
通过容器内边距预留右下角按钮避让空间。
“清空”和“复制发送”绝不额外占用一整行按钮栏。
两个按钮采用紧凑样式，不明显挤压输入区域主宽度。
“复制发送”位于最右侧，“清空”位于其左侧。
```

## 4. 复制发送命令设计

### 4.1 目标命令

V0.09 的核心功能是生成一条可直接粘贴到终端执行的命令。

目标形式：

```text
codex -C "当前工作目录" resume SESSION_ID "回复内容"
```

例如当前会话为：

```text
codex resume 019e003a-0448-7963-b92a-7c3aba7499c9 -C "M:\WORK\OneDrive - Cairo British College\1_PCSoftware_1\Codex\2604116CX_无附件"
```

回复框内容为：

```text
回复
```

则复制出来的命令应为：

```text
codex -C "M:\WORK\OneDrive - Cairo British College\1_PCSoftware_1\Codex\2604116CX_无附件" resume 019e003a-0448-7963-b92a-7c3aba7499c9 "回复"
```

### 4.2 命令来源

命令生成所需信息来源建议明确为：

```text
当前选中会话的工作目录。
当前选中会话的 SESSION id。
当前回复框中的输入内容。
```

如果任一关键字段缺失：

```text
路径缺失：不能复制发送。
SESSION id 缺失：不能复制发送。
回复为空：不能复制发送。
```

此时应使用自动消失 toast 提示用户，不弹确认框。

### 4.3 转义策略

V0.09 已确认要做可靠转义，因此文档中建议把规则写死。

推荐策略：

```text
以当前 Windows PowerShell / Windows 终端主路径为标准目标环境。
回复内容中的双引号、反引号、反斜杠、换行必须做安全转义。
支持中文、空格和多行文本。
简单单行回复时，尽量保持命令可读。
复杂多行或包含特殊字符时，允许切换到更安全的 PowerShell 友好格式。
最终目标不是“命令尽量好看”，而是“复制后可直接运行且不误解参数”。
```

文档中需要明确：

```text
V0.09 的“复制发送”优先保证执行可靠性。
不强求所有复杂输入都保持最朴素的可读形式。
```

## 5. 输入与快捷键规则

回复框中的键盘行为建议明确如下：

```text
光标位于回复框中时：
Enter = 复制发送快捷键。
Shift + Enter = 换行快捷键。
```

但必须增加输入法保护规则：

```text
当输入法正在组字时，Enter 只能用于确认候选，不得触发复制发送。
只有在非组字状态下，Enter 才等价于点击“复制发送”。
```

否则中文输入会产生高概率误触发。

## 6. 清空按钮规则

由于“复制发送”后不自动清空，因此 V0.09 需要提供手动清空能力。

建议规则：

```text
“清空”按钮位于“复制发送”左侧。
点击“清空”后立即清空输入框。
清空后焦点返回输入框。
默认不弹确认框，保持流畅。
允许浏览器原生撤销操作继续可用，以便误清空后可尝试 Ctrl+Z。
```

这样可以兼顾：

```text
连续改写同一条回复时，不会因为自动清空而丢字。
确认要开始下一轮内容时，又能一键清空。
```

## 7. 草稿保留策略

为了服务“持续对话”场景，V0.09 建议增加轻量草稿保留。

规则建议：

```text
回复框内容按当前会话临时保留。
切换到其他会话后，再切回当前会话时，草稿仍在。
点击“快刷”或“刷新”后，不自动清空草稿。
点击“复制发送”后，不自动清空草稿。
只有点击“清空”时才真正清空草稿。
```

不建议在 V0.09 做更重的跨浏览器持久化存储，只做当前页面会话级状态即可。

## 8. 成功提示与错误提示

V0.09 继续沿用自动消失 toast。

建议文案方向：

```text
复制发送成功：已复制发送命令。
回复为空：请输入回复内容。
当前会话缺少路径：当前没有可发送的会话路径。
当前会话缺少 SESSION：当前会话缺少 SESSION id，无法生成发送命令。
清空成功不必提示。
```

不建议：

```text
复制成功后弹确认框。
清空时弹确认框。
输入框每次换行都出现提示。
```

## 9. 副作用和风险

### 9.1 界面空间

新增底部回复区后，会话正文可视高度会略微减少。

影响：

```text
在小屏幕上，正文可视区域会变短。
当输入框接近 20 行时，正文区域会进一步缩小。
```

缓解：

```text
默认高度保持较低。
按钮内嵌，不再额外占一行。
超过 20 行后内部滚动，而不是继续无限长高。
```

### 9.2 输入法误触发

如果不处理组字状态，中文输入时按 Enter 很容易误触发“复制发送”。

这是 V0.09 的高优先级风险，必须在设计中明确规避。

### 9.3 命令转义复杂度

“复制发送”不是普通复制文本，而是复制一条可执行命令。

风险：

```text
多行文本。
引号。
反引号。
反斜杠。
中文。
空行。
```

都可能导致命令在终端中被错误解析。

V0.09 必须优先保证：

```text
命令可执行。
参数边界不误判。
SESSION id 和回复文本不串位。
```

### 9.4 清空误触发

新增“清空”按钮会带来误触清空风险。

缓解：

```text
按钮放在“复制发送”左侧，降低误触主动作的概率。
不使用过于醒目的危险色，但与普通按钮有明确区分。
尽量保留浏览器原生撤销能力。
```

### 9.5 复杂输入时命令可读性下降

为了可靠转义，复杂输入场景下复制出来的命令可能比简单回复时更难阅读。

这是可接受副作用，因为：

```text
该命令的主要目标是“可直接运行”。
不是让用户长期手工编辑这一整条命令。
```
