# 语迹 V0.22 会话切换、刷新、快刷阅读进度锚点保持

状态：已实施

日期：2026-06-21

## 1. 修改目标

V0.22 基于当前 V0.21，解决会话区阅读进度在切换、刷新、快刷后丢失的问题。

需要实现：

```text
切换对话框之后，保持进度。
刷新之后，保持进度，不能跳到最上面。
快刷之后，保持进度，不能跳到最上面。
进度锚点统一按照当前选中的用户提问框。
```

本版本重点是交互稳定性，不改变聊天记录解析规则，不改变来源体系，不改变 Markdown 渲染、复制、导出、搜索、备注、回复框等既有功能的语义。

## 2. 当前 V0.21 基础

V0.21 当前已经存在“选中提问”的基础状态：

```text
selectedQuestionKey
pendingQuestionFocus
data-question-key
scrollToQuestion()
setSelectedQuestionKey()
focusFirstQuestion()
focusLastQuestion()
jumpQuestion()
```

当前也已经存在刷新后尝试保留提问的逻辑：

```text
刷新前记录 previousQuestionKey。
刷新后重新选择 previousSessionKey。
刷新后把 selectedQuestionKey 设回 previousQuestionKey。
重新加载当前会话详情并 renderViewer()。
```

但 V0.21 的实际风险是：

```text
如果 previousQuestionKey 在重渲染后没有命中，syncSelectedQuestionKey() 会退回第一条提问。
第一条提问通常位于会话顶部，因此刷新或快刷后会表现为跳到最上面。
切换会话时 selectSession() 会固定 pendingQuestionFocus = 'last'，每次打开都倾向定位最后一个提问。
当前没有“每个会话自己的上次阅读进度”记录。
```

因此 V0.22 不需要重新发明定位体系，而是要把现有“选中提问”补成完整的阅读进度锚点机制。

## 3. 进度定义

V0.22 将“阅读进度”定义为：

```text
当前会话区中被选中的用户提问框。
```

不是定义为：

```text
纯 scrollTop 数值。
纯页面百分比。
当前屏幕第一行文字。
回答框、过程框、工具框的位置。
```

原因：

```text
用户已经通过点击提问、上下键、回到顶部、底部等操作形成了“当前选中提问”的交互模型。
刷新后内容高度可能变化，纯 scrollTop 容易漂移。
过程明细、工具输出、图片、Markdown 表格等可能按需渲染，绝对像素位置不稳定。
提问框是会话中的自然导航节点，最适合作为稳定锚点。
```

## 4. 进度锚点数据结构

每次需要捕获进度时，建议记录一份 Progress Anchor：

```text
sourceId：当前来源。
workspacePath：当前目录，即 workspace.cwd。
sessionKey：当前会话。
questionKey：当前选中的提问 key。
questionIndex：当前提问在本会话用户提问列表中的序号。
questionTextHash：当前提问正文的短 hash，作为 questionKey 失效时的辅助匹配。
offsetFromQuestionTop：可选字段，提问框顶部距离会话区可视顶部的偏移量。
viewMode：全部 / 提问，作为上下文记录，不用于自动还原视图模式。
searchScope：全部 / 当前，作为上下文记录，不用于自动还原搜索范围。
searchQuery：当前搜索词。
capturedAt：捕获时间，用于避免旧恢复动作误用。
```

其中 `workspacePath` 必须使用 `workspace.cwd`，不要使用 `workspace.id`。V0.21 的构建脚本会为 workspace 生成新的 GUID：

```text
id = "ws-" + [System.Guid]::NewGuid().ToString("N")
```

因此刷新、快刷、全量重建后 `workspace.id` 可能变化。V0.21 现有刷新逻辑也已经使用 `workspace.cwd` 来重新寻找刷新前的目录。

`questionKey` 仍然作为第一优先级；`questionIndex` 和 `questionTextHash` 作为兜底。

需要明确：

```text
questionKey 格式为 sessionKey + '::question::' + eventIndex。
eventIndex 是完整事件列表的下标，包含 user、assistant、tool、system 等事件。
eventIndex 不是用户提问列表里的序号。
questionIndex 是用户提问列表里的序号，独立于 eventIndex。
兜底匹配时使用 questionIndex，不要把 eventIndex 当作 questionIndex 使用。
```

`questionTextHash` 建议使用稳定、轻量、无依赖的算法，例如：

```text
取用户提问正文规范化后的前 120 个字符。
使用 FNV-1a 或 djb2 计算短 hash。
保存 16 进制结果的前 8 位。
```

`offsetFromQuestionTop` 只用于尽量保持视觉位置，例如刷新前当前提问距离会话区顶部 20px，刷新后仍尽量恢复到类似位置。这个字段是可选增强；如果 V0.22 实施时为了降低复杂度暂不做像素微调，可以先保存为 0，核心恢复仍以提问锚点为准。

## 5. 恢复优先级

恢复进度时按以下顺序执行：

```text
1. sourceId、sessionKey 仍然一致，并且 questionKey 命中：恢复到同一个提问。
2. questionKey 未命中，但 questionTextHash 命中：恢复到相同文本的提问。
3. 文本 hash 也未命中，但 questionIndex 仍在范围内：恢复到同序号提问。
4. questionIndex 越界：优先恢复到最近的上一条提问。
5. 上一条也不存在：恢复到下一条提问。
6. 仍无可用提问：保持会话区顶部或空态，不强行恢复。
```

禁止行为：

```text
不能因为 questionKey 未命中就直接退回第一条提问。
不能把旧会话的锚点恢复到新会话。
不能在来源已经切换后继续应用旧锚点。
不能为了恢复锚点反复滚动或持续监听布局变化。
```

## 6. 场景设计

### 6.1 切换对话框之后保持进度

目标：

```text
每个会话记住自己的上次选中提问。
从 A 会话切到 B 会话，再切回 A 会话时，A 会话恢复到离开前选中的提问。
```

行为规则：

```text
首次打开一个从未访问过的会话，保持 V0.21 现有逻辑：默认聚焦最后一个提问。
已经访问过的会话，再次打开时优先恢复该会话上次选中的提问。
用户在会话区点击某个提问、使用上下键切换提问、点击回到顶部或底部，都要更新该会话的进度锚点。
```

切回已访问会话时需要避免双重滚动：

```text
如果目标会话存在已保存的 Progress Anchor，selectSession() 不应再走 pendingQuestionFocus = 'last' 的默认滚动路径。
可以跳过 pendingQuestionFocus = 'last'，或在 renderViewer() 前先把 selectedQuestionKey 设为锚点里的 questionKey。
随后由 restoreProgressAnchor() 统一处理滚动。
这样可以避免 renderViewer() 先滚到最后一条提问，再由 restoreProgressAnchor() 滚回保存锚点，造成用户可见的闪跳。
首次打开未访问会话不受影响，因为没有保存锚点时仍然保持默认定位最后一个提问。
```

建议保存位置：

```text
页面内 Map 即可，不默认写入 localStorage。
```

原因：

```text
本需求主要解决当前浏览页面内的切换和刷新体验。
不写入 localStorage 可以避免长期堆积大量会话位置数据。
也避免跨版本、跨来源、跨数据重建后的陈旧锚点误恢复。
```

如果未来需要“关闭网页后再打开仍记住位置”，可以另立版本讨论。

### 6.2 刷新之后保持进度

刷新前：

```text
捕获当前会话的 Progress Anchor。
记录本次刷新请求 token。
```

刷新中：

```text
允许显示刷新进度和 toast。
不提前清空当前锚点。
不主动把 selectedQuestionKey 设为 null。
```

刷新后：

```text
如果刷新后仍然选中同一来源、同一会话，则按恢复优先级恢复到刷新前的提问。
如果刷新过程中用户切换了来源或会话，则取消本次恢复。
如果刷新后当前会话不存在，则按现有规则选择可用会话，但不套用旧锚点。
```

滚动方式：

```text
使用 auto 定位，不使用 smooth。
只恢复一次，不做长时间追踪。
```

### 6.3 快刷之后保持进度

快刷前：

```text
捕获当前会话 Progress Anchor。
```

快刷后：

```text
优先恢复到快刷前选中的提问。
即使当前会话新增了回答、新工具结果或新提问，也不自动跳到底部。
```

原因：

```text
用户提出的是“保持进度”，而不是“快刷后跳到最新”。
快刷常用于 CLI 对话后查看更新，但如果用户正在读中间内容，强行跳底会打断阅读。
```

如果未来需要“快刷后跳到最新”的模式，可以另加可选按钮或设置，不放入 V0.22。

## 7. 与现有功能的关系

### 7.1 上下键切换

V0.22 不改变上下键含义：

```text
向上：切到上一条提问，并把提问放到当前画面上方。
向下：切到下一条提问，并把提问放到当前画面上方。
```

新增要求：

```text
每次上下键切换成功后，同步更新当前会话 Progress Anchor。
```

### 7.2 点击提问

点击会话区某个提问后：

```text
更新 selectedQuestionKey。
更新当前会话 Progress Anchor。
焦点仍给到会话区，使上下键继续可用。
```

### 7.3 回到顶部 / 底部

回到顶部：

```text
仍自动选中第一个提问。
同步更新 Progress Anchor 为第一个提问。
```

底部：

```text
仍自动选中最后一个提问。
同步更新 Progress Anchor 为最后一个提问。
```

### 7.4 只看提问 / 全部

切换“全部 / 提问”时：

```text
优先保持当前 selectedQuestionKey。
切换后如果该提问可见，恢复到该提问。
如果不可见，按当前视图中的可导航提问兜底。
```

### 7.5 搜索

搜索状态下：

```text
如果当前选中提问仍在搜索结果里，保持该提问。
如果当前提问不在搜索结果里，不强行跳到非命中内容。
可以按当前搜索结果内的第一条可见提问作为临时选中项。
清空搜索或切回其他搜索范围后，再按会话 Progress Anchor 恢复。
```

这里的“临时选中项”只用于搜索状态下的键盘导航和视觉提示：

```text
系统自动选中第一条搜索结果时，不更新 Progress Anchor。
这样用户清空搜索后，会回到搜索前的真实阅读进度。
如果用户在搜索结果中主动点击某个提问，则按 7.2 的规则更新 Progress Anchor。
```

这样可以避免用户搜索时看到一个和筛选结果无关的位置。

### 7.6 复制全文、导出 MD、路径、SESSION、回复框

V0.22 不改变这些功能：

```text
复制全文仍按当前消息完整复制。
导出 MD 仍按完整会话导出。
路径、SESSION、回复框复制发送命令不受进度锚点影响。
```

## 8. 实现建议

建议新增几个小函数，避免把恢复逻辑散落到刷新、快刷、切换会话各处：

```text
captureProgressAnchor(session)
saveProgressAnchorForCurrentSession()
getProgressAnchorForSession(session)
resolveQuestionKeyFromAnchor(anchor)
restoreProgressAnchor(anchor, options)
cancelStaleProgressRestore(token)
```

建议数据结构：

```text
const sessionProgressAnchors = new Map();
let progressRestoreToken = 0;
```

建议触发保存的位置：

```text
setSelectedQuestionKey()
focusFirstQuestion()
focusLastQuestion()
jumpQuestion()
transcript click 选中提问后
刷新和快刷发起前
selectSession() 切换离开旧会话前
```

保存触发需要区分用户意图：

```text
用户点击提问、上下键切换、回到顶部、底部等明确导航动作，应更新 Progress Anchor。
搜索过程中系统自动选择第一条可见结果作为临时选中项时，不应更新 Progress Anchor。
实现上可以给 setSelectedQuestionKey() 增加类似 persistAnchor: false 的选项，用于临时选中。
```

特别注意 `selectSession()` 的顺序：

```text
V0.21 会在切换到不同会话时调用 clearCurrentDetail() 并把 selectedQuestionKey 置空。
保存旧会话锚点必须发生在 clearCurrentDetail() / selectedQuestionKey = null 之前。
如果在置空之后再保存，旧会话的阅读进度已经丢失。
```

建议触发恢复的位置：

```text
selectSession() 加载详情并 renderViewer() 后。
runRefreshRequest() 刷新并 renderViewer() 后。
refreshCurrentSession() 复用 runRefreshRequest() 的恢复逻辑。
清空搜索词或切换搜索范围并调用 renderViewer() 后，如果当前会话存在 Progress Anchor，也应调用 restoreProgressAnchor()。
```

注意：

```text
恢复动作应该发生在 transcript.innerHTML 更新、hydrateOpenLazyDetails()、highlightCurrentQuestion() 之后。
恢复时应该先设置 selectedQuestionKey，再滚动到对应元素。
当 selectSession() 的目标会话已有 Progress Anchor 时，不要同时设置 pendingQuestionFocus = 'last' 触发 renderViewer() 内部滚动。
这类会话应由 restoreProgressAnchor() 负责唯一一次滚动，避免“最后一条提问”和“保存锚点”连续两帧抢滚动位置。
restoreProgressAnchor() 应在 renderViewer() 完成后直接调用 scrollToQuestion(resolvedKey, 'auto')。
restoreProgressAnchor() 不应依赖 pendingQuestionFocus，也不应只依赖 renderViewer() 内部的滚动条件。
原因是 V0.21 的 renderViewer() 只有在 questionFocus 存在或 viewerViewMode === 'all' 时才会自动滚动。
当用户处于“提问”模式且刷新后的 pendingQuestionFocus 为空时，renderViewer() 内部不会触发滚动。
恢复后调用 focusTranscriptForQuestionNavigation({ preventScroll: true })，保证上下键继续可用。
```

## 9. 性能要求

V0.22 不能破坏此前性能要求：

```text
网页打开速度不应明显变慢。
打开后滚动不能变卡。
不能为了保持进度一次性渲染隐藏的过程明细。
不能持续监听所有 DOM 高度变化。
不能在滚动事件里做重计算。
不能为了锚点恢复保存大段正文。
```

建议：

```text
questionTextHash 只保存短 hash，不保存完整问题正文。
sessionProgressAnchors 只保存最近访问过的有限数量会话，例如 200 条。
超出数量时删除最早记录。
恢复滚动只做一次 requestAnimationFrame 或少量稳定帧，不做长循环。
```

## 10. 副作用与规避

### 10.1 原提问找不到

可能原因：

```text
刷新后解析顺序变化。
会话文件被修改。
旧提问被删除或合并。
questionKey 依赖 eventIndex，新增事件插入前面时可能变化。
```

规避：

```text
不要只依赖 questionKey。
增加 questionIndex 和 questionTextHash 兜底。
找不到同一提问时恢复到邻近提问，而不是第一条提问。
```

### 10.2 快刷时 questionKey 集中失效

可能原因：

```text
快刷会重新解析当前会话文件。
如果当前会话在已有事件前插入了新的 system/context/tool 等事件，后续事件的 eventIndex 都会偏移。
由于 questionKey 使用完整事件列表里的 eventIndex，当前会话内多个提问的 questionKey 可能同时失效。
```

规避：

```text
快刷恢复不能只依赖 previousQuestionKey。
必须走 questionTextHash 和 questionIndex 兜底。
快刷后如果 questionKey 未命中，仍应优先找同文本提问或同序号提问，而不是回到第一条。
```

### 10.3 切换会话时保存顺序错误

可能原因：

```text
selectSession() 切换不同会话时会很早调用 clearCurrentDetail() 并清空 selectedQuestionKey。
如果保存旧会话锚点发生在清空之后，旧会话的进度会被保存成空值。
```

规避：

```text
进入新会话前先 captureProgressAnchor() 并保存旧会话锚点。
然后再 clearCurrentDetail() 和切换 selectedSessionKey。
```

### 10.4 视觉位置有少量偏差

可能原因：

```text
图片高度变化。
Markdown 表格重排。
过程明细折叠/展开状态变化。
工具摘要长度变化。
字体加载或浏览器缩放导致高度变化。
```

规避：

```text
以提问框为主锚点，不以绝对 scrollTop 为主。
offsetFromQuestionTop 只作为辅助视觉微调。
不追求像素级完全一致。
```

### 10.5 刷新完成时用户已经切换位置

可能情况：

```text
用户点击刷新后立刻切换来源。
用户点击刷新后立刻切换到另一个会话。
用户点击刷新后立刻手动滚动并选中别的提问。
```

规避：

```text
每次刷新分配 token。
恢复前校验 sourceId、sessionKey、token 是否仍然匹配。
如果用户已经产生新的选中提问，以用户的新操作为准。
```

### 10.6 搜索结果和锚点冲突

可能情况：

```text
当前选中的提问不匹配搜索词。
全局搜索后当前会话不再可见。
切换搜索范围后列表和会话区都重渲染。
```

规避：

```text
搜索模式优先尊重搜索结果。
不可见锚点不强行滚动。
清空搜索或回到可见状态后再恢复会话自身锚点。
```

### 10.7 内存增加

可能原因：

```text
为多个会话保存进度锚点。
```

规避：

```text
只保存轻量字段。
不保存完整消息正文。
限制 Map 数量。
默认不持久化到 localStorage。
```

### 10.8 用户对“快刷后不跳最新”的预期差异

可能情况：

```text
用户刚在 CLI 里发完消息，希望快刷后看到最新回答。
但当前需求要求快刷后保持阅读进度。
```

规避：

```text
V0.22 按用户明确要求保持进度。
如果未来需要“快刷并跳到底部”，另行增加独立入口，不混进当前快刷行为。
```

## 11. 测试与验收

### 11.1 手动验收

需要覆盖：

```text
打开一个长会话，点击中间某个提问，切换到其他会话，再切回来，仍停在原提问。
打开一个长会话，点击中间某个提问，点击刷新，刷新后仍停在原提问。
打开一个长会话，点击中间某个提问，点击快刷，快刷后仍停在原提问。
点击回到顶部后，刷新，仍停在第一个提问。
点击底部后，刷新，仍停在最后一个提问。
只看提问模式下切换和刷新，不丢失当前提问。
搜索模式下刷新，不跳到无关位置。
刷新过程中快速切换会话，不把旧锚点恢复到新会话。
```

### 11.2 自动或脚本测试

建议补充：

```text
captureProgressAnchor 能正确记录 questionKey、questionIndex、offset。
resolveQuestionKeyFromAnchor 在 questionKey 命中时返回原 key。
resolveQuestionKeyFromAnchor 在 questionKey 失效但 hash 命中时返回匹配项。
resolveQuestionKeyFromAnchor 在 hash 也失效时按 questionIndex 兜底。
刷新后 sourceId 或 sessionKey 不一致时不会恢复旧锚点。
```

### 11.3 浏览器验收

实施后需要使用浏览器打开页面验收：

```text
验证刷新和快刷后不会跳到顶部。
验证滚动仍然流畅。
验证上下键仍然可用。
验证切换会话后恢复进度。
验证搜索、只看提问、复制全文、导出 MD、路径、SESSION、回复框不受影响。
```

验收完成后：

```text
关闭打开的浏览器测试页。
关闭测试期间启动的本地服务端口。
如果用户需要使用，再由用户自行打开。
```
