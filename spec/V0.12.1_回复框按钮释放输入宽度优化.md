# Open-CodexChatIndex V0.12.1 回复框按钮释放输入宽度优化

状态：已实现并验收

日期：2026-05-08

## 1. 修改目标

V0.12.1 是 V0.12 的小修补记录，不改变软件显示版本号。

本次只优化会话区底部回复框的输入体验：

```text
清空、复制发送两个按钮不应占用输入框右侧一整列宽度。
输入框正文区域应尽量恢复接近完整宽度。
按钮仍保留在输入框内部或视觉上贴近输入框右下角。
按钮不能挤压整体输入框宽度。
软件大标题和启动窗口版本号仍保持 V0.12，不改成 V0.12.1。
```

## 2. 当前问题

V0.12 当前回复框结构为：

```text
replyComposer
  replyInput textarea
  reply-composer-actions
    清空
    复制发送
```

当前 CSS 中，输入框为了给右下角按钮留位置，使用了较大的右侧内边距：

```text
padding: 12px 150px 52px 14px;
```

这会导致：

```text
输入框右侧约 150px 区域长期不能输入文字。
清空、复制发送两个按钮看起来像占据了一整列。
在会话区宽度较窄时，正文可读宽度明显变小。
长句输入更早换行，降低输入效率。
```

这个问题属于布局设计问题，不是功能逻辑错误。

## 3. 正式设计方向

推荐方案：按钮保持右下角紧凑浮层，但不再占用右侧整列。

### 3.1 输入框释放右侧宽度

将输入框右侧 padding 从大约 150px 降低到正常文本边距，例如：

```text
padding-right: 14px 或 16px;
```

继续保留底部 padding 给按钮区，例如：

```text
padding-bottom: 52px;
```

这样输入文字可以使用完整横向宽度，只有底部最后一小段区域需要避开按钮。

### 3.2 按钮区改为底部横向浮层

按钮区继续绝对定位，但只贴在输入框右下角：

```text
right: 34px;
bottom: 30px;
display: inline-flex;
gap: 6px;
```

按钮应保持紧凑：

```text
清空：较弱按钮，宽度按文字自适应。
复制发送：主按钮，宽度按文字自适应。
两个按钮横向排列，不占据竖向整列。
```

### 3.3 避免按钮遮挡正在输入的文字

由于右侧不再整列避让，底部按钮可能覆盖输入框最后一行右侧区域。

这个风险通过保留底部 padding 解决：

```text
输入框底部留出一行以上操作区高度。
文字可以占满上方完整宽度。
滚动到底部时，最后一行不会被按钮遮挡。
```

如果实测仍有遮挡，可以将底部 padding 增加少量，而不是恢复大右侧 padding。

### 3.4 小屏幕适配

在窄屏或会话区宽度较小时：

```text
按钮仍保持横向排列。
按钮字号和 padding 可以略微压缩。
如果极窄宽度下放不下，允许按钮区换行到两行，但仍不应变成右侧整列占位。
```

建议使用：

```text
max-width: calc(100% - 68px);
flex-wrap: wrap;
justify-content: flex-end;
```

## 4. 不改变的行为

本次只改回复框布局，不改变交互逻辑：

```text
Enter 仍然是复制发送。
Shift + Enter 仍然是换行。
清空按钮仍然清空当前会话草稿。
复制发送按钮仍然复制 codex -C ... resume ... 指令。
回复框仍然自动增高。
超过 20 行后仍然在输入框内部滚动。
草稿仍然按会话保留。
按钮禁用逻辑不变。
toast 提示不变。
```

版本号要求：

```text
页面大标题仍显示 V0.12。
Open-CodexChatIndex.cmd 窗口标题仍显示 V0.12。
Build-CodexChatIndex.ps1 的 builderVersion 仍保持 V0.12。

```

## 5. 副作用和风险

### 5.1 底部按钮可能遮挡最后一行

释放右侧 padding 后，按钮不再拥有整列避让空间。

可能影响：

```text
输入内容滚动到底部时，最后一行右下角可能被按钮盖住。
```

应对：

```text
保留足够的 padding-bottom。
重点测试 1 行、2 行、10 行、20 行和超过 20 行的输入。
如有遮挡，只增加底部 padding，不恢复大右侧 padding。
```

### 5.2 按钮浮层与滚动条距离更近

按钮贴右下角后，可能离输入框内部滚动条更近。

可能影响：

```text
鼠标点击滚动条时可能更容易靠近按钮。
```

应对：

```text
右侧仍保留 12px 到 16px 间距。
按钮区不贴死到输入框边缘。
```

### 5.3 小屏幕按钮换行

在极窄会话区里，两个按钮横向放置可能空间不足。

可能影响：

```text
按钮可能换成两行。
底部占用高度略增。
```

应对：

```text
允许按钮区 flex-wrap。
输入框底部 padding 与按钮实际高度匹配。
保持按钮不挤压 textarea 宽度。
```

### 5.4 观看体验变化

预期改善：

```text
回复框正文更宽。
长句更少提前换行。
右侧不再出现明显空白列。
按钮从“占一列”变成“角落操作区”，视觉更轻。
```

可能变化：

```text
底部最后一行输入区域会主动让出按钮高度。
按钮与正文距离更近，需要通过留白保持不拥挤。
```
