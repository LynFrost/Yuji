# Open-CodexChatIndex V0.11 修改文档

状态：已实现并验收

日期：2026-05-07

## 1. 修改目标

V0.11 的目标是修复标题区点击选择时滚动位置被意外改变的问题，并将会话区搜索升级为全库级筛选能力。

本版本重点优化：

```text
点击标题区任意标题或分支时，标题区滚动条位置不应被自动向下带动。
会话区搜索框不再只搜索当前会话，而是搜索所有目录、所有标题下的所有会话内容。
搜索命中后，目录区和标题区同步筛出包含命中会话的目录、标题和分支。
搜索无命中时，目录区、标题区、会话区显示空结果，行为和当前无匹配提示保持一致。
```

本版本不改变以下既有能力：

```text
智能增量刷新。
当前会话快刷。
全量重建。
SESSION 复制。
复制发送命令。
回复草稿保留。
提问定位。
上下键切换提问。
回到顶部后自动聚焦。
只看提问。
过程懒渲染。
复制全文。
导出 MD。
复制路径。
复制 SESSION。
打开速度和滚动流畅性优先级。
```

## 2. 标题区点击后滚动位置保持

### 2.1 当前问题

当前点击标题区某个标题时，标题区滚动条可能继续向下滚动。

已观察到的规律：

```text
当标题区滚动条位于最顶部时，这个问题通常不会发生。
当标题区滚动条已经不在最顶部时，点击标题后更容易发生滚动条被向下带动。
```

这会导致用户点击一个标题后，标题区视野发生意外变化，不利于连续查看相邻标题。

### 2.2 目标行为

V0.11 要求：

```text
点击标题区标题时，标题区滚动位置保持不变。
点击标题区分支时，标题区滚动位置保持不变。
点击后仍然要更新标题区选中提示。
点击后会话区仍然自动聚焦到最后一个提问。
点击后仍然可以直接用上下键切换提问。
```

### 2.3 实现建议

建议优先从减少标题区重绘入手：

```text
选择会话时，尽量只更新选中状态，不重新生成整个标题列表。
如果现有结构需要重新渲染标题列表，则在重绘前记录 sessionList.scrollTop，重绘后恢复该值。
恢复滚动位置时使用同步赋值或 requestAnimationFrame 后赋值，避免浏览器焦点自动滚动覆盖恢复结果。
给标题按钮聚焦或给会话区聚焦时使用 preventScroll。
```

实现时应避免：

```text
不要为了选中提示调用 scrollIntoView 之类会主动改变标题区滚动位置的逻辑。
不要把标题区滚动锁定做成全局禁止滚动，否则用户主动滚动标题区会受影响。
不要牺牲点击标题后会话区键盘导航能力。
```

## 3. 会话区搜索升级为全库筛选

### 3.1 搜索范围

V0.11 将会话区顶部搜索框定义为全库会话搜索。

搜索范围为：

```text
所有目录。
所有标题。
所有会话分支。
每个会话中的用户提问、最终回答、过程摘要、工具摘要、系统摘要。
必要时也应覆盖过程明细和工具原始输出中未默认渲染的内容。
```

也就是说，这个搜索框同时承担“搜索”和“筛选”的作用。

### 3.2 搜索后的三栏联动

输入搜索关键词后：

```text
目录区只显示包含命中会话的目录。
标题区只显示当前可见目录中包含命中会话的标题和分支。
会话区只显示当前选中命中会话中匹配搜索条件的内容。
```

如果当前选中的目录或会话不在命中结果中：

```text
目录区仍然只显示命中目录。
标题区仍然只显示命中标题。
会话区显示无匹配提示或空白状态，不应偷偷跳到其他会话。
```

这样可以避免用户误以为自己仍然停留在原会话，实际却被自动切换到了另一条会话。

清空搜索框后：

```text
目录区恢复原完整目录列表。
标题区恢复当前目录下的完整标题列表。
会话区恢复当前选中会话的完整显示。
```

### 3.3 搜索无命中

如果全库没有任何命中：

```text
目录区显示无匹配。
标题区显示无匹配。
会话区显示无匹配或空白提示。
```

行为要和当前搜索无结果的体验一致，不弹窗、不打断。

### 3.4 和标题筛选的关系

V0.11 不建议新增第二个“全库搜索框”。

建议规则：

```text
标题区原有筛选框继续用于筛选标题、摘要、路径等轻量信息。
会话区搜索框升级为全库正文搜索，并联动筛选目录区和标题区。
两个筛选条件可以叠加。
```

叠加后的可见结果应满足：

```text
同时满足目录区筛选条件。
同时满足标题区筛选条件。
同时满足会话区全库正文搜索条件。
同时满足 provider/source 等筛选条件。
```

## 4. 搜索性能与内存设计

### 4.1 不建议的实现

V0.11 不建议在网页打开时一次性加载所有会话详情。

原因：

```text
会明显增加网页首次打开时间。
会增加浏览器内存占用。
会破坏 V0.06 以来建立的过程懒渲染和大体量会话保护策略。
大量隐藏正文进入 DOM 或 JS 内存后，可能造成滚动变卡。
```

也不建议在每次输入时由前端逐个 fetch 所有会话详情文件。

原因：

```text
第一次搜索会触发大量请求。
输入较快时容易出现过期结果覆盖新结果。
在会话很多时响应时间不可控。
```

### 4.2 推荐实现

推荐在构建索引时生成独立的轻量搜索索引。

建议结构：

```text
主 data 文件继续保持轻量，只负责目录、标题、会话元信息。
每个会话详情文件继续按需加载。
新增搜索索引用于全库正文匹配。
搜索索引不直接进入主 HTML。
搜索索引不在网页打开时默认加载。
```

实现方式可以有两种：

```text
方案 A：server 侧搜索，前端调用 /api/search，由 Python server 读取搜索索引并返回命中的 session key。
方案 B：前端首次全库搜索时懒加载搜索索引，再在浏览器内完成匹配。
```

推荐采用方案 A。

推荐理由：

```text
浏览器内存压力更小。
网页打开速度更稳定。
搜索索引可以保留在本地运行数据中，不污染主页面。
后续可以更容易加入命中数量、命中片段、搜索耗时等信息。
```

### 4.3 搜索交互节流

搜索输入建议增加防抖。

建议规则：

```text
用户连续输入时，不对每个字符立即触发完整搜索。
输入停止约 200-300ms 后再执行搜索。
新的搜索发起后，旧搜索结果如果晚返回，应被丢弃。
清空搜索框时立即恢复完整列表，不等待防抖。
```

这样可以减少重复搜索，也可以避免旧结果覆盖新结果。

### 4.4 搜索内容完整性

搜索必须尽量覆盖未默认渲染的内容。

原因：

```text
V0.06 起过程明细和工具结果默认懒渲染。
用户搜索时不应因为内容没有展开就搜不到。
```

建议索引内容包括：

```text
用户提问 rawText。
最终回答 rawText。
过程 summary 和 rawText。
工具 toolName、status、summary 和 rawText。
系统 summary 和 rawText。
标题、摘要、路径、工作目录。
```

如果为了体积控制需要压缩原始内容，也必须在文档和实现中明确压缩规则，避免用户以为全库搜索覆盖全部内容但实际漏搜。

## 5. 选择与显示规则

### 5.1 搜索时是否自动切换会话

V0.11 建议不自动切换到第一个搜索结果。

理由：

```text
用户可能只是想筛出所在目录和标题。
自动跳转可能造成上下文误判。
搜索框正在输入时频繁切换会话也会增加闪动和加载成本。
```

建议行为：

```text
如果当前会话命中，则会话区显示当前会话中的命中内容。
如果当前会话不命中，则会话区显示无匹配提示。
用户可以手动点击目录区或标题区中的命中项进入对应会话。
```

### 5.2 搜索时标题区显示

标题区应保留现有分组结构：

```text
同源标题仍按标题分组。
多分支标题仍显示分支。
只有命中的分支显示出来。
如果一个标题下只有一个命中分支，则不额外展示空的三级分支结构。
```

现有关于“单分支不显示三级区分”的规则继续保留。

### 5.3 搜索时会话区显示

会话区搜索仍然需要保留现有正文匹配能力：

```text
当前选中会话命中时，只显示当前会话中匹配关键词的内容。
过程懒渲染仍然保留。
未展开的过程和工具内容如果命中，应能通过摘要提示用户存在命中。
复制全文和导出 MD 不因为搜索过滤而丢失完整内容。
```

## 6. 副作用和风险

### 6.1 标题区滚动锁定

可能影响：

```text
点击一个标题后，标题区不会自动滚动到选中项附近。
```

这是符合本版本目标的行为。选中提示仍然保留，会话区仍然自动聚焦，键盘导航仍然可用。

### 6.2 全库搜索带来的认知变化

会话区搜索框从“当前会话内搜索”变成“全库筛选”后，目录区和标题区会跟着变化。

可能影响：

```text
用户输入搜索词后，会看到左侧目录和标题列表同步减少。
清空搜索词后，列表会恢复。
```

这是功能目标本身。实现时应通过无匹配提示、placeholder 或简洁状态文案降低误解。

### 6.3 搜索性能

全库正文搜索一定比当前会话内搜索更重。

缓解方式：

```text
使用独立搜索索引。
优先采用 server 侧搜索。
搜索输入防抖。
丢弃过期搜索结果。
不在打开网页时加载全部正文。
不把全部会话详情渲染进 DOM。
```

这样可以把影响集中在“用户正在搜索”的时刻，而不是拖慢网页打开和日常滚动。

### 6.4 构建和刷新成本

新增搜索索引后，构建和刷新会多一份索引写入成本。

影响：

```text
全量重建会略慢。
智能增量刷新需要更新新增或变更会话对应的索引内容。
当前会话快刷需要同步更新当前会话对应的索引内容。
运行数据目录会新增搜索索引文件，磁盘占用增加。
```

但这比打开网页时一次性加载所有正文更可控，也更符合滚动不卡和内存尽量低的要求。

### 6.5 搜索命中完整性

如果搜索索引为了体积做截断，就可能出现漏搜。

V0.11 建议：

```text
默认不截断用户提问和最终回答。
过程、工具、系统内容如需压缩，也要优先保留可搜索的原始文本或明确标注压缩范围。
测试必须覆盖未默认渲染的过程和工具内容可以被全库搜索命中。
```

V0.11 验收时应满足：

```text

点击标题后会话区仍自动聚焦到最后一个提问。
点击标题后上下键导航仍然立即可用。
会话区搜索框可以搜索所有目录、所有标题、所有会话内容。

搜索无命中时，三栏显示空结果或无匹配提示。
清空搜索后，列表和会话区恢复正常。
搜索不导致网页打开明显变慢。
搜索不导致日常滚动变卡。
复制全文、导出 MD、快刷、回复框、路径、SESSION 等既有功能不回退。
```
