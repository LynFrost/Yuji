# Open-CodexChatIndex V0.15 回复框输入流畅度与拼写检查关闭优化

状态：已实现并验收

日期：2026-06-04

## 1. 修改目标

V0.15 的目标是优化会话区底部回复框的输入体验，减少输入文字时的轻微卡顿，并关闭输入框中意义不明的下波浪线。

本版本重点优化：

```text
回复框输入文字时应更流畅，减少每次按键触发的同步布局计算。
回复框不再显示浏览器拼写检查或语法检查产生的下波浪线。
Enter 仍然是复制发送快捷键。
Shift + Enter 仍然是换行快捷键。
清空、复制发送、草稿保留、20 行高度上限和内部滚动都不能回退。
```

加载流畅度方面，V0.15 只考虑低风险优化：

```text
当前加载效果已经可接受，不做大结构改造。
不改索引结构。
不改详情分片结构。
不改搜索 API。
不改 notes.json 数据结构。
如果有收益，只做不影响主流程的调度优化。
```

## 2. 当前问题和根因判断

### 2.1 输入轻微卡顿

V0.14 当前回复框输入链路为：

```text
replyInput input
persistReplyDraft()
replyDrafts.set(...)
updateReplyComposerState()
buildReplyResumeCommand(...)
autoResizeReplyInput()
getComputedStyle(...)
scrollHeight 读写
style.height = auto
style.height = nextHeight
style.overflowY = ...
```

其中存在几个性能敏感点：

```text
每次按键都同步执行 autoResizeReplyInput。
autoResizeReplyInput 每次都调用 getComputedStyle。
autoResizeReplyInput 每次都读 scrollHeight，并多次写 style.height。
updateReplyComposerState 每次都调用 buildReplyResumeCommand。
buildReplyResumeCommand 会对完整回复文本做转义和拼接，但输入时只是为了判断按钮是否可用。
中文 IME 组合输入期间，input 事件仍会触发上述完整路径。
```

这类操作单次不重，但在连续输入时会和浏览器排版、滚动条状态、输入法组合过程叠加，表现为轻微卡顿。

### 2.2 下波浪线

V0.14 当前回复框是普通 textarea：

```html
<textarea id="replyInput" rows="2" placeholder="输入回复内容。Enter 复制发送，Shift + Enter 换行。"></textarea>
```

没有显式关闭浏览器拼写检查。

因此输入时出现的下波浪线，最可能是浏览器原生拼写检查或语法检查，不是 Open-CodexChatIndex 自己的功能。

## 3. 正式设计方向

### 3.1 输入事件只做最小同步工作

输入时应只同步做必须马上完成的事情：

```text
把当前 textarea.value 保存到内存草稿 Map。
记录需要更新回复框状态。
```

不应在每次 input 同步执行：

```text
完整构建 codex resume 命令。
完整计算 textarea 高度。
多次读写布局相关属性。
```

### 3.2 回复框状态更新改为帧合并

新增一个轻量调度函数，例如：

```text
scheduleReplyComposerUpdate()
```

行为：

```text
如果当前已经有待执行的 requestAnimationFrame，则不重复安排。
下一帧统一执行按钮状态更新和自动高度调整。
同一帧内多个 input 事件只触发一次布局计算。
```

建议链路：

```text
replyInput input
saveReplyDraftValueOnly()
scheduleReplyComposerUpdate()

requestAnimationFrame
updateReplyComposerState()
autoResizeReplyInput()
```

这样可以把密集输入时的同步压力降下来。

### 3.3 按钮可用性改为轻量判断

当前 `updateReplyComposerState()` 为了判断复制发送按钮是否可用，会调用完整的：

```text
buildReplyResumeCommand(session, text)
```

V0.15 建议拆出轻量判断：

```text
canBuildReplyResumeCommand(session, text)
```

只判断：

```text
session 存在。
session.id 存在。
工作目录 cwd 存在。
text.trim() 非空。
```

真正点击“复制发送”时，再调用：

```text
buildReplyResumeCommand(session, text)
```

这样避免每次按键都对完整文本做转义和命令拼接。

### 3.4 自动高度计算缓存静态尺寸

`autoResizeReplyInput()` 中的这些值在样式不变时基本固定：

```text
lineHeight
paddingTop
paddingBottom
borderTop
borderBottom
maxHeight
```

V0.15 建议缓存这些尺寸。

推荐方式：

```text
首次需要自动高度时计算一次。
窗口 resize 或字体尺寸可能变化时清空缓存。
回复框重新显示时允许重新计算。
```

每次输入仍然需要读取 `scrollHeight`，但应避免每次都重新 `getComputedStyle`。

### 3.5 中文输入法组合期间减少重布局

当前已有：

```text
compositionstart
compositionend
replyInputIsComposing
```

但这个标记主要用于 Enter 快捷键判断。

V0.15 建议扩展使用：

```text
compositionstart 后，input 期间只保存草稿，不立即重布局。
compositionend 后，统一 scheduleReplyComposerUpdate。
```

这样可以减少中文输入法候选过程中被同步布局打断。

### 3.6 关闭拼写检查和自动纠正

回复框应增加：

```html
spellcheck="false"
autocomplete="off"
autocorrect="off"
autocapitalize="off"
```

目的：

```text
关闭浏览器原生拼写检查或语法检查下波浪线。
避免浏览器在输入过程中额外分析文本。
避免自动纠正干扰命令文本。
```

如果某些浏览器扩展仍然强行注入波浪线，应用侧不能完全控制，但原生浏览器检查应被关闭。

## 4. 加载流畅度谨慎优化

当前加载效果已经可接受，所以 V0.15 不建议做高风险加载重构。

不建议改动：

```text
索引数据结构。
详情 shard 结构。
搜索索引生成方式。
刷新和快刷 API。
首个会话详情加载逻辑。
```

可讨论的低风险优化只有一个：

```text
主索引和首屏先渲染。
notes 备注数据在首屏后异步加载。
notes 加载完成后，只给已有标题按钮补充 has-note 标记和备注浮窗数据。
```

这个优化的收益可能有限，因为 `CodexChatIndex.notes.json` 通常很小。

潜在副作用：

```text
首屏刚出现时，备注小圆点可能短暂缺失。
notes 加载完成后，小圆点补出现，用户可能看到轻微视觉变化。
```

建议 V0.15 的正式策略：

```text
优先解决回复框输入流畅度和下波浪线。
加载优化只作为可选低风险项写入文档。
除非浏览器验收确认没有明显闪动，否则不强行改启动流程。
```

## 5. 不改变的行为

V0.15 不应改变以下行为：

```text
回复框仍按会话保留草稿。
切换会话后仍能恢复对应草稿。
点击清空仍能清空当前会话草稿。
点击复制发送仍复制完整 codex -C ... resume ... 命令。
Enter 仍触发复制发送。
Shift + Enter 仍插入换行。
中文输入法组合期间按 Enter 不误触发复制发送。
回复框仍自动增高。
回复框仍限制最多 20 行高度。
超过 20 行后仍显示内部滚动。
复制发送按钮和清空按钮禁用状态仍正确。
```

## 6. 副作用和风险

### 6.1 按钮状态会延后一帧更新

把状态更新放到 `requestAnimationFrame` 后：

```text
复制发送按钮和清空按钮的 disabled 状态可能比输入晚一帧。
通常约 16ms，用户基本无感。
```

应对：

```text
点击复制发送时仍实时读取 textarea.value。
不能只依赖按钮状态判断。
```

### 6.2 自动高度变化会延后一帧

自动高度从同步更新改为帧合并后：

```text
刚输入导致换行或新增行时，高度可能晚一帧变化。
```

应对：

```text
一帧延迟换取输入流畅度。
复制发送、清空、切换会话时可强制 flush 一次高度更新。
```

### 6.3 缓存尺寸可能在字体变化后失效

如果缓存 lineHeight、padding 等尺寸：

```text
浏览器缩放、窗口变化或 CSS 变化后，旧缓存可能不准确。
```

应对：

```text
窗口 resize 时清空缓存。
回复框重新显示时允许重新计算。
计算异常时回退到当前 getComputedStyle 逻辑。
```

### 6.4 禁用拼写检查会失去英文纠错

`spellcheck="false"` 的直接结果：

```text
英文拼写错误不会再出现浏览器提示。
```

这是符合需求的副作用，因为回复框主要用于复制命令文本，不是富文本写作编辑器。

### 6.5 延后 notes 加载可能产生短暂视觉变化

如果实施加载流畅度可选优化：

```text
备注小圆点可能在首屏后补出现。
```

应对：

```text
如果浏览器验收中能看到明显闪动，则放弃该项优化。
V0.15 不应为了小收益引入新的观看干扰。
```
