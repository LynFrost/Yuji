# Open-CodexChatIndex V0.14 标题区备注标记与选中状态一致性优化

状态：已实现并验收

日期：2026-05-17

## 1. 修改目标

V0.14 的目标是修复 V0.13 中“带备注标题被选中后，选中状态不明显”的视觉问题。

本版本重点优化：

```text
标题区标题无论是否带备注，被选中时都应显示完全一致的选中样式。
用户应能一眼看出当前选中的是哪个标题或分支。
是否带备注仍然要能被看出来，但不能影响选中状态。
备注状态不再通过整张卡片的背景、边框、阴影表达。
备注状态改为独立小标记，例如右上角小圆点或折角标记。
```

本版本不改变以下既有能力：

```text
备注保存位置。
备注 key 绑定规则。
备注右键菜单。
备注新建、编辑、删除弹窗。
备注悬停浮窗。
无备注时原生 title 悬停。
标题区点击零抖动。
标题区筛选和排序。
会话区全库搜索。
提问定位和上下键切换。
快刷、刷新、全量重建。
回复框和复制发送命令。
```

## 2. 当前问题和根因

V0.13 为有备注的标题项增加了 `.has-note` 样式。

当前大致逻辑为：

```text
.title-group-head.active / .session-btn.active
  用背景、边框、阴影表示选中。

.title-group-head.has-note / .session-btn.has-note
  也用背景、边框、阴影表示有备注。
```

由于 `.has-note` 样式和 `.active` 样式都在竞争同一批视觉属性：

```text
border-color
background
box-shadow
```

并且 `.has-note` 写在 `.active` 后面，或与 `.active` 优先级接近，最终会出现：

```text
带备注标题被选中时，备注样式覆盖或削弱选中样式。
用户看不清当前选中的是哪个标题。
```

这不是会话选择逻辑错误，而是视觉状态设计冲突。

## 3. 正式设计原则

V0.14 应把“选中状态”和“备注状态”拆成两层表达。

### 3.1 选中状态负责整张卡片

选中状态继续控制标题项的主要视觉：

```text
背景色
边框色
外圈或阴影
左侧选中强调条
```

选中样式必须保持一致：

```text
选中无备注标题 = 统一选中样式
选中有备注标题 = 统一选中样式 + 备注小标记
```

用户判断当前标题时，不需要再思考该标题是否有备注。

### 3.2 备注状态只负责独立小标记

备注状态不再改变整张标题卡片的主要背景、边框或阴影。

备注状态只增加一个独立标记：

```text
右上角暖黄色小圆点
或右上角纸片折角
或标题项右侧很小的“备”标记
```

推荐实现：

```text
使用 ::after 伪元素绘制右上角小圆点或折角。
不额外增加 DOM 节点。
不挤占标题文字宽度。
不改变标题项高度。
```

最终状态矩阵：

```text
普通无备注：普通标题样式
普通有备注：普通标题样式 + 备注小标记
选中无备注：统一选中样式
选中有备注：统一选中样式 + 备注小标记
```

### 3.3 视觉优先级

V0.14 的视觉优先级应明确为：

```text
选中状态 > hover 状态 > 普通状态
备注标记独立存在，不参与背景、边框、阴影竞争
```

也就是说：

```text
hover 不能覆盖 active。
has-note 不能覆盖 active。
active.has-note 和 active 应在主体卡片上看起来一致。
```

## 4. 样式设计建议

### 4.1 标题项需要 position: relative

为了放置备注小标记，标题按钮需要支持伪元素定位。

建议：

```text
.title-group-head,
.session-btn {
  position: relative;
}
```

该修改不应改变布局。

### 4.2 备注标记使用伪元素

推荐小圆点方案：

```text
.title-group-head.has-note::after,
.session-btn.has-note::after {
  content: "";
  position: absolute;
  top: 8px;
  right: 8px;
  width: 8px;
  height: 8px;
  border-radius: 999px;
  background: #b7791f;
  box-shadow: 0 0 0 2px rgba(255,250,242,.9);
}
```

如果选中背景较深，可以给选中态下的标记增加白色外圈：

```text
.title-group-head.active.has-note::after,
.session-btn.active.has-note::after {
  box-shadow: 0 0 0 2px rgba(255,255,255,.9);
}
```

### 4.3 移除 has-note 对主体卡片的覆盖

V0.13 当前 `.has-note` 不应继续设置：

```text
border-color
background
box-shadow
```

这些属性应交还给普通、hover、active 状态。

如果还想让普通有备注标题略微可见，可以只保留极轻量的非竞争属性：

```text
无布局影响的小标记。
必要时增加 title 行内末尾的小标记，但不建议 V0.14 做。
```

### 4.4 选中态保持统一

应避免新增不同的主体样式：

```text
.title-group-head.active.has-note
.session-btn.active.has-note
```

如果新增，也只能用于保护一致性，例如：

```text
background: 与 .active 完全一样
border-color: 与 .active 完全一样
box-shadow: 与 .active 完全一样
```

不能让有备注的选中标题呈现另一套主体样式。

## 5. 交互设计

V0.14 不改变备注交互。

仍然保持：

```text
右键有备注标题：编辑备注、删除备注。
右键无备注标题：新建备注。
鼠标悬停有备注标题：显示自定义备注浮窗。
鼠标悬停无备注标题：保持原生 title。
保存、编辑、删除备注后，标题项备注标记即时更新。
```

需要补充的交互要求：

```text
选中有备注标题时，备注小标记仍可见。
hover 选中有备注标题时，选中主体样式仍保持不变。
删除备注后，小标记立即消失，但选中状态保持。
新增备注后，小标记立即出现，但选中状态保持。
```

## 6. 性能和内存影响

V0.14 预期不会影响打开速度、滚动性能或内存。

原因：

```text
主要修改是 CSS。
备注小标记用伪元素实现，不增加 DOM 节点。
不新增 API。
不新增数据读取。
不改变 notes.json 结构。
不改变标题区渲染数量。
```

可能的渲染成本：

```text
浏览器需要为 has-note 标题绘制一个小伪元素。
该成本极低，远小于已有标题列表渲染成本。
```

## 7. 副作用和风险

### 7.1 备注存在感会比 V0.13 略低

V0.13 使用整张卡片暖黄色背景表达备注。

V0.14 改成小标记后：

```text
备注提示不再像整张卡片变色那么强。
用户需要注意右上角小标记。
```

应对：

```text
小标记颜色使用暖棕色或金黄色，和整体风格协调但足够醒目。
悬停有备注标题仍会显示明显的备注浮窗。
右键菜单仍会根据是否有备注显示不同操作。
```

### 7.2 小标记可能遮挡极短标题区域

右上角小圆点或折角可能覆盖少量文字空间。

应对：

```text
标记尺寸控制在 8px 左右。
放在按钮右上角边缘。
必要时给标题项右侧增加极小 padding，例如 18px，但不能明显压缩标题宽度。
```

### 7.3 CSS 状态规则需要更清晰

从“has-note 直接改卡片样式”改成“has-note 只画标记”，需要避免未来再次把备注态写回主体样式。

应对：

```text
测试中明确禁止 has-note 主体规则设置 background、border-color、box-shadow。
文档中明确选中态控制主体卡片，备注态只控制独立标记。
```

### 7.4 视觉回归需要浏览器验收

CSS 修改很小，但视觉目标非常具体。

应对：

```text
必须用当前 notes.json 中已有真实备注项验收。
同时验收大标题和子标题。
同时验收有备注选中、无备注选中、hover 有备注选中、删除备注后仍选中。
```
