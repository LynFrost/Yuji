### 2.2 标题误判根因

问题截图：

```text
软件/文档/BUG_V0.29/Snipaste_2026-08-02_12-01-27.png
```

当前 `Build-CodexChatIndex.ps1` 已有 `Test-IsInjectedCodexContextMessage()`，可以识别以下“整条消息只包含一个系统区块”的情况：

```text
<environment_context>...</environment_context>
<permissions instructions>...</permissions instructions>
<collaboration_mode>...</collaboration_mode>
<skills_instructions>...</skills_instructions>
<app-context>...</app-context>
<subagent_notification>...</subagent_notification>
<turn_aborted>...</turn_aborted>
AGENTS.md 指令块
```

用户给出的真实故障消息是一条连续内容：

```text
<recommended_plugins>...</recommended_plugins>
<environment_context>...</environment_context>
```

现有逻辑存在两个缺口：

```text
1. 白名单没有 recommended_plugins。
2. 判断要求整条消息恰好等于单个区块，不能顺序处理多个连续区块。
```

因此该消息被生成成普通 user 事件。后续标题逻辑直接取过滤后第一条 user 事件的第一行，最终大量标题变成 `<recommended_plugins>`，同时注入内容还会错误参与提问计数、导航、搜索、复制和导出。

## 5. 图片弹窗滚轮缩放与左键拖动

### 5.1 交互规则

图片弹窗打开时：

```text
滚轮向上：放大。
滚轮向下：缩小。
缩放中心：鼠标指针当前指向的图片位置。
初始适配状态：100%。
最小比例：25%。
最大比例：500%。
标准鼠标滚轮每个逻辑刻度约调整 10%。
放大超过适配尺寸后：按住鼠标左键拖动图片。
```

不新增必须操作的缩放按钮，不改变现有关闭、上一张、下一张和计数布局。

### 5.2 缩放和拖动状态

在现有图片组状态之外增加单一预览状态对象，至少包含：

```text
scale：当前缩放比例，初始 1。
translateX：当前水平位移，初始 0。
translateY：当前垂直位移，初始 0。
pointerId：当前拖动指针，没有拖动时为空。
dragStartX / dragStartY：按下位置。
dragOriginX / dragOriginY：拖动开始时的位移。
dragMoved：是否超过拖动阈值。
wheelFrame：待处理滚轮动画帧。
dragFrame：待处理拖动动画帧。
```

增加统一入口：

```text
resetImagePreviewTransform()
applyImagePreviewTransform()
queueImagePreviewZoom(event)
clampImagePreviewTranslation()
```

所有缩放、平移、切图和关闭操作必须只维护这一套状态，不允许箭头切图、滚轮和拖动各自保存独立比例或位移。

### 5.3 以指针为中心缩放

V0.29 的 `imagePreviewStage` 当前是随图片内容收缩的 `inline-flex` 容器。V0.30 不能直接在该结构上只增加 transform，否则图片放大到原容器以外后，外侧区域不能稳定接收滚轮和拖动。

图片舞台必须先改成固定的预览视口：

```text
桌面端占据关闭按钮和左右箭头之间的中央可用区域。
窄屏端占据扣除安全边距后的中央可用区域。
使用 display: flex 居中初始图片。
使用 overflow: hidden 裁切放大后超出视口的部分。
初始图片继续按 contain 方式适配，不拉伸小图。
计数和加载失败提示继续相对舞台定位。
点击舞台中图片以外的空白区域仍按既有规则关闭弹窗。
```

这样缩放后的图片始终在一个尺寸稳定的视口中平移，舞台边界也可作为位移限制的唯一测量基准。

滚轮监听固定注册在 `imagePreviewStage`，并使用 `{ passive: false }`，以便只在实际缩放时调用 `preventDefault()`。

处理规则：

```text
1. 图片弹窗未打开、图片加载失败或指针不在图片舞台内时不处理。
2. 读取指针相对于图片舞台的位置。
3. 将高分辨率触控板或鼠标滚轮的 delta 归一化并按动画帧合并。
4. 一个标准滚轮逻辑刻度使用约 1.1 的乘法比例；单帧变化设置上限，避免触控板一次滑动突然放到 500%。
5. 新比例限制在 0.25 到 5.0。
6. 调整 translateX / translateY，使缩放前指针下的图片内容在缩放后仍尽量位于同一指针位置。
7. 对位移做边界限制，防止图片被拖到完全看不见。
8. 只更新 transform，不修改图片 src，不重建模态框或会话 DOM。
```

滚轮只在图片舞台内被接管：

```text
图片弹窗外的页面滚动不受影响。
指针位于模态背景、关闭按钮或左右箭头时不触发缩放。
触控板双指滚动在图片舞台内与鼠标滚轮一致，作为缩放处理。
```

### 5.4 左键拖动

拖动规则：

```text
只响应主鼠标左键。
只有 scale > 1 时允许拖动；缩小状态保持居中，不允许把小图拖离中心。
pointerdown 后设置 pointer capture，避免指针短暂离开图片导致拖动中断。
移动超过 4 px 才认定为拖动，低于阈值仍视为普通点击。
pointermove 只记录最新目标位移，由 requestAnimationFrame 合并更新。
pointerup、pointercancel、关闭和切图时都必须释放 pointer capture 并清理状态。
图片使用 user-select: none，并阻止浏览器原生图片拖拽幽灵图。
可拖动时光标为 grab，拖动中为 grabbing。
```

位移限制目标：

```text
允许查看放大图片的四角和边缘。
不允许把整张图片拖出可视区域。
窗口尺寸变化后重新限制当前位移。
```

### 5.5 点击关闭边界

现有规则保持：点击图片和预览控制项以外的模态空白区域关闭。

新增拖动后必须保证：

```text
点击图片本身不关闭。
拖动图片结束不关闭。
点击左右箭头、计数和关闭按钮保持原功能。
拖动产生的 click 如果 dragMoved 为 true，则拦截该次 click，不能冒泡成背景关闭。
真正点击图片外空白区域仍立即关闭。
```

### 5.6 切图、关闭和焦点

以下时机必须调用 `resetImagePreviewTransform()`：

```text
首次打开图片预览。
成功切换到上一张或下一张之前。
关闭图片预览时。
当前图片加载失败时。
```

关闭时继续执行 V0.29 已有清理：

```text
清空 imagePreviewImage.src 和 alt。
清空图片按钮引用集合。
重置图片索引。
将焦点返回最后查看图片对应的缩略图按钮。
```

缩放状态不能跨图片、跨提问或跨会话保留。

### 5.7 性能和内存要求

```text
只复用唯一的 imagePreviewImage，不创建隐藏的大图副本。
不复制 Base64 字符串，不为每个缩放级别生成位图。
使用 CSS transform，不通过 width / height 高频触发布局。
wheel 和 pointermove 都按动画帧合并，不能每个原始事件重渲染。
缩放和拖动不得调用 renderViewer()、renderSessionList() 或 renderWorkspaceList()。
关闭时取消尚未执行的动画帧并清空状态，避免持续持有 DOM 和事件数据。
```

## 6. Codex 系统注入内容清洗与标题修复

### 6.1 设计原则

采用“严格白名单 + 前导顺序解析”，不采用泛化 XML、HTML 或尖括号正则。

目标：

```text
能够识别一条消息开头连续出现的一个或多个已知系统注入区块。
系统区块后有真实用户文字或图片时，只删除前导注入并保留真实内容。
整条消息完全由注入区块组成时，不生成用户提问事件。
普通正文中间或末尾出现同名标签时不处理。
未知标签、未闭合标签和大小写不匹配标签不删除。
```

### 6.2 初始白名单

V0.30 首批白名单固定为：

```text
<recommended_plugins>...</recommended_plugins>
<environment_context>...</environment_context>
<app-context>...</app-context>
<permissions instructions>...</permissions instructions>
<collaboration_mode>...</collaboration_mode>
<skills_instructions>...</skills_instructions>
<apps_instructions>...</apps_instructions>
<plugins_instructions>...</plugins_instructions>
<subagent_notification>...</subagent_notification>
<turn_aborted>...</turn_aborted>
# AGENTS.md instructions for ... <INSTRUCTIONS>...</INSTRUCTIONS>
```

白名单集中维护在一个位置。未来发现新的系统区块时，只增加白名单项和对应测试，不扩大为任意标签删除。

### 6.3 顺序解析函数

将现有单一布尔判断重构为返回清洗结果的辅助函数，建议命名：

```text
Remove-CodexInjectedContextPrefix
```

返回结构至少包含：

```text
Text：剥离后的正文。
Changed：是否剥离过至少一个完整区块。
FullyInjected：剥离后是否没有真实文字。
RemovedBlockCount：剥离的区块数量，仅供测试和诊断，不写入页面正文。
```

解析步骤：

```text
1. 保留原始输入，不先做会吞掉内部内容的全局替换。
2. 从消息开头开始，允许跳过 UTF-8 BOM 和前导空白。
3. 只匹配白名单中完整且正确闭合的区块。
4. 找到一个完整区块后前进到其结束位置，并跳过区块之间的空白。
5. 继续尝试下一个白名单区块，直到不再匹配。
6. 返回剩余真实正文；真实正文只做与现有用户消息一致的 Trim，不改变内部 Markdown。
7. 若第一个前导内容不是白名单完整区块，则原文原样返回。
```

实现不得使用一个跨全部内容的贪婪 `.*` 来猜测多个区块，避免误吞真实问题和在超长插件列表上产生不必要的正则回溯。

### 6.4 两条 Codex 用户消息入口统一处理

以下两条入口必须在生成 `New-ReaderEvent -Kind 'user'` 之前调用同一清洗函数：

```text
response_item / message / role=user
event_msg / user_message
```

统一处理顺序：

```text
提取文字和图片。
清洗前导注入区块。
根据清洗后的文字和现有图片决定是否保留事件。
对清洗后的文字做相邻重复判断。
生成用户事件。
```

不得只修复标题计算或只修复其中一条 JSONL 入口，否则会继续出现正文、计数和导航不一致。

### 6.5 文字与图片边界

```text
清洗后有真实文字：保留真实文字和图片。
清洗后没有文字但有图片：保留图片提问，文字沿用现有“[图片]”语义。
清洗后既无文字也无图片：整条消息跳过。
消息带图片不能成为跳过真实图片的理由。
```

### 6.6 标题、摘要和会话统计

清洗后的事件列表作为以下内容的唯一来源：

```text
第一条真实用户提问。
会话 title。
会话 summary。
userCount 和 messageCount。
提问导航列表和 questionKey。
全文搜索索引。
复制全文和导出 MD。
```

标题规则：

```text
优先取第一条清洗后真实提问的第一行。
继续沿用现有 300 字显示上限和完整标题悬停规则。
如果整场会话没有有效用户提问，沿用当前 JSONL 文件名兜底。
不得再以 <recommended_plugins> 或其他已知注入标签作为标题。
```

### 6.7 原始数据和复制导出边界

```text
原始 JSONL 不修改、不回写、不重排。
页面、提问导航、搜索、复制全文和导出 MD 都不包含被确认的系统注入内容。
这与 V0.29 对已识别 environment_context 等区块的既有行为保持一致。
需要查看原始注入内容时继续使用原始 JSONL。
不在前端内存中额外保存一份仅供导出的隐藏注入正文。
```

### 6.8 缓存失效和历史标题修复

当前增量缓存同时校验：

```text
cacheVersion = 3
builderVersion = 当前软件版本
```

V0.30 将 `builderVersion` 升为 V0.30 后，V0.29 缓存会被现有兼容性检查判定为不兼容，第一次刷新自动转为全量重建。

固定要求：

```text
不伪造旧缓存兼容。
不只修复以后新增或修改过的 JSONL。
首次刷新重新解析当前来源全部会话，使历史错误标题一次性改正。
完成后写入 V0.30 缓存，后续恢复增量刷新。
页面必须沿用现有“共享缓存版本不兼容，已自动执行全量重建”或同等明确提示。
```

### 6.9 Progress Anchor 兼容

删除注入提问后，后续事件下标可能变化，旧 `questionKey` 可能失效。

恢复顺序继续采用已有稳健策略：

```text
1. 尝试原 questionKey。
2. 失败后使用提问正文指纹匹配。
3. 再使用用户提问序号作为兜底。
4. 仍找不到时使用当前会话默认定位，不允许抛错或卡死。
```

V0.30 需要增加注入事件删除导致 eventIndex 偏移的测试，确保刷新后不会错误选中系统区块或完全丢失键盘导航。

## 7. 独立“标题”搜索开关

### 7.1 工具栏布局和语义

搜索框旁保持现有搜索范围组：

```text
全部 / 当前
```

这两个按钮必须始终二选一，继续使用清晰的选中样式和 `aria-pressed` 状态。

在搜索范围组旁新增独立按钮：

```text
标题
```

“标题”可以选中，也可以不选中：

```text
未选中：沿用全文搜索。
选中：只搜索标题正文。
```

现有显示模式组：

```text
全部 / 提问
```

保持原样，不与新增“标题”按钮合并。界面和代码必须区分“搜索范围”“搜索字段”和“会话显示模式”三种状态。

### 7.2 状态定义

新增独立布尔状态，建议：

```text
viewerSearchTitleOnly = false
```

状态规则：

```text
点击“标题”只切换 viewerSearchTitleOnly，不改变 viewerSearchScope。
点击“全部 / 当前”只改变 viewerSearchScope，不关闭“标题”。
刷新和快刷保持查询词、全部/当前和标题开关状态。
切换来源时沿用 V0.29 现有规则清空查询、恢复搜索范围为全部，并关闭标题开关。
页面重新打开时默认关闭标题开关，保持当前默认全文搜索行为。
```

按钮必须有可见选中状态、`aria-pressed` 和明确 title，例如“只搜索标题正文”。不增加另一个含义重复的“全部”按钮。

### 7.3 标题搜索字段边界

标题模式只搜索：

```text
问题类大标题的完整 title。
同一源头下各分支会话的完整 title。
```

标题模式明确不搜索：

```text
备注。
目录和完整路径。
SESSION。
摘要。
创建时间和更新时间。
用户数、回答数和其他元信息。
会话正文、过程、工具和系统事件。
```

搜索使用数据中的完整标题，不使用界面经过 300 字截断或宽度省略后的可见字符串。

### 7.4 “全部 + 标题”

行为：

```text
在当前来源的已加载 APP.workspaces / sessions 标题数据中本地筛选。
目录区只保留至少有一个标题命中的目录。
标题区只保留命中的标题和为展示分组所必需的父级结构。
当前选中会话标题命中时，会话正文完整显示。
当前选中会话标题未命中时，会话区显示标题搜索空结果，不展示非命中正文。
点击其他命中标题后完整显示该会话正文。
```

不得调用全文 `/api/search`，不得读取会话详情来判断标题是否命中。这样标题搜索应明显快于全部会话全文搜索。

### 7.5 “当前 + 标题”

行为：

```text
只判断当前打开会话的完整标题。
标题命中：完整显示当前会话正文。
标题未命中：当前会话区显示空结果。
目录区和标题区保持“当前”搜索范围的既有行为，不扩展为全部标题筛选。
```

“当前 + 标题”的结果只有当前会话，不因当前标题未命中而自动跳到其他会话。

### 7.6 标题命中后的正文

标题搜索只决定会话是否命中，不对正文做第二次关键词过滤：

```text
提问、回答、过程摘要和工具摘要按当前“全部 / 提问”显示模式正常渲染。
不因标题搜索隐藏未命中的回答。
不在正文中增加无意义的关键词高亮。
不改变 selectedQuestionKey。
不自动选择第一条提问。
切换标题开关或清空搜索后，按 Progress Anchor 恢复原提问位置。
```

### 7.7 异步全文搜索竞态

从全文“全部”搜索切换到标题模式时，可能已有 `/api/search` 请求尚未返回。

必须：

```text
清除待执行的全文搜索 timer。
增加 requestId 或取消当前请求，使旧响应失效。
清空旧的 pending 和 error 状态。
立即执行本地标题筛选。
旧全文响应即使稍后返回，也不能覆盖标题结果。
```

关闭“标题”时：

```text
保留原查询词和全部/当前范围。
按当前范围重新执行全文搜索。
当前范围为全部时重新调度服务端搜索。
当前范围为当前时重新渲染当前会话搜索结果。
```

### 7.8 空查询和无结果提示

```text
查询为空时不进行筛选，显示正常目录、标题和会话内容。
标题模式无命中时明确提示“没有匹配这些关键词的标题”或同等文字。
全文模式继续沿用当前空结果提示。
错误提示不得把标题无命中显示成网络或渲染失败。
```

## 8. 多关键词 AND 规则

### 8.1 统一拆词

搜索词统一处理为：

```text
去除首尾空白。
按一个或多个空格、Tab 或换行拆分。
忽略空词。
英文比较不区分大小写，中文保持自然包含匹配。
不把中文逗号、英文逗号或其他标点自动当成分隔符。
不在 V0.30 增加引号短语、OR、NOT 或正则语法。
```

示例：

```text
输入：WebDAV 上传 失败
语义：必须同时包含 WebDAV、上传、失败。
```

### 8.2 三条搜索链路

以下链路都必须使用 `every(term => searchableText.includes(term))` 的等价 AND 语义：

```text
全部 + 全文：保持服务端现有 all(term in text) 逻辑。
当前 + 全文：保持前端现有 every() 逻辑。
标题开启：新增的本地标题筛选使用相同 AND 逻辑。
```

不得只在标题搜索中实现 AND，却意外把现有全文搜索改回 OR。

### 8.3 性能

```text
标题搜索只遍历已加载的会话标题，复杂度为 O(标题数量 × 关键词数量)。
不复制正文搜索索引，不加载隐藏会话详情。
查询输入继续保留中文输入法 composition 防抖。
全部全文搜索继续使用服务端索引，不回退到浏览器扫描所有正文。
当前全文搜索继续只扫描当前详情。
```

## 12. 副作用与规避

### 12.1 首次刷新变慢

副作用：

```text
V0.29 缓存因 builderVersion 升级而失效，V0.30 第一次刷新会重新解析当前来源全部会话。
```

规避：

```text
这是一次性成本，用于修正所有历史错误标题。
全量完成后生成 V0.30 缓存，后续恢复增量刷新。
不在每次刷新额外执行全量标题迁移。
```

### 12.2 注入白名单可能遗漏未来格式

副作用：

```text
Codex 未来新增未知注入标签时，新标签仍可能暂时成为标题或提问。
```

规避：

```text
坚持白名单而不是泛化删除，优先杜绝边界误判。
未来确认新格式后补一个白名单项和测试即可。
```

### 12.3 极少数用户主动发送系统标签

副作用：

```text
如果用户主动发送一条从开头开始、完全由白名单完整系统区块组成的消息，该消息会被当成注入内容。
```

规避：

```text
只处理消息开头的完整、正确闭合、大小写匹配白名单区块。
区块后有任何真实文字或图片时继续保留。
普通正文中间、未知标签和未闭合标签不处理。
原始 JSONL 始终保留完整内容。
```

### 12.4 提问计数和阅读锚点变化

副作用：

```text
删除过去误计为提问的注入事件后，用户数和事件下标会减少，旧 questionKey 可能失效。
```

规避：

```text
计数变化是修正后的预期结果。
恢复时优先使用正文指纹，再使用提问序号兜底。
不把注入事件保留成隐藏提问来维持错误下标。
```

### 12.5 滚轮和触控板行为变化

副作用：

```text
图片舞台内的滚轮及触控板双指滚动会用于缩放，而不是滚动页面。
```

规避：

```text
只在图片弹窗打开且指针位于图片舞台内接管滚轮。
模态背景、按钮和弹窗外页面不接管。
关闭图片后立即恢复正常页面滚动。
```

### 12.6 超大图片的图形渲染压力

副作用：

```text
超高分辨率或大 Base64 图片放大后可能增加浏览器 GPU 合成压力。
```

规避：

```text
不复制或重新编码图片，只复用一个 img。
使用 transform 和 requestAnimationFrame。
比例限制为 25% 到 500%。
切图和关闭时清空缩放状态及 src。
```

### 12.7 拖动与点击关闭冲突

副作用：

```text
如果没有区分点击和拖动，拖动结束可能被误判为点击空白区域并关闭图片。
```

规避：

```text
使用 4 px 移动阈值、pointer capture 和 dragMoved 标记。
拖动后的 click 被消费，真正点击图片外仍关闭。
```

### 12.8 AND 搜索结果减少

副作用：

```text
关键词越多，必须全部满足，结果会明显少于 OR 搜索。
```

规避：

```text
这是用户确认的语义。
无命中时显示明确空状态。
只按空白拆词，逗号保持普通字符，避免隐式拆词。
```

### 12.9 标题模式看不到正文命中

副作用：

```text
“标题”开启时，即使提问或回答正文包含关键词，只要标题不包含全部关键词就不会命中。
```

规避：

```text
标题按钮使用独立、清晰的选中状态。
关闭标题后保留查询词并立即恢复全文搜索。
标题命中后完整显示正文，避免二次过滤影响阅读。
```

### 12.10 标题切换的异步竞态

副作用：

```text
全文搜索旧请求可能在切到标题模式后返回并覆盖当前结果。
```

规避：

```text
切换时取消 timer、递增 requestId，并忽略旧响应。
标题筛选完全使用本地标题数据。
```

```text
CodexChatIndex_V0.29 会增加一份源码；误开归档中的 CMD 会运行旧版。
```

规避：

```text
只归档第 4.1 节白名单，不复制运行数据和生成 HTML。

归档只用于回滚和审查，不作为日常运行目录。
```
