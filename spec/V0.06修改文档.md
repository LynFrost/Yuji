# Open-CodexChatIndex V0.06 修改文档

状态：已讨论确认，尚未实施

日期：2026-05-04

## 1. 修改目标

V0.06 的目标是优化大型会话的会话区渲染性能。

重点要求：

```text
打开大型会话后页面不能卡。
打开大型会话后滚动不能卡。
打开速度尽量控制在 5 秒以内。
尽量减少浏览器内存占用。
不能因为性能优化导致复制、导出或搜索丢内容。
```

本版本重点不改变目录区、标题区和会话基础功能，而是改造会话区正文渲染策略：默认渲染高阅读价值内容，低阅读价值和大体积内容按需展开。

## 2. 推荐方案

采用“轻量默认渲染 + 过程明细懒展开 + 完整数据仍保留在数据层”的方案。

默认进入会话时，优先渲染：

```text
用户提问
最终回答
过程摘要
工具摘要
系统事件合并摘要
```

默认不一次性渲染：

```text
全部过程明细
大段工具原始输出
重复系统统计
任务开始事件
任务结束事件
低阅读价值系统事件
```

完整内容仍保留在 `CURRENT_DETAIL.events` 或等效完整数据结构中。页面 DOM 只是轻量显示层，不作为完整内容的唯一来源。

## 3. 过程内容默认摘要

过程内容默认只显示摘要，不在进入会话时一次性渲染全部过程明细。

摘要必须明确提示数量，例如：

```text
执行过程 38 条 · 工具 12 条 · 系统 9 条
```

如果搜索命中过程内容，摘要需要提示命中数量，例如：

```text
执行过程 38 条，命中 5 条，点击展开查看完整命中内容
```

用户点击展开过程摘要后，再渲染该过程组的具体明细。

用户收起过程摘要后，推荐销毁已展开的明细 DOM，只保留摘要 DOM，避免浏览器内存持续升高。

展开后必须可以看到完整过程内容，不能只显示摘要或截断版。

## 4. 系统事件合并显示

大量系统事件默认合并显示。

以下低阅读价值或重复事件默认不逐条渲染：

```text
重复系统统计
任务开始
任务结束
状态同步
低价值心跳或元信息
```

合并显示时需要保留数量和类型概览，例如：

```text
系统事件 46 条：任务开始 12 条，任务结束 12 条，统计 22 条
```

如果系统事件中存在明显错误、失败、警告或高价值信息，可以在摘要中突出显示，避免用户错过关键异常。

用户展开系统事件摘要后，应能看到完整系统事件明细。

## 5. 工具执行结果默认摘要

工具执行结果默认只显示：

```text
工具名称
执行状态
简短摘要
时间信息
```

默认不把大段原始输出、stdout、stderr、trace、完整 JSON 直接渲染到页面正文中。

工具摘要示例：

```text
exec_command · exit=0 · 输出 128 行，摘要：测试通过 41 项
```

如果工具失败，摘要需要突出失败状态，例如：

```text
exec_command · exit=1 · 错误输出 24 行
```

用户展开工具结果后，可以看到完整原始输出。

复制和导出必须仍能包含完整工具输出，不能只包含摘要。

## 6. 超大会话保护机制

遇到内容特别多的会话时，进入性能保护模式。

建议触发条件可以按以下维度综合判断：

```text
事件总数特别多
过程事件特别多
工具输出原始文本特别大
系统事件重复数量特别多
预计默认 DOM 节点数过高
预计默认 HTML 字符串过大
```

性能保护模式下：

```text
优先显示用户提问。
优先显示最终回答。
优先显示过程摘要。
优先显示工具摘要。
优先显示系统事件合并摘要。
延迟渲染过程明细。
延迟渲染工具原始输出。
延迟渲染系统事件明细。
```

页面可以显示轻提示：

```text
已启用性能保护：过程明细按需展开，复制和导出仍包含完整内容。
```

性能保护模式不能影响提问定位、上下键切换、回到顶部后自动聚焦等核心阅读动线。

## 7. 搜索范围设计

搜索必须搜索完整会话数据，而不是只搜索当前已渲染 DOM。

原因是过程明细、工具输出和系统事件默认不会全部渲染。如果搜索只查 DOM，用户会遇到“内容存在但搜不到”的问题，这是不可接受的。

搜索范围应包含：

```text
用户提问 rawText
最终回答 rawText
过程明细 rawText
工具名称
工具状态
工具摘要
工具原始输出
系统事件摘要
系统事件原始内容
```

搜索命中未展开内容时，不建议自动把所有隐藏明细全部展开。

推荐行为：

```text
摘要卡片显示命中数量。
用户点击摘要卡片后展开命中的完整明细。
如果命中数量很大，优先展开命中摘要列表，再由用户继续展开单条完整内容。
```

这样可以避免搜索一个常见词后瞬间渲染大量隐藏内容，导致页面卡顿。

搜索空结果文案需要明确搜索范围是完整会话内容，而不是当前 DOM，例如：

```text
当前会话完整内容中没有匹配结果。
```

## 8. 复制和导出完整性

复制全文和导出 MD 不能依赖当前 DOM。

复制和导出必须从完整事件数据生成内容，例如 `CURRENT_DETAIL.events` 或等效完整数据结构。

即使用户没有展开过程明细，复制和导出也应尽量包含：

```text
用户提问
最终回答
过程明细
工具执行摘要
工具原始输出
系统事件
时间信息
会话路径
```

不能因为页面没有渲染某段过程明细，就导致复制或导出丢失该段内容。

如果单条消息的“复制全文”按钮复制的是该消息自身，则仍保持现有语义。

如果过程摘要卡片新增“复制全文”按钮，则应复制该过程组的完整明细，而不是只复制摘要。

导出 MD 可以继续保持比页面显示更完整，因为导出目标是留档，不是轻量阅读。

## 9. 现有功能不受影响

V0.06 性能优化不能影响以下既有功能：

```text
进入会话后定位最后一个提问
点击标题后直接使用上下键切换提问
向上、向下按钮切换提问
回到顶部后自动聚焦第一个提问
只看提问
搜索当前会话
复制全文
导出 MD
复制路径
复制 SESSION
标题区选中提示
刷新按钮 loading 状态
```

尤其需要保证：过程明细默认不渲染，不等于完整内容不存在。

所有依赖完整内容的功能必须走完整数据层，而不是页面 DOM。

## 10. 性能约束

页面打开速度尽量控制在 5 秒以内。

打开之后滚动不能变卡，这一点不可接受。

实现时应避免：

```text
进入会话时一次性拼接超大 HTML 字符串
把大量隐藏内容塞进 DOM
把大段工具输出放进 display:none 区域
滚动监听中做重计算
频繁读取 offset、scrollHeight 等触发布局的属性
每次搜索都全量重建巨大 DOM
```

推荐：

```text
默认 DOM 数量与用户提问、最终回答、摘要卡片数量相关。
过程明细展开时再生成 DOM。
收起后释放明细 DOM。
搜索命中隐藏内容时先显示命中摘要。
必要时分批渲染，避免长任务阻塞主线程。
```

## 11. 副作用和风险

默认阅读体验会发生变化：用户进入会话后不再立即看到所有过程明细，而是先看到过程摘要。好处是大型会话更快、更稳；代价是查看完整过程需要多点一次展开。

搜索体验会更复杂：搜索需要覆盖未渲染内容，但不能因为命中隐藏内容就自动渲染全部明细。需要用“命中摘要 + 点击展开”降低误解。

展开过程明细时可能出现局部短暂渲染开销。如果某个过程组本身非常大，展开瞬间仍可能有压力。需要对单个超大组继续使用分批渲染或二级展开。

系统事件合并可能让少数用户觉得信息被“藏起来”。需要通过数量提示、展开入口和异常突出显示来降低这个风险。

工具输出默认摘要可能让排查问题多一步。好处是避免大段输出拖慢滚动；代价是需要展开才能看完整 stdout/stderr。

复制和导出从完整数据层生成，逻辑上比从 DOM 复制更可靠，但实现复杂度更高。需要测试确保页面未展开时仍不丢内容。

如果搜索每次都扫描完整原始文本，超大会话搜索本身也可能带来性能压力。后续实现时需要考虑查询去抖、缓存标准化搜索文本、或只在用户停止输入后搜索。

本版本会减少默认 DOM 和内存占用，但完整会话数据仍需加载到内存才能支持搜索、复制和导出。因此内存不会降到只剩当前 DOM 的水平；优化重点是避免 DOM 膨胀和隐藏内容持续占内存。

## 12. 不采用的方案

不建议 V0.06 直接实现完整虚拟列表。

原因是虚拟列表会牵涉：

```text
提问定位
上下键切换
回到顶部聚焦
搜索命中定位
过程展开状态
复制按钮状态
动态高度测量
滚动锚点维护
```

这些都容易引入边界问题。V0.06 优先切掉最大 DOM 来源，即过程、工具、系统明细默认不渲染。

不建议只用 CSS 折叠隐藏完整明细。

原因是 `display:none` 或折叠隐藏仍然可能把大量内容放进 DOM 或字符串里，无法真正降低内存和初始渲染压力。

不建议搜索只查当前 DOM。

原因是这会导致未展开内容搜不到，和用户预期冲突。

## 13. 验收标准

进入大型会话时，用户提问和最终回答能优先显示。

进入大型会话时，过程内容默认显示摘要，不一次性渲染全部过程明细。

过程摘要显示过程明细数量。

点击过程摘要后，可以看到完整过程明细。

收起过程摘要后，已展开明细 DOM 应释放或不再保留大量隐藏内容。

大量系统事件默认合并显示，并提示数量和类型。

点击系统事件摘要后，可以看到完整系统事件明细。

工具执行结果默认只显示工具名称、执行状态和简短摘要。

点击工具摘要后，可以看到完整工具原始输出。

超大会话启用性能保护时，页面提示清晰，不影响阅读主线。

搜索能命中未展开的过程明细、工具输出和系统事件。

搜索命中隐藏内容时，摘要显示命中数量。

搜索不会因为命中大量隐藏内容而一次性渲染全部明细导致卡顿。

复制全文不依赖已展开 DOM，未展开过程也不丢内容。

导出 MD 不依赖已展开 DOM，未展开过程也不丢内容。

进入会话后定位最后一个提问仍正常。

点击标题后直接使用上下键切换提问仍正常。

向上、向下按钮切换提问仍正常。

回到顶部后自动聚焦第一个提问仍正常。

只看提问功能仍正常。

复制路径和复制 SESSION 功能仍正常。

页面打开速度尽量控制在 5 秒以内。

页面打开后滚动不能变卡。

浏览器内存不应因为大量隐藏 DOM 持续升高。

## 14. 验收流程补充

最终验收必须使用浏览器工具打开页面实际查看效果，不只靠代码阅读或命令输出。

浏览器验收至少需要覆盖：

```text
普通会话默认渲染
大型会话默认渲染
过程摘要数量提示
过程展开和收起
系统事件合并摘要
工具摘要和完整输出展开
搜索未展开内容
复制全文未展开内容不丢失
导出 MD 未展开内容不丢失
提问定位
上下键切换
回到顶部自动聚焦
只看提问
滚动流畅性
```

浏览器验收完成后，所有为验收临时打开的本地服务端口都必须关闭。

如果后续还需要查看，保留的做法应由用户自己重新打开，不默认常驻占用端口。
