# Open-CodexChatIndex V0.07 修改文档

状态：已实施并验收

日期：2026-05-04

## 1. 修改目标

V0.07 的目标是修复会话显示中的数据正确性问题，并统一提问切换时的滚动动画。

本版本重点修复：

```text
时间显示错误。
已回滚分支内容被错误渲染。
向上、向下切换提问时滚动动画不一致。
```

本版本不扩展新的 UI 功能，不改变目录区、标题区、复制、导出、搜索等既有功能的设计方向。

## 3. 时间显示修复

当前时间错误不是简单的显示格式问题，而是时间解析过程中丢失了 UTC 语义。

JSONL 中原始时间类似：

```text
2026-05-04T08:02:57.576Z
```

这个时间代表 UTC 时间，对应中国标准时间应显示为：

```text
2026-05-04 16:02:57
```

当前实现中，`ConvertFrom-Json` 会把 ISO 时间自动转成 `DateTime`。随后代码把它转成 `[string]`，字符串变成类似：

```text
05/04/2026 08:02:57
```

此时 `Z` 和 `Utc` 语义已经丢失，再调用本地时间转换时，就可能原样显示成 `08:02:57`。

V0.07 应调整时间处理方式：

```text
不要在时间转换前无条件转成 string。
如果输入是 DateTime，并且 Kind 是 Utc，则直接转成本地时间。
如果输入是 DateTimeOffset，则直接 ToLocalTime。
如果输入是 ISO 字符串，则按 DateTimeOffset 解析后 ToLocalTime。
如果输入是普通字符串且无法识别时，才保留原文。
```

显示时间和排序时间需要分开处理：

```text
显示字段使用本地时间文本。
排序字段继续使用稳定的原始 UTC 时间或可比较时间值。
不能为了显示修复破坏标题区和目录区按更新时间排序。
```

## 4. 回滚分支内容修复

当前内容错误的核心原因是软件没有处理 JSONL 中的 `thread_rolled_back` 事件。

样本会话中存在：

```json
{"timestamp":"2026-05-04T08:02:43.711Z","type":"event_msg","payload":{"type":"thread_rolled_back","num_turns":7}}
```

在 Codex Desktop 中，`thread_rolled_back` 之前被回滚的分支不会作为当前有效会话继续展示。

当前软件没有识别这个事件，导致：

```text
已回滚的用户提问被保留。
已回滚的 assistant 回答被保留。
已回滚的过程、工具、系统事件也可能被保留。
后续真实提问的上下文位置被污染。
用户看到的“上一条回答”与 Codex Desktop 不一致。
```

V0.07 应在解析阶段处理回滚：

```text
识别 event_msg / thread_rolled_back。
读取 payload.num_turns。
从当前有效事件流中移除最近 num_turns 个有效 turn。
被移除 turn 关联的用户、回答、过程、工具、系统事件都不进入默认会话视图。
```

为支持回滚，应保证事件归属清晰：

```text
解析 task_started 时记录当前 turnId。
用户消息、assistant 消息、工具结果、系统事件都尽量绑定到对应 turnId。
如果事件自身没有 turn_id，则使用当前活动 turnId。
task_complete 结束当前 turn，但事件本身仍属于该 turn。
```

正常阅读、搜索、复制全文、导出 MD 都应基于“有效事件流”，不能把已回滚分支混进去。

## 5. 回滚后的搜索、复制和导出规则

V0.07 默认不提供“查看已回滚分支”的入口。

因此以下功能都不应包含已回滚分支内容：

```text
会话区默认渲染。
只看提问。
向上、向下切换提问。
搜索当前会话。
复制全文。
导出 MD。
复制 SESSION。
```

如果后续确实需要排查原始 JSONL，可以另做“原始事件调试视图”，但不放入 V0.07。

这样可以保证默认阅读结果更接近 Codex Desktop。

## 6. 滚动动画一致性修复

当前向上切换提问时，靠近底部的前几个提问会出现：

```text
先滚到目标位置上方一点。
再向下滑回目标位置。
```

后续继续向上时，又变成：

```text
直接一直向上到达目标位置。
```

这说明滚动目标在动画过程中发生了变化。

当前实现中，为了让底部提问也能贴到画面顶部，会动态调整 `--transcript-scroll-spacer`。如果在平滑滚动前后反复清零、重算 spacer，再计算目标位置，就容易造成目标点变化，看起来像“越过后回弹”。

V0.07 应统一滚动策略：

```text
先根据目标提问一次性计算需要的底部 spacer。
先稳定 spacer。
再计算唯一 targetTop。
最后执行滚动动画。
动画过程中不再修改 spacer 和 targetTop。
```

向上、向下都使用同一套定位逻辑。

快速连续按上下键时：

```text
取消上一段未完成动画。
以最新目标提问为准重新计算 targetTop。
不要多个 smooth scroll 互相叠加。
```

最终效果要求：

```text
向上切换时，动画只向上移动到目标提问。
向下切换时，动画只向下移动到目标提问。
不能出现先越过目标再反向修正。
```

```

尤其需要保证：

```

## 8. 副作用和风险

时间修复后，历史会话中之前显示成 UTC 的时间会批量变成本地时间。这是正确变化，但用户视觉上会感觉很多时间同时变了。

如果有某些 JSONL 的时间字段不是标准 ISO UTC，而是已经本地化的普通字符串，新的时间解析需要避免二次转换。无法识别的普通字符串应原样保留。

回滚修复后，已回滚分支内容不会出现在默认阅读、搜索和导出里。这会更贴近 Codex Desktop，但如果用户想追查废弃分支，需要以后单独增加原始事件视图。

回滚逻辑如果只按事件数量删除，容易删错；必须按 turn 删除。否则会出现删掉半个问答、留下孤立工具结果或孤立系统事件的问题。

滚动动画改为自控后，手感可能和浏览器原生 `smooth` 略有差异。需要优先保证方向一致和不回弹。

快速连续按键时取消旧动画，可能让动画看起来更“干脆”，但这是为了避免多个滚动动画互相叠加。
