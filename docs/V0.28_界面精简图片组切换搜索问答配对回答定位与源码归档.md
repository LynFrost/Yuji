## 5. 图片预览组内切换

### 5.1 范围定义

图片组严格限定为“当前点击图片所属的同一个提问框中的可用图片”。

```text
不跨提问切换。
不跨会话切换。
不把加载失败或 disabled 的缩略图加入可切换集合。
图片顺序与提问框内缩略图顺序一致。
```

### 5.2 预览状态

预览状态固定为：

```text
imagePreviewTrigger：当前正在查看图片对应的缩略图按钮；打开和每次切换成功后都必须更新。
imagePreviewItems：同一 message-images 容器中的可用图片按钮引用。
imagePreviewIndex：当前预览图片在集合中的索引。
```

推荐保存缩略图按钮引用，不额外复制所有图片 src 字符串。切换时从目标按钮读取当前图片地址和替代文本，避免为长 data URL 建立第二套持久数组。

新增统一切换入口：

```text
showImagePreviewAt(index)
```

该函数负责：

```text
1. 验证 index 是否在 imagePreviewItems 范围内。
2. 读取目标按钮中的图片 src 和 alt。
3. 更新 imagePreviewIndex。
4. 将 imagePreviewTrigger 更新为 imagePreviewItems[imagePreviewIndex]。
5. 更新唯一的 imagePreviewImage。
6. 更新上一张、下一张按钮和计数状态。
```

上一张按钮、下一张按钮和键盘左右键都必须调用 `showImagePreviewAt()`，不得各自维护另一套索引或焦点逻辑。

打开流程：

```text
1. 从被点击按钮的最近 message-images 容器收集可用图片按钮。
2. 找到被点击按钮的索引。
3. 保存图片集合。
4. 调用 showImagePreviewAt(index)，同时更新当前索引、imagePreviewTrigger、图片和控制项状态。
5. 打开模态框并把焦点放到关闭按钮。
```

关闭流程：

```text
1. 隐藏模态框。
2. 清空 imagePreviewImage.src 和 alt。
3. 清空 imagePreviewItems。
4. 将 imagePreviewIndex 重置为 -1。
5. 将焦点还给 imagePreviewTrigger，也就是关闭前最后查看图片对应的缩略图按钮；按钮已不存在或已脱离 document 时不强制聚焦。
6. 最后将 imagePreviewTrigger 清空。
```

因此，用户从第 2 张切换到第 3 张后关闭，焦点必须返回第 3 张缩略图，而不是最初打开的第 2 张。

在现有模态框中固定新增以下元素：

```html

  <button type="button" id="imagePreviewClose" class="image-preview-close">关闭</button>
  <button type="button" id="imagePreviewPrev" class="image-preview-nav image-preview-nav--prev" aria-label="上一张图片" hidden>←</button>

  </div>
  <button type="button" id="imagePreviewNext" class="image-preview-nav image-preview-nav--next" aria-label="下一张图片" hidden>→</button>

```

布局固定采用“绝对定位控制项 + 居中图片舞台”：

```text
imagePreviewModal 继续覆盖整个视口并负责居中 imagePreviewStage。
imagePreviewStage 使用 position: relative，只按图片内容占据中心区域，不铺满整个模态框。
imagePreviewImage 在桌面端使用 max-width: min(calc(100vw - 140px), 1440px) 和 max-height: calc(100vh - 92px)。

imagePreviewPrev 使用 left: 18px，imagePreviewNext 使用 right: 18px。
左右按钮最小尺寸为 44 × 44 px，使用半透明高对比背景和清晰 focus-visible 轮廓。
imagePreviewCount 使用 position: absolute、left: 50%、bottom: 10px、transform: translateX(-50%)，固定在图片舞台底部中央并使用半透明背景。
imagePreviewStatus 与图片舞台同域显示，只在当前大图加载失败时出现。
桌面宽度下为左右按钮预留侧边空间，图片不被按钮覆盖。
在 max-width: 640px 下，图片改用 max-width: calc(100vw - 24px)，左右按钮分别改为 left: 8px 和 right: 8px，允许轻微覆盖图片边缘，但不得覆盖关闭按钮和计数。
```

新增 DOM 常量：

```text
imagePreviewPrev
imagePreviewNext
imagePreviewStage
imagePreviewCount
imagePreviewStatus
```

不得动态重复创建这些节点；每次打开只更新状态和属性。

### 5.4 左右按钮与计数

多图时显示：

```text
左侧上一张按钮。
右侧下一张按钮。
当前序号 / 总数，例如 2 / 5。
```

规则：

```text
第一张时禁用左按钮。
最后一张时禁用右按钮。
不循环切换。
只有一张可用图片时，隐藏左右按钮和计数。
按钮点击必须 preventDefault 和 stopPropagation，不能触发背景关闭。
按钮至少提供 44 × 44 px 可点击区域，并有清晰的 focus-visible 状态。
按钮使用 aria-label“上一张图片”“下一张图片”。
计数使用 aria-live="polite"，以非打断方式播报序号变化。
```

左右按钮固定在图片两侧，不挤压原图可用尺寸。窄屏时按钮可以靠近屏幕边缘，但不能盖住关闭按钮。

### 5.5 键盘行为

图片预览打开时：

```text
ArrowLeft：切换到上一张；已经是第一张时不动作。
ArrowRight：切换到下一张；已经是最后一张时不动作。
Escape：关闭图片预览。
```

新增 `handleImagePreviewKeydown(event)`，并在 document 捕获阶段注册，使图片模态框键盘行为先于现有会话快捷键处理：

```text
图片模态框未打开：立即返回，不拦截任何按键。
ArrowLeft：preventDefault、stopPropagation，调用 showImagePreviewAt(imagePreviewIndex - 1)。
ArrowRight：preventDefault、stopPropagation，调用 showImagePreviewAt(imagePreviewIndex + 1)。
Escape：preventDefault、stopPropagation，调用 closeImagePreview()。
其他按键：不处理。
```

现有 transcript 快捷键处理入口同时增加防御性守卫：图片模态框打开时立即返回。虽然 V0.27 打开预览后焦点通常位于关闭按钮、当前不会进入 transcript 快捷键分支，但仍应显式隔离，防止后续焦点行为变化造成冲突。

### 5.6 扩展既有的图片外区域关闭

V0.27 已有行为：

```text
只有 event.target === imagePreviewModal 时，点击才会关闭。
```

V0.28 新增图片舞台、箭头和计数后，模态框内部会出现新的包装节点和空白区域。因此本节不是重新实现“背景关闭”，而是扩展既有点击边界。

以下行为关闭预览：

```text
点击深色遮罩背景。
点击图片、左右按钮、计数、关闭按钮以外的模态空白区域。
点击“关闭”按钮。
按 Escape。
```

以下行为不关闭预览：

```text
点击图片本身。
点击上一张或下一张按钮。
点击计数区域。
```

事件处理固定为：

```text
点击目标位于 imagePreviewImage、imagePreviewPrev、imagePreviewNext、imagePreviewCount 或 imagePreviewClose 内时，不按空白区域关闭处理。
其他位于 imagePreviewModal 内的点击，包括 imagePreviewStage 的图片外空白部分，调用 closeImagePreview()。
上一张、下一张和关闭按钮继续执行各自按钮功能。
```

模态框点击监听固定使用以下判断：

```javascript
const protectedTarget = event.target.closest(
  '#imagePreviewImage, #imagePreviewPrev, #imagePreviewNext, #imagePreviewCount, #imagePreviewClose'
);
if (!protectedTarget) closeImagePreview();
```

左右按钮点击仍主动阻止冒泡，形成双层保护。

### 5.7 图片切换性能和失败处理

```text
只复用一个 imagePreviewImage，不为每张图创建隐藏大图节点。
不主动预加载全部大图。
缩略图和大图继续使用同一 URL，由浏览器缓存决定是否复用响应。
切换时直接替换 src，不使用长时间动画。
当前图片加载失败时显示“图片无法加载”，但保留左右切换能力。
关闭时必须清空 src 和图片集合，避免会话切换后继续持有旧图片引用。
```

## 6. 搜索结果完整问答配对

### 6.1 目标行为

在“全部”视图中，搜索结果按问答关系显示：

```text
提问命中：显示该提问，并显示它对应的全部最终回答，即使回答正文没有命中。
任一最终回答命中：显示对应提问和该问答组的全部最终回答；只有真正命中的回答使用直接命中样式，其余回答作为配对内容显示。
提问和回答都命中：两者都作为直接命中显示。
同一提问或回答只显示一次。
提问没有最终回答：只显示命中的提问。
```

“对应最终回答”定义为：

```text
从该 user 事件之后开始，到下一条 user 事件之前出现的 assistant_final 事件。
assistant_commentary、tool、system 不属于最终回答。
如果一个提问具有多条 assistant_final，则都属于该提问；提问或任一最终回答命中时全部显示，Enter 定位到其中第一条。
```

“提问”视图继续只显示提问：

```text
即使当前有搜索词，也不在“提问”视图中插入回答。
切回“全部”后再显示完整问答配对。
```

### 6.2 过程和工具命中保持现状

V0.28 不扩大过程明细默认渲染：

```text
过程、工具或系统事件命中时，继续按现有规则显示关联提问和命中的过程摘要或明细入口。
仅当同组提问本身或最终回答命中时，才触发完整问答配对。
不会因为某条工具输出命中而自动带出整段未命中的最终回答。
不会默认展开全部过程明细。
```

### 6.3 推荐数据处理方式

不要在 DOM 渲染后查找相邻节点来猜测问答关系。推荐在 `getVisibleDetailEvents()` 或其上游新增一次线性分组：

```text
1. 顺序遍历当前会话事件。
2. 每遇到 user，开始一个新的问答组并记录 questionKey。
3. 下一条 user 之前的 assistant_final 归入该组。
4. commentary、tool、system 仍按现有过程逻辑处理。
5. 计算 questionMatched、answerMatched 和 processMatched。
6. 按第 6.1、6.2 节规则输出事件，并使用 Set 去重。
```

复杂度保持为当前会话事件数量的 O(n)，不得对每条提问再次遍历全部事件。

搜索状态只作为本次渲染元数据存在，固定使用：

```text
isDirectSearchHit
isSearchCompanion
```

不得修改原始 `APP.currentDetail.events`，避免清空搜索后残留搜索样式或污染复制、导出数据。

### 6.4 纯样式区分，不增加标签

直接命中的提问或回答：

```text
增加细金色侧边线。
增加非常浅的暖色背景。
继续保留现有命中关键词 mark 高亮。
```

因问答配对带出的未命中提问或回答：

```text
使用更淡的中性色侧边线。
正文背景基本保持现状，只允许极轻的中性色变化。
不对未命中的文字添加 mark。
```

## 7. Enter 定位对应最终回答

### 7.1 触发条件

Enter 功能只在以下条件同时满足时生效：

```text
会话区 transcript 或其中非交互正文元素拥有键盘焦点。
selectedQuestionKey 对应一个当前选中的提问。
event.target 不在 button、a、input、textarea、select 或 contenteditable 内。
图片预览、备注窗口等模态交互没有占用 Enter。
```

不影响：

```text
回复框 Enter“复制发送”。
回复框 Shift+Enter 换行。
备注框 Ctrl+Enter 保存。
按钮本身的 Enter 激活。
搜索输入框中的 Enter。
```

在现有 transcript 相关 document keydown 处理中增加 Enter 分支，调用 `handleTranscriptEnter(event)`。该函数先执行本节守卫，再 `preventDefault()`；输入法正在组合文字或按下 Shift、Ctrl、Alt、Meta 时不触发回答定位。

### 7.2 建立准确的问答 DOM 关联

当前最终回答没有 questionKey DOM 标记。V0.28 明确修改 `buildReaderMarkup()` 和 `renderEvent()`：

```text
buildReaderMarkup() 新增局部变量 currentQuestionKey，初始为空字符串。
遇到 user 事件时，将 currentQuestionKey 更新为 event.questionKey，并照常渲染提问。
遇到 assistant_final 时，调用 renderEvent(event, { answerForQuestionKey: currentQuestionKey })。
renderEvent() 的 assistant_final 分支读取 options.answerForQuestionKey，并输出 data-answer-for-question-key。
```

最终 DOM：

```html
<article class="message message--final assistant"
         data-answer-for-question-key="..."></article>
```

规则：

```text
遇到 user 时更新当前 questionKey。
下一条 user 之前的 assistant_final 使用该 questionKey。
过程和工具事件不改变当前 questionKey。
搜索中配对带出的回答沿用其原问答组的 questionKey。
不依赖 DOM 中“下一个 .assistant”进行猜测。
```

新增 `findAnswerElement(questionKey)`，通过 dataset 精确比较，返回该提问对应的第一条最终回答。

新增独立回答滚动链路：

```text
handleTranscriptEnter(event)
  → 读取当前 selectedQuestionKey
  → findAnswerElement(selectedQuestionKey)
  → scrollElementToTranscriptTop(answerElement)
```

明确禁止：

```text
Enter 不调用 setSelectedQuestionKey()。
Enter 不调用 scrollToQuestion()。
Enter 不调用 saveProgressAnchorForCurrentSession()。
Enter 不通过 persistAnchor: false 绕行提问选中链路。
```

`persistAnchor: false` 是现有 `setSelectedQuestionKey()` 的能力，但本功能不改变选中提问，因此不需要新增参数，也不需要调用该参数。回答定位只操作滚动位置。

### 7.3 各视图中的行为

普通“全部”视图：

```text
直接查找已渲染的对应最终回答并定位。
```

搜索状态下的“全部”视图：

```text
第 6 节已经保证提问命中时对应回答也在当前 DOM 中。
Enter 只定位现有回答，不临时插入内容，不触发搜索结果二次重排。
```

“提问”视图：

```text
1. 将 pendingAnswerFocusQuestionKey 设置为当前 selectedQuestionKey。
2. 将 viewerViewMode 切换为 all。
3. 保持 viewerSearchQuery、viewerSearchScope 和 selectedQuestionKey。
4. 调用 renderViewer()。
```

`renderViewer()` 在写入 transcript.innerHTML 并完成高亮后按以下优先级处理滚动：

```text
1. 如果 pendingAnswerFocusQuestionKey 有值，保存并立即清空该一次性状态。
2. 跳过本轮现有的 requestAnimationFrame(() => scrollToQuestion(selectedQuestionKey, 'auto'))。
3. 只注册一次 requestAnimationFrame，在其中重新查找该 questionKey 对应的回答并调用 scrollElementToTranscriptTop()。
4. 如果回答不存在，保持当前位置并显示无回答提示。
5. 没有 pendingAnswerFocusQuestionKey 时，继续执行 V0.27 原有提问自动滚动逻辑。
```

不采用 double requestAnimationFrame 让“提问滚动”和“回答滚动”依次竞争。V0.28 必须在同一轮渲染中抑制提问自动滚动，只执行一次回答定位，避免先跳到提问再跳到回答的闪动。

没有最终回答：

```text
保持当前位置和 selectedQuestionKey 不变。
调用现有 showToast('该提问暂时没有最终回答', { duration: 2200 })。
```

当前 V0.27 已有 `showToast(message, options)` 和自动消失计时器；V0.28 不新增第二套 toast 系统。

### 7.4 滚动位置和阅读锚点

```text
回答顶部定位到会话区顶部约 16px，视觉上替代原提问所在的顶部阅读位置。
使用 behavior: auto，不使用 smooth。
selectedQuestionKey 仍保持原提问，不把回答变成新的提问锚点。
Enter 不更新 Progress Anchor。
按 ArrowUp / ArrowDown 时仍从原选中提问切换到相邻提问。
```

当前 `calculateQuestionScrollSpacer(element)` 的函数体已经适用于任意目标元素，不需要重新抽取算法。V0.28 只做以下机械调整：

```text
将 calculateQuestionScrollSpacer(element) 重命名为 calculateTranscriptScrollSpacer(element)。
更新 convergeScrollToQuestion() 中的现有调用。
更新 stableScrollToQuestionForKeyboard() 中的现有调用。
更新 scrollToQuestion() 中的现有调用。
合计更新当前 5 个调用点，并由新增 scrollElementToTranscriptTop() 复用同一函数。
```

`scrollElementToTranscriptTop(element)` 专门接收已经找到的 DOM 元素，不接受 questionKey，也不修改 selectedQuestionKey。它使用 `calculateTranscriptScrollSpacer(element)` 保证最后一条短回答也能到达顶部。

滚动稳定规则沿用 V0.26：

```text
短暂锁定布局。
等待一个 requestAnimationFrame 后测量。
先计算底部 spacer，再计算 targetTop。
执行一次 auto 滚动。
只在偏差超过现有容差时最多进行一次轻量修正。
及时释放布局锁，不启用长收敛循环。
```

## 11. 副作用与规避

### 11.1 删除说明文字后识别信息减少

副作用：

```text
浏览器标签只显示“语迹”，不能直接从标签文字看出软件用途。
来源下拉框前没有“来源：”，初次使用者的语义提示减少。
```

规避：

```text
来源选项本身使用“XF-本机 Codex”等完整名称。
保留 aria-label 和 title。
软件用途继续在 README 中说明。
```

### 11.2 图片左右键与其他快捷键冲突

副作用：

```text
模态框打开时，左右方向键可能继续传播给页面其他监听器。
```

规避：

```text
图片快捷键在 document 捕获阶段先判断图片模态框状态。
处理左右键时 preventDefault、stopPropagation，并统一调用 showImagePreviewAt()。
transcript 快捷键入口同时增加“图片模态框打开则返回”的防御性守卫。
关闭模态框后立即恢复普通键盘行为。
```

### 11.3 点击空白关闭可能造成误关闭

副作用：

```text
用户在图片周边空白处点击时会关闭预览。
```

规避与结论：

```text
这是用户明确要求的关闭方式。
V0.28 是对 V0.27 最外层背景关闭能力的扩展，不是新增第二套点击监听。
图片、箭头、计数和关闭按钮均设置为安全交互区域，不会被空白关闭分支处理。
关闭后焦点返回最后查看图片对应的缩略图，便于立即重新打开。
```

### 11.4 图片组状态增加内存引用

副作用：

```text
预览期间会持有同一提问内图片按钮的引用。
```

规避：

```text
只持有当前提问的按钮引用，不复制全部 src。
不创建隐藏大图，不预加载全部图片。
每次切换通过 showImagePreviewAt() 同步更新 imagePreviewIndex 和 imagePreviewTrigger。
关闭时先用 imagePreviewTrigger 恢复焦点，再清空 trigger、集合、索引和 img.src。
会话重新渲染前如预览仍打开，应先关闭并清理状态。
```

### 11.5 搜索结果长度和首次渲染量增加

副作用：

```text
提问命中时会增加未命中最终回答，宽泛搜索可能让结果明显变长。
长回答的 Markdown 初次渲染会增加少量 CPU 和 DOM 成本。
```

规避：

```text
问答分组采用一次 O(n) 遍历和 Set 去重。
不复制原事件，不默认展开过程明细。
继续使用 message 的 content-visibility 和图片 loading="lazy"。
不添加每帧滚动监听或搜索结果滚动计算。
所有符合规则的回答仍完整显示，不通过截断或数量上限牺牲内容。
```

预期影响：

```text
搜索结果首次生成可能比 V0.27 略慢，尤其是宽泛关键词命中大量提问时。
普通会话打开、未搜索状态和搜索后的持续滚动不应因此变慢。
```

### 11.6 搜索样式影响阅读

副作用：

```text
如果直接命中和配对样式过强，会破坏问答连续阅读。
```

规避：

```text
只使用细侧边线和极浅背景。
不增加文字标签，不改变正文排版。
不使用动画。
浏览器验收时同时观察浅色背景下的对比度和长文阅读。
```

### 11.7 Enter 与输入控件冲突

副作用：

```text
全局 Enter 监听如果边界过宽，可能破坏回复框发送、换行、备注保存或按钮激活。
```

规避：

```text
只在 transcript 焦点范围生效。
排除 button、a、input、textarea、select、contenteditable。
排除输入法组合状态和带 Shift、Ctrl、Alt、Meta 的 Enter。
保留现有回复框和备注框自己的 keydown 处理优先级。
回答定位直接调用 findAnswerElement() 和 scrollElementToTranscriptTop()，不进入 setSelectedQuestionKey() 链路。
增加完整交互测试，而不只检查函数是否存在。
```

### 11.8 Enter 后仍以提问为锚点可能不直观

副作用：

```text
回答位于顶部时，选中提问可能已经滚出画面，但上下键仍从该提问继续。
```

规避与结论：

```text
这是保持提问导航模型和 Progress Anchor 不变的设计目标。
回答不成为新的导航节点，避免破坏上下键和刷新进度恢复。
按上下键后会立即选中并定位相邻提问。
```

### 11.9 “提问”视图按 Enter 会改变视图模式

副作用：

```text

```

```text
不清空搜索、不切换会话。
使用一次性 pendingAnswerFocusQuestionKey，并在 renderViewer() 中抑制本轮提问自动滚动。
只安排一次回答定位，不使用 double requestAnimationFrame 让两个滚动竞争。
```

### 11.10 回答定位靠近会话末尾需要底部 spacer

副作用：

```text
最后一条较短回答若没有足够底部空间，浏览器无法把它滚到顶部。
动态 spacer 计算错误可能产生多余空白或滚动闪动。
```

规避：

```text
复用现有提问定位的稳定测量顺序和容差。
现有 calculateQuestionScrollSpacer() 算法不变，只重命名为 calculateTranscriptScrollSpacer() 并更新全部调用点。
提问定位和回答定位共同调用 calculateTranscriptScrollSpacer()，不维护两套算法。
切回提问、切换会话或重新渲染时重新计算或清理 spacer。
只做 auto 定位和最多一次轻量修正。
```
