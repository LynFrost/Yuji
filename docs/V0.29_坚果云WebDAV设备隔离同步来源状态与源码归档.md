# 语迹 V0.29 坚果云 WebDAV 设备隔离同步、来源状态与源码归档

状态：待确认，未实施

日期：2026-07-19

## 1. 修改目标

V0.29 基于当前 V0.28，新增可选的 WebDAV 多端同步能力，默认适配坚果云，并保持语迹“本机来源只上传、其他设备来源只下载”的单向数据边界。

本版本固定完成以下内容：

```text
1. 顶栏新增“云设置”，并按当前来源显示“上传”或“下载”。
2. 支持保存一组 WebDAV 连接，默认适配坚果云官方 WebDAV 地址。
3. 为每台电脑生成稳定设备 UUID，各设备只写自己的云端目录。
4. 本机 Codex、本机 Claude 及其归档会话允许上传，不允许从云端覆盖本机原始聊天记录。
5. 其他设备的 Codex、Claude 分别作为只读云端来源，允许下载，不允许上传或编辑原始记录。
6. 手工复制的外部来源不上传；WebDAV 来源不上传；本设备自己的云端副本不重复显示。
7. 会话原始文件使用内容寻址对象、稳定小文件包和 64 MB 大文件分块进行增量传输。
8. 会话数据与备注分别维护 chatRevisionId 和 notesRevisionId；备注只有来源设备可编辑。
9. 上传和下载均由用户手动触发，自动检查只负责判断是否最新。
10. 刷新按钮根据本机来源是否变化决定可用或置灰；上传状态与刷新状态相互独立。
11. 下载采用完整暂存、严格校验、解析成功后原子替换，失败时继续显示上一次成功版本。
12. 后台任务展示文件、字节、阶段和百分比；网页刷新后可重新连接任务。
13. WebDAV 配置、缓存、日志和暂存内容继续放在项目的“运行数据”中，并按本机键隔离。
14. 实施前新建 软件/CodexChatIndex_V0.28，按源码白名单归档当前实际 V0.28；原 软件/CodexChatIndex 原位升为 V0.29。
```

V0.29 的云端用途是多端同步，不是备份系统：

```text
不保留远端历史版本。
不提供回收站或延迟删除。
来源设备确认删除的记录会从新清单中立即移除。
清单提交后，旧的未引用对象进入清理流程。
```

本文档落成后不执行源码归档、代码修改、升版、构建、网络连接或测试，必须等待用户再次确认后再实施。

## 4. 来源方向和功能边界

### 4.1 来源类型

V0.29 使用以下来源类型：

```text
local-codex：当前设备的 Codex，会话和归档均可上传。
local-claude：当前设备的 Claude，可上传。
external-codex-jsonl：手工复制到外部文件夹的记录，不参与 WebDAV 上传。
webdav-codex：其他设备下载到本机的 Codex，只读。
webdav-claude：其他设备下载到本机的 Claude，只读。
```

来源显示示例：

```text
XF-本机 Codex
XF-本机 Claude
Laptop-云端 Codex
Laptop-云端 Claude
```

同名设备使用：

```text
Laptop-a1b2c3-云端 Codex
Laptop-a1b2c3-云端 Claude
```

其中 `a1b2c3` 为设备 UUID 的前 6 个十六进制字符，只在设备显示名重复时追加。

### 4.2 固定方向矩阵

| 当前来源 | 上传 | 下载 | 刷新 | 快刷 | 全量 | SESSION/回复 | 备注编辑 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 本机 Codex | 是 | 否 | 是 | 是 | 是 | 是 | 是 |
| 本机 Claude | 是 | 否 | 是 | 是 | 是 | 是 | 是 |
| 手工外部来源 | 否 | 否 | 是 | 按现有能力 | 是 | 按现有能力 | 是 |
| 其他设备云端 Codex | 否 | 是 | 否 | 否 | 仅重建本地缓存索引 | 否 | 否 |
| 其他设备云端 Claude | 否 | 是 | 否 | 否 | 仅重建本地缓存索引 | 否 | 否 |

补充规则：

```text
上传只处理当前选中的本机来源，不同时上传 Codex 和 Claude。
下载只处理当前选中的云端来源，不同时下载同设备的另一个来源。
本设备上传到云端的副本不作为新的来源显示。
来源切换继续限定目录、标题、会话和搜索范围。
云端来源允许查看、搜索、筛选、复制全文、导出 MD 和查看只读备注。
云端“路径”允许显示和复制来源设备原路径，但必须提示该路径可能不属于当前电脑。
```

### 4.3 能力字段

服务端为每个来源返回明确能力，不让前端依赖标签文字猜测：

```json
{
  "canRefresh": true,
  "canQuickRefresh": true,
  "canRebuild": true,
  "canUpload": true,
  "canDownload": false,
  "canResume": true,
  "canReply": true,
  "canEditNotes": true,
  "canResolveLocalImages": true,
  "isReadOnly": false
}
```

云端来源必须由服务端同时拒绝备注写入、上传、SESSION 和回复请求；不能只在前端隐藏按钮。

## 5. 坚果云连接和凭据

### 5.1 默认配置

坚果云默认值：

```text
WebDAV URL：https://dav.jianguoyun.com/dav/
用户名：坚果云账号邮箱
密码：坚果云生成的第三方应用密码，不是登录密码
远端根目录：YujiSync
认证：HTTP Basic Auth over HTTPS
```

`YujiSync` 使用 ASCII 名称，避免不同 WebDAV 客户端对中文路径编码处理不一致。

实施和用户说明以坚果云官方资料为准：

```text
https://help.jianguoyun.com/?p=2064
https://help.jianguoyun.com/?p=3348
```

### 5.2 单连接规则

V0.29 只启用一组 WebDAV 连接，但配置中保留 `connectionId`：

```json
{
  "version": 1,
  "connectionId": "随机 UUID",
  "enabled": true,
  "baseUrl": "https://dav.jianguoyun.com/dav/",
  "username": "脱敏前的真实账号",
  "protectedPassword": "DPAPI 密文 Base64",
  "remoteRoot": "YujiSync",
  "deviceDisplayName": "XF",
  "allowInsecurePrivateHttp": false
}
```

修改以下任一项时创建新的 `connectionId`，并要求重新输入密码：

```text
baseUrl
username
remoteRoot
```

只修改设备显示名不创建新连接。

连接改变后：

```text
旧连接的云端来源停止显示。
询问是否清理旧连接的本地缓存。
不自动连接旧服务器删除任何数据。
新连接必须重新检查连通性。
```

### 5.3 DPAPI 密码保存

```text
密码使用 Windows DPAPI CurrentUser 加密后保存为 Base64。
配置文件不保存明文密码。
同一电脑、同一 Windows 用户不需要重复输入。
项目复制到其他电脑或改由其他 Windows 用户运行时，需要重新输入一次。
前端读取设置时只得到 passwordSaved=true，不得到密文或明文。
密码输入框显示“已保存，留空不修改”。
修改 URL、用户名或远端根目录时，留空密码无效，必须重新输入。
```

V0.29 不使用 Windows Credential Manager，也不依赖第三方密码服务。

### 5.4 HTTPS 和重定向

```text
坚果云必须使用 HTTPS，并使用系统证书校验。
不提供“忽略证书错误”或自签名证书绕过。
公开网络 HTTP 地址禁止保存。
仅允许用户显式打开“允许局域网 HTTP”，且目标解析结果必须全部是回环、链路本地或 RFC1918 私有地址。
只允许同协议、同主机、同端口重定向。
跨主机重定向立即停止，绝不转发 Authorization。
URL 中禁止嵌入用户名、密码、查询凭据和 fragment。
```

### 5.5 连通性检查

设置窗口使用尚未保存的输入值进行检查。检查过程在：

```text
YujiSync/.probe/<随机 UUID>/
```

验证：

```text
PROPFIND
MKCOL
PUT
GET
MOVE
DELETE
```

测试写入随机短文本，读取后校验内容，再移动和删除；同时验证 ETag、`If-Match` 和 `If-None-Match` 条件请求。测试完成后清理探针；清理失败时记录路径，下次检查继续清理。任何检查都不能读取或修改 `v1/devices/` 中的正式来源数据。

## 6. 设备身份和本机运行数据

### 6.1 本机键

由于项目可能位于 OneDrive 目录，不能让多台电脑共享同一个设备文件。

本机键固定计算为：

```text
SHA-256(Windows MachineGuid + "\n" + 当前用户 SID) 的前 16 个小写十六进制字符
```

规则：

```text
不保存原始 MachineGuid 或 SID。
电脑改名不改变本机键。
重装 Windows、克隆系统身份或更换 Windows 用户可能产生新本机键，并被视为新设备。
无法可靠取得 MachineGuid 或 SID 时，WebDAV 功能停止并显示明确错误，不生成每次变化的临时身份。
```

### 6.2 本机目录

采用已确认的 44B：所有配置和缓存继续保存在项目 `运行数据` 中。

```text
运行数据/
  CodexChatIndex.local/
    <本机键>/
      CodexChatIndex.device.json
      CodexChatIndex.webdav.json
      CodexChatIndex.webdav-state.json
      CodexChatIndex.ui-state.json
      CodexChatIndex.webdav/
        connections/
          <connectionId>/
            catalog.json
            logs/
            tasks/
            devices/
              <远端设备UUID>/
                local-codex/
                  manifest.json
                  raw/
                  staging/
                  journal/
                local-claude/
                  manifest.json
                  raw/
                  staging/
                  journal/
      CodexChatIndex.sources/
        webdav-<connectionId>-<设备UUID>-local-codex/
        webdav-<connectionId>-<设备UUID>-local-claude/
```

现有本机和手工外部来源继续使用原 `运行数据/CodexChatIndex.sources/` 布局；新增 WebDAV 来源通过 `get_source_paths()` 的来源能力映射到本机键目录，不能写入其他电脑的 WebDAV 缓存目录。

当前选中来源等本机 UI 状态写入 `CodexChatIndex.ui-state.json`，不把其他设备才存在的 WebDAV sourceId 写入所有电脑共享的旧来源状态文件。

### 6.3 设备 UUID

`CodexChatIndex.device.json` 保存：

```json
{
  "version": 1,
  "deviceId": "UUID v4",
  "createdAt": "UTC ISO-8601"
}
```

设备 UUID 随机生成一次并稳定保留。设备显示名默认使用电脑名，可在设置中修改，但显示名不是身份依据。

## 7. WebDAV 远端协议

### 7.1 目录结构

```text
YujiSync/
  .probe/
  v1/
    devices/
      <设备UUID>/
        device.json
        local-codex/
          manifest.json
          staging/
          manifests/
            <manifestRevisionId>.json
          objects/
            <SHA256前两位>/
              <SHA256>.bin
          notes/
            <notesRevisionId>.json
        local-claude/
          manifest.json
          staging/
          manifests/
            <manifestRevisionId>.json
          objects/
            <SHA256前两位>/
              <SHA256>.bin
          notes/
            <notesRevisionId>.json
```

含义：

```text
YujiSync：本软件默认远端根目录。
v1：云端协议版本，与软件 V0.29 版本无关。
devices：设备集合。
设备 UUID：稳定写入通道，每台设备只写自己的目录。
local-codex / local-claude：两个独立来源通道。
```

V0.29 不创建所有设备共同写入的全局 catalog。设备发现使用 `devices/` 的 Depth:1 `PROPFIND`，设备详情使用 `device.json` 和 ETag 本地缓存。

### 7.2 JSON 规范

协议 JSON 统一：

```text
UTF-8，无 BOM。
换行使用 LF。
散列输入使用键名排序、无多余空白的 canonical JSON。
所有协议时间写 UTC ISO-8601，仅用于显示和日志，不参与“是否最新”判断。
所有 SHA-256 使用 64 位小写十六进制。
未知可选字段可以忽略；未知 schemaVersion 或 requiredFeatures 必须拒绝。
```

### 7.3 device.json

```json
{
  "schemaVersion": 1,
  "protocol": "YujiSync/v1",
  "deviceId": "设备 UUID",
  "displayName": "XF",
  "updatedAt": "UTC ISO-8601",
  "sources": ["local-codex", "local-claude"]
}
```

`updatedAt` 不决定数据新旧。设备删除只能在一次完整、成功的设备目录检查中确认；网络错误不能被解释为设备已删除。

### 7.4 manifest.json 当前指针

`manifest.json` 是小型当前指针：

```json
{
  "schemaVersion": 1,
  "protocol": "YujiSync/v1",
  "deviceId": "设备 UUID",
  "sourceType": "local-codex",
  "manifestRevisionId": "SHA256",
  "manifestPath": "manifests/<manifestRevisionId>.json",
  "chatRevisionId": "SHA256",
  "notesRevisionId": "SHA256",
  "logicalFileCount": 123,
  "logicalBytes": 456789,
  "updatedAt": "UTC ISO-8601"
}
```

状态检查只需条件读取该指针，不需要列出 `objects/`。

最终提交使用对 `manifest.json` 本身的条件 `PUT`：

```text
首次创建使用 If-None-Match: *。
更新使用之前 GET 得到的 If-Match: <ETag>。
412 Precondition Failed 视为同设备通道并发冲突，立即停止并标红。
```

不能把 `If-Match` 错误地应用到临时 MOVE 的源文件；条件必须保护最终的 `manifest.json` 资源。

### 7.5 完整 manifest

完整清单保存为不可变的 `manifests/<manifestRevisionId>.json`：

```json
{
  "schemaVersion": 1,
  "protocol": "YujiSync/v1",
  "deviceId": "设备 UUID",
  "sourceType": "local-codex",
  "chatRevisionId": "SHA256",
  "notesRevisionId": "SHA256",
  "logicalFileCount": 123,
  "logicalBytes": 456789,
  "logicalFiles": [],
  "notes": {
    "path": "notes/<notesRevisionId>.json",
    "size": 0,
    "sha256": "SHA256"
  }
}
```

完整 manifest 内部不保存 `manifestRevisionId`，避免清单散列自引用。计算规则固定为：

```text
manifestRevisionId = SHA-256(完整 manifest 的 canonical UTF-8 字节)
```

下载时按相同规则计算并与文件名及当前指针同时比对。完整 manifest 不包含生成时间等非确定性字段；同一份会话和备注逻辑内容必须生成同一个 `manifestRevisionId`。

每个 `logicalFiles` 项固定包含：

```text
logicalPath：来源内规范化相对路径，使用 /。
originPath：来源设备原始绝对路径，只用于展示和复制，不用于本机解包目标。
size：本次快照逻辑字节数。
sha256：本次快照逻辑文件 SHA-256。
archived：是否归档。
sourceMeta：固定结构的来源元数据，包括 rootKind、recordFormat 和 Claude entrypoint；不允许任意未定义对象。
storage：object、pack-entry 或 chunks 三种存储描述之一。
```

`sourceMeta` 取值固定为：

```text
rootKind：sessions、archived_sessions、projects、sessions_metadata 或 claude_desktop。
recordFormat：jsonl 或 json。
entrypoint：Claude 已解析到的 cli、claude-desktop-3p 或空字符串；Codex 固定为空字符串。
```

完整 manifest 的 `logicalFiles` 必须按 logicalPath ordinal 排序，chunks 必须按数字序号排序。`chatRevisionId` 固定基于 logicalPath、originPath、逻辑内容 SHA-256、大小、归档状态和上述 sourceMeta 计算，不包含文件 mtime、设备时间或打包方式。来源路径或 sourceMeta 变化时，即使正文不变，也必须产生新的 chatRevisionId。

## 8. 上传快照、打包和对象

### 8.1 扫描范围

本机 Codex 上传：

```text
$HOME/.codex/sessions/**/*.jsonl
$HOME/.codex/archived_sessions/**/*.jsonl
```

本机 Claude 上传：

```text
递归读取当前本机 Claude 来源解析器已支持的 *.jsonl。
包含解析 Claude Code CLI 和 Claude Desktop 所需的 .claude/sessions/*.json 元信息。
保留 entrypoint 等必要元信息，用于区分 cli 和 claude-desktop-3p，但来源层面统一为本机 Claude。
不扩展到现有解析器未支持的任意用户目录。
```

上传服务不得在 Python 中另写一套 Codex/Claude 文件边界判断。Build-CodexChatIndex.ps1 新增 `-ExportSyncInventoryPath <任务临时文件>`，复用当前构建使用的来源枚举、归档判断和 Claude 根目录规则，输出：

```text
sourceId
sourceType
sourceSignature
每个文件的 absolutePath、logicalPath、originPath、rootKind、recordFormat、archived、entrypoint
scanComplete 和全部扫描错误
```

同步 inventory 只写入当前 WebDAV 任务 staging，上传结束后删除，不写入长期日志。只有 `scanComplete=true` 且不存在未处理扫描错误时才能继续打包。

### 8.2 活动文件一致性

对 JSONL：

```text
任务开始时记录文件身份和长度。
只读取到该长度以内最后一个完整换行结束的 JSONL 记录。
末尾半条记录不上传。
上传过程中追加的数据留到下一次上传。
任务完成后重新检查来源快速签名；发生变化时“上传”继续可用。
```

对 Claude JSON 元信息：

```text
读取前后核对大小和 mtime。
发生变化时最多重新读取一次。
仍不稳定则本次上传安全失败，不提交残缺清单。
```

### 8.3 小文件稳定分组

小于 `1 MiB` 的逻辑文件进入稳定分组：

```text
bucket = SHA-256(规范化 logicalPath UTF-8) 的前两位。
最多 256 个 bucket：00 至 ff。
组内按 logicalPath 的 ordinal 顺序排列。
包使用 ZIP_DEFLATED，compresslevel=1。
ZIP 项目时间固定，路径使用 /，不写本机绝对路径和非确定性 extra 字段。
单包目标逻辑大小不超过 64 MiB；超过时按排序结果稳定分段。
```

清单为每个文件记录包对象 SHA-256、包内 entry 名称、逻辑大小和逻辑 SHA-256。修改一个普通小文件通常只重建其 bucket 对应的小包。

### 8.4 独立对象和大文件分块

```text
大于等于 1 MiB 且不超过 64 MiB：作为单独内容寻址对象。
超过 64 MiB：按固定 64 MiB 二进制边界分块，最后一块使用实际长度。
每一块单独记录大小和 SHA-256。
下载后按清单顺序重组，再验证完整逻辑文件 SHA-256。
```

远端对象路径使用：

```text
objects/<SHA256前两位>/<SHA256>.bin
```

软件不依赖列出整个 `objects/` 目录。缺失对象通过精确路径条件写入；已经存在且散列相同的对象直接复用。

### 8.5 内存和临时文件

```text
哈希、ZIP 写入、上传和下载均使用固定大小缓冲区流式处理。
不在 Python 或浏览器内存中保存完整大文件、完整 ZIP 或全部对象正文。
ZIP 先写本机 staging 临时文件，再计算对象 SHA-256。
任务成功、取消或失败后清理不再需要的临时文件。
```

## 9. 上传事务

### 9.1 前置检查

上传前必须：

```text
确认当前来源为 local-codex 或 local-claude。
确认 WebDAV 已启用且连接字段完整。
确认没有其他 WebDAV 传输任务。
通过 -ExportSyncInventoryPath 完整扫描来源并区分“真实为空”和“扫描失败”。
读取当前远端 manifest.json、正文和 ETag；不存在时按首次上传处理。
获取本机备注快照。
```

首次点击上传直接开始，不增加普通知情确认。

### 9.2 大量删除保护

以下情况要求明确确认：

```text
远端原有记录非空，新清单变为空。
删除数量不少于 20 条，并且达到远端原记录的 20%。
```

来源目录不可访问、扫描中断或解析失败时不能用确认绕过，必须直接禁止上传。

确认只对本次计算结果有效。确认后来源再次变化时必须重新扫描和确认。

### 9.3 提交顺序

```text
1. 记录旧 manifest.json 内容和 ETag。
2. 根据完整快照计算 chatRevisionId。
3. 根据本机来源备注计算 notesRevisionId。
4. 生成小文件包、独立对象和大文件块。
5. 使用内容寻址路径上传远端缺失对象；已存在对象复用。
6. 仅在 notesRevisionId 变化时上传 notes/<notesRevisionId>.json。
7. 生成完整 manifest 并计算 manifestRevisionId；先上传到当前来源的 staging/<taskId>/manifest.json，成功后使用 MOVE 发布到不可变 manifests/<manifestRevisionId>.json。目标已存在时必须读取并验证散列后复用。
8. 使用 If-Match 或 If-None-Match 条件 PUT 更新 manifest.json 当前指针。
9. 指针提交成功后更新本机已上传修订状态。
10. 删除旧清单不再引用的对象、旧 notes 和旧完整 manifest。
11. 重新检查本机快速签名，决定上传按钮是否仍可用。
```

`manifest.json` 成功提交是可见版本切换点。提交前取消或失败，其他设备继续读取旧版本；提交后取消按钮立即禁用，剩余工作只包括安全清理和本机状态落盘。

### 9.4 备注单独增量

只有备注变化时：

```text
复用旧 chatRevisionId 和全部聊天对象。
只上传新的 notes 对象、完整 manifest 和当前指针。
不重新打包 JSONL。
不重新解析本机会话。
```

### 9.5 失败和清理

```text
ETag 冲突：提示“当前设备通道已被另一实例修改”，不覆盖。
网络、认证、限流或服务器错误：停止并显示具体原因，不自动长时间重试。
指针提交前失败：远端可见版本不变。
指针提交后旧对象清理失败：新版本仍有效，记录待清理清单，下一次手动任务继续清理。
本机日志记录已上传对象，手动重试时复用，不从头传输。
```

## 10. 下载、缓存和解析

### 10.1 云端来源发现

其他设备的 `device.json` 一旦被成功发现，对应 Codex、Claude 来源立即出现在来源下拉框中，即使本机尚未下载。

首次选择时显示空状态：

```text
此云端来源尚未下载。
```

同时显示可用“下载”按钮。

### 10.2 下载顺序

```text
1. 条件读取 manifest.json 当前指针。
2. 校验协议、设备 UUID、来源类型和修订字段。
3. 读取并校验不可变完整 manifest。
4. 根据 logicalBytes、缺失对象、暂存空间和旧缓存计算所需磁盘空间。
5. 空间不足时在下载前停止，显示所需与可用空间。
6. 把缺失对象流式下载到 staging。
7. 每个对象验证声明大小和 SHA-256。
8. 安全解包、重组逻辑文件，并再次验证每个逻辑文件大小和 SHA-256。
9. 生成 originPath 映射，但绝不以 originPath 作为本机写入路径。
10. 使用云端来源类型调用 Build-CodexChatIndex.ps1 解析 staging 快照。
11. 构建输出写入任务专属 staging index 根目录，不直接写当前可见索引。
12. 数据、搜索索引、会话详情和备注均成功后，原子替换当前云端缓存和索引。
13. 提交本机 downloadedChatRevisionId 和 downloadedNotesRevisionId。
14. 恢复当前来源的 Progress Anchor。
15. 删除旧缓存、下载对象临时文件和 staging。
```

### 10.3 云端来源构建参数

Build-CodexChatIndex.ps1 新增明确参数：

```text
-SourceType webdav-codex / webdav-claude
-RemoteSourceRoot <本机 staging 或 raw 根目录>
-OriginMapPath <经过校验的逻辑路径到来源原路径映射>
-DisableLocalPathImages
```

规则：

```text
webdav-codex 复用 Codex 解析器，不扫描当前用户 .codex。
webdav-claude 复用 Claude 解析器，不扫描当前用户 .claude。
生成数据中的 path 使用 originPath 供查看和复制。
读取正文只使用受控 raw 路径。
本机绝对路径图片解析关闭，避免把其他电脑路径误当成本机文件。
JSONL 内嵌 Base64 图片仍按现有规则显示。
下载解析和云端“全量”都把 -DataRoot、-OutputPath 指向任务 staging；验证输出完整后只替换该 webdav sourceId 的数据目录，不用半成品覆盖当前索引。
```

### 10.4 备注单独下载

若 `chatRevisionId` 未变而 `notesRevisionId` 变化：

```text
只下载和校验 notes 对象。
原子替换该云端来源的只读备注缓存。
不下载聊天对象。
不重新构建会话索引。
```

### 10.5 下载失败和回滚

```text
任何对象、逻辑文件、清单或解析失败都拒绝整次更新。
继续显示上一次成功下载和解析的版本。
不把部分新记录混入旧索引。
不提交新的 downloadedRevisionId。
失败按钮标红并允许用户手动重试。
```

### 10.6 阅读位置

下载成功后复用现有 Progress Anchor：

```text
优先恢复当前目录、标题、会话和选中提问。
使用稳定 sessionKey/questionKey 及已有回退规则。
直接 auto 定位，不使用平滑滚动。
目标会话已被来源设备删除时，会话区显示“当前会话已不存在”，不自动跳到其他会话。
不得先跳顶部或最后提问，再跳回锚点。
```

### 10.7 离线缓存和清理

停用 WebDAV 后：

```text
已下载来源继续作为只读离线缓存显示。
上传/下载按钮隐藏。
重新启用同一连接后恢复状态检查。
```

设置窗口列出每个云端来源缓存大小，并提供：

```text
清除当前来源缓存
清除全部云端缓存
```

清除前明确提示“只删除本机缓存，不删除坚果云内容”。清除正在显示的来源后，会话区变为空并重新显示下载入口。

## 11. 备注同步

### 11.1 单写规则

```text
本机来源：备注可新建、编辑、删除，并参与上传。
其他设备云端来源：备注可查看，但新建、编辑、删除全部禁止。
```

云端来源触发写备注 API 时，服务端返回：

```text
云端备注只能在来源设备编辑
```

不能仅通过隐藏右键菜单来保证只读。

### 11.2 备注对象

notes 对象只包含当前来源的备注，不同步其他来源备注：

```json
{
  "schemaVersion": 1,
  "deviceId": "设备 UUID",
  "sourceType": "local-codex",
  "notes": {}
}
```

`notesRevisionId` 为 canonical notes JSON 的 SHA-256。备注更新时间可保留用于显示，但不用时间戳解决冲突。

备注键按 ordinal 排序后再生成 canonical JSON，确保同一备注内容在不同电脑上得到相同 notesRevisionId。

### 11.3 明确不同步的状态

```text
阅读进度
目录、标题和会话选中项
筛选和排序
搜索词与搜索范围
回复框草稿
WebDAV 设置和密码
浏览器 UI 偏好
```

## 12. 来源发现和设备生命周期

### 12.1 无共享 catalog

设备发现流程：

```text
1. 对 YujiSync/v1/devices/ 做 Depth:1 PROPFIND。
2. 正确处理坚果云 750 项分页或 continuation 信息，直到完整结束。
3. 与本机 catalog.json 对比设备目录和 ETag。
4. 只对新增或 ETag 变化的设备重新读取 device.json。
5. 缓存未变化设备信息。
```

只有完整成功的目录检查才能确认设备删除。超时、认证失败、分页失败或解析失败都不能删除本地来源入口和缓存。

### 12.2 来源 ID

```text
webdav-<connectionId>-<设备UUID>-local-codex
webdav-<connectionId>-<设备UUID>-local-claude
```

来源 ID 不使用设备显示名，因此改名不会丢失缓存、备注或阅读锚点。

### 12.3 停用与注销

“停用 WebDAV”：

```text
只停止连接和自动状态检查。
不删除远端数据。
保留本地离线缓存。
```

“从云端注销本设备”：

```text
要求用户输入当前设备显示名确认。
只删除 YujiSync/v1/devices/<当前设备UUID>/。
不能选择或删除其他设备。
删除成功后保留或清除本机缓存由明确提示决定。
```

设备已经遗失时，只能通过坚果云文件管理或其他 WebDAV 管理工具删除旧设备目录；V0.29 不提供接管其他 UUID 的功能。

## 13. 状态检查和顶栏按钮

### 13.1 当前来源状态

新增统一状态接口，至少返回：

```json
{
  "ok": true,
  "sourceId": "local-codex",
  "refresh": {
    "state": "latest|changed|checking|error|unsupported",
    "reason": ""
  },
  "sync": {
    "action": "upload|download|none",
    "state": "latest|changed|checking|running|error|disabled",
    "chatChanged": false,
    "notesChanged": false,
    "reason": ""
  }
}
```

状态错误绝不能映射成 `latest`。

### 13.2 本机刷新 StatusOnly

Build-CodexChatIndex.ps1 新增 `-StatusOnly`，复用现有 `New-SourceSignature` 和缓存签名逻辑：

```text
只枚举当前来源支持的文件并生成来源签名。
与 CodexChatIndex.cache.json.sourceSignature 比较。
同时检查 data、search、cache 和会话详情输出是否完整。
不解析 JSONL。
不写 HTML、data、search、cache、sessions 或 sources manifest。
最后只输出机器可读 JSON 摘要。
```

结果：

```text
签名相同且输出完整：刷新置灰。
签名变化或输出缺失：刷新可用。
检测失败：刷新标红但可点击，点击执行正常增量刷新。
云端来源：普通刷新和快刷置灰。
```

### 13.3 上传是否最新

本机来源使用两阶段检查：

```text
快速阶段比较本机来源签名、备注状态、最近成功上传状态和当前远端指针。
快速签名变化时上传可用，点击后再计算完整内容 SHA-256。
如果只发生 mtime 变化而内容修订未变，上传任务安全返回 no-op 并恢复置灰。
不能为了每次焦点检查而重新哈希全部 JSONL。
```

### 13.4 下载是否最新

```text
远端 chatRevisionId 或 notesRevisionId 与本机成功下载状态不同：下载可用。
两者都相同：下载置灰。
尚未下载：下载可用。
检查失败：下载标红但可点击，点击重新检查并尝试下载。
```

### 13.5 检查触发点

```text
页面启动。
来源切换。
浏览器重新获得焦点。
刷新、上传、下载、清缓存或设置保存完成后。
页面持续可见时最多每 60 秒一次兜底检查。
```

范围固定为：

```text
启动或重新获得焦点时检查设备目录是否变化。
只检查当前选中的同步来源清单。
当前为本机来源时检查本地变化和本设备远端清单。
当前为其他设备云端来源时只检查该来源远端清单。
切换来源立即检查，不等待 60 秒。
```

### 13.6 上传、下载和刷新相互独立

```text
刷新只更新本地网页索引。
上传只发布任务开始时的本机原始记录和备注快照。
上传不自动刷新本机网页。
刷新不自动上传。
下载成功必须自动解析云端缓存，不需要再点刷新。
```

## 14. 后台任务、进度和取消

### 14.1 单任务

同一服务器进程同一时间只允许一个 WebDAV 上传或下载任务。

```text
第二个浏览器页面读取并显示同一任务。
第二次传输请求不创建重复任务。
设置检查可以读取配置，但正式传输期间不能修改连接或清理相关缓存。
```

### 14.2 任务状态

任务至少记录：

```text
taskId
action
sourceId
stage
status
filesTotal / filesDone
bytesTotal / bytesDone
percent
startedAt / updatedAt
cancelRequested
canCancel
errorSummary
```

任务阶段：

```text
扫描
打包
比较清单
上传对象 / 下载对象
校验
重组
解析
提交清单 / 替换缓存
清理
完成
```

前端轮询任务；网页刷新后使用 taskId 重新连接。传输不依赖浏览器页面持续打开。

### 14.3 取消

```text
取消在文件或分块边界协作生效。
当前正在传输的部分临时文件丢弃，下次从该对象开头重试。
已经完成的内容寻址对象保留并复用。
不实现 HTTP Range 字节级续传。
最终 manifest.json 指针提交后 canCancel=false。
```

### 14.4 服务器关闭

```text
网页刷新不会中断后台任务。
关闭 CMD 或服务器进程会中断任务。
下次启动读取 journal，将任务标记为“传输已中断”并标红。
不自动联网续传。
用户手动点击后复用已完成对象和本机暂存信息。
```

### 14.5 与本地构建的资源协调

上传期间仍允许本机刷新、快刷和全量：

```text
本地构建任务优先。
WebDAV 打包在文件边界暂停或降低工作速率。
压缩使用 level=1，不启用多个并行压缩任务。
网络传输采用受控单流，不用高并发请求抢占磁盘和 CPU。
```

## 16. 严格校验和安全边界

### 16.1 云端数据校验

下载必须检查：

```text
协议和 schemaVersion。
deviceId 与目录一致。
sourceType 与当前来源一致。
manifestRevisionId、chatRevisionId、notesRevisionId 格式。
完整 manifest 自身 canonical SHA-256。
对象路径是否严格符合内容散列。
对象声明大小和实际大小。
对象 SHA-256。
逻辑文件重组后大小和 SHA-256。
ZIP entry 是否与清单一致。
```

任一失败拒绝整个新版本。

读取上限固定为：

```text
device.json 和 manifest.json 当前指针：各 256 KiB。
完整 manifest 和 notes 对象：各 64 MiB。
单页 PROPFIND XML：16 MiB；分页后逐页释放，不累计保存原始 XML。
本地浏览器 JSON 修改请求体：256 KiB。
WebDAV 错误响应最多读取 64 KiB，持久日志最多保留清理后的 8 KiB。
```

超过上限必须显示明确错误，不能静默截断后继续解析。聊天对象和 ZIP 包不通过一次性响应正文加载，而是按第 8.5 节流式写入磁盘。

### 16.2 路径和 ZIP 安全

```text
拒绝绝对路径、盘符、UNC、..、空路径、NUL 和规范化后逃逸。
解包目标必须在当前 staging 根目录内。
只解包清单声明的 entry。
总解包大小不得超过 manifest.logicalBytes 和磁盘预检额度。
不执行 ZIP 中的符号链接、设备文件或权限元数据。
originPath 永远只作为普通字符串保存和展示。
```

### 16.3 本地 API 防护

```text
服务器只监听 127.0.0.1。
不返回 Access-Control-Allow-Origin: *。
服务启动时生成随机会话令牌。
页面通过同源只读接口取得令牌；跨域页面无法读取。
所有 POST、PUT、DELETE 类修改请求要求自定义令牌头，并校验 Origin/Referer 与当前本地服务一致。
请求体设置明确大小上限。
WebDAV 密码、DPAPI 密文和 Authorization 不进入 API 响应或普通日志。
```

### 16.4 远端未知内容

软件只管理明确的：

```text
YujiSync/v1/devices/<当前设备UUID>/
```

未知文件和未来版本目录默认忽略。清理对象只能根据当前设备、当前来源的旧清单和本机任务 journal 计算，不能递归删除整个 WebDAV 根目录。

### 16.5 不提供端到端加密

V0.29 采用 HTTPS 传输，但不对聊天正文和备注增加应用层加密。清单中的来源原路径、对象和备注在坚果云服务器端可被读取。

设置窗口和 README 必须明确这一点，不能继续笼统描述为“所有聊天记录不会上传第三方”。

## 17. 坚果云限制处理

已知设计约束：

```text
单个上传对象默认不得超过 500 MB。
免费账户约 600 请求 / 30 分钟。
付费账户约 1500 请求 / 30 分钟。
大型目录的 PROPFIND 可能按 750 项分页。
```

V0.29 对应措施：

```text
对象和包控制在约 64 MB，不接近 500 MB 上限。
小文件最多 256 个稳定 bucket，避免首次上传数千个 PUT。
状态检查优先读 manifest.json，不列出 objects。
对象目录按 SHA-256 前两位分片。
设备发现完整处理分页。
不并发启动多个传输。
```

限流处理采用用户已确认的手动策略：

```text
收到 429、503 或服务器限流信息后立即安全停止。
不实现长时间自动等待和自动重试。
清楚显示 Retry-After 和服务器原因。
用户稍后手动点击重新尝试。
已经完成的对象继续复用。
```

## 21. 副作用与规避

### 21.1 首次同步耗时较长

副作用：

```text
首次上传需要读取、哈希和打包全部本机会话，首次下载需要完整缓存和解析。
坚果云免费账户可能触发请求限额。
```

规避：

```text
小文件使用最多 256 个稳定 bucket。
大文件按 64 MiB 分块。
内容对象可复用。
限流原因和 Retry-After 清楚展示，由用户稍后手动重试。
后续普通增量通常只处理少量变化。
```

### 21.2 OneDrive 重复同步缓存

副作用：

```text
采用 44B 后，运行数据中的 WebDAV 缓存可能再次被 OneDrive 同步。
可能增加网络和磁盘占用；文件按需可能在查看时触发回下载。
```

规避：

```text
配置、状态和缓存按本机键隔离，避免不同设备互相覆盖。
临时包和旧缓存成功后立即清理。
提供每个来源缓存大小和清理按钮。
软件不自动改变 OneDrive 策略；文档建议按需要将缓存目录设为“始终保留在此设备上”。
```

### 21.3 下载临时双份空间

副作用：

```text
为了完整校验和回滚，更新期间可能同时存在旧缓存和新 staging。
```

规避：

```text
下载前按清单预估空间并保留安全余量。
空间不足时不开始替换。
成功后立即删除旧版本和临时对象。
```

### 21.4 无端到端加密

副作用：

```text
坚果云服务器理论上可以读取聊天正文、备注和来源原路径。
聊天记录可能包含项目路径、命令输出或敏感片段。
```

规避：

```text
使用坚果云 HTTPS 和独立第三方应用密码。
密码使用 DPAPI 保存。
README 和设置明确风险，不给出“完全本地”误导。
未来如增加端到端加密，应使用新的云端协议版本，不在 v1 中隐式改变格式。
```

### 21.5 远端绝对路径图片缺失

副作用：

```text
其他设备路径只在来源设备存在，下载端无法显示对应图片。
```

规避：

```text
不显示破损缩略图。
保留原始提问文字和图片引用文本。
Base64 内嵌图片继续显示。
图片资产同步明确不纳入 V0.29。
```

### 21.6 状态检查产生磁盘和网络请求

副作用：

```text
本机 StatusOnly 需要枚举来源文件元数据；远端检查需要读取设备目录或当前指针。
```

规避：

