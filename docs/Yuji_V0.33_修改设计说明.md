## 1. V0.33 修改目标

V0.33 聚焦两类纯前端交互优化：

1. **同标题多分支的母标题交互调整**
   - 右下角展开/收起箭头改得更明显，不再使用透明无边框样式。
   - 对“同标题下存在多个子会话”的母标题，点击整个母标题主体时，不再自动跳转到第一条子会话。
   - 整个母标题主体与右下角箭头统一执行同一个动作：展开 / 收起子会话。
   - 单会话标题保持当前点击进入会话的行为。

2. **备注显示模式切换**
   - 在顶部“云设置”左侧新增一个按钮。
   - 默认按钮文字为“备注”。
   - 默认保持 V0.32 当前行为：备注浮层只在鼠标悬停有备注的标题卡片时显示。
   - 点击“备注”后，按钮文字切换为“隐藏”。
   - 进入“常驻备注”模式后，备注仍然使用现有黄色浮层样式，不把备注正文写进标题卡片。
   - 所有当前可见、且有备注的母标题 / 子会话标题，同时显示各自独立的常驻备注浮层。
   - 再点击“隐藏”后，所有常驻备注浮层隐藏，恢复 V0.32 当前的鼠标悬停显示方式。

## 4. V0.32 当前标题分组行为

V0.32 已经具备：

- `groupSessionsByTitle()`
- 完全相同标题分组
- 多子会话标题组
- 右下角展开/收起箭头
- `localStorage` 保存折叠状态

当前多分支标题组大致结构：

```text
母标题

  ├─ 子会话 1
  ├─ 子会话 2
  └─ 子会话 3
```

当前代码中：

- 母标题主体：`.title-group-head`
- 箭头按钮：`.title-group-toggle`
- 子会话容器：`.title-group-sessions`

### 4.1 当前箭头样式问题

V0.32 当前箭头按钮主要样式：

```css
border: 0;
background: transparent;
```

只有 hover/focus 时才出现较弱背景。

因此视觉存在以下问题：

- 箭头区域边界不明显。
- 用户不容易第一眼判断它是可点击按钮。
- 与页面上其他带边框按钮的视觉语言不统一。

### 4.2 当前母标题点击行为

V0.32 对多分支母标题点击后执行：

```javascript
selectSessionFromTitlePane(group.sessions[0])
```

也就是：

**点击母标题 = 自动打开第一个子会话**

而右下角箭头才负责：

**点击箭头 = 展开 / 收起**

V0.33 要取消这种“双语义”，统一成：

**多分支母标题整个卡片 = 展开 / 收起**

## 5. V0.33 多分支母标题交互定义

### 5.1 多分支母标题

适用条件：

```javascript
group.sessions.length > 1
```

点击以下任意区域：

- 母标题文字
- 母标题元信息
- 母标题空白区域
- 右下角箭头

都执行相同行为：

```text
展开状态 → 收起
收起状态 → 展开
```

并且：

**不再自动跳转到任何子会话。**

### 5.2 单会话标题

如果：

```javascript
group.sessions.length === 1
```

则不显示展开/收起箭头。

点击标题时继续保持 V0.32 行为：

**直接打开该会话。**

因此 V0.33 的点击语义为：

| 标题类型 | 点击标题 | 点击箭头 |
|---|---|---|
| 单会话标题 | 打开会话 | 无箭头 |
| 多分支母标题 | 展开 / 收起 | 展开 / 收起 |
| 子会话标题 | 打开该会话 | 无箭头 |

## 6. 母标题与当前选中会话的关系

折叠状态与当前选中会话必须保持独立。

例如：

1. 当前正在查看母标题 A 下的子会话 A2。
2. 用户点击母标题 A。
3. 子会话列表被收起。
4. 主阅读区继续显示 A2。
5. `selectedSessionKey` 不改变。
6. 母标题仍保持 active 状态，用于表示当前阅读会话属于该组。

再次展开：

- A2 仍然保持选中。
- A2 对应子会话按钮仍为 active。

### 6.1 点击另一个未激活的母标题

例如当前正在查看 A2，此时点击母标题 B：

- 只展开/收起 B。
- 不自动切换到 B1。
- 主阅读区仍然显示 A2。

这样把：

**导航选择**

和：

**标题树展开状态**

完全分离。

## 7. 箭头按钮视觉修改

### 7.1 目标

箭头仍位于：

**母标题右下角**

但不再采用无边框透明样式。

建议视觉：

- 明确 1px 边框。
- 浅色背景。
- 与 Yuji 当前棕色主题一致。
- hover 时边框、背景、文字略增强。
- focus-visible 时有清晰焦点反馈。
- 收起时保持旋转方向变化。

建议逻辑样式：

```css
border: 1px solid rgba(...);
background: rgba(...);
color: var(--accent);
border-radius: 8px;
```

具体数值以 V0.32 现有主题变量为基准，不引入新的突兀配色。

### 7.2 尺寸

V0.32 当前约为：

```text
24 × 24
```

V0.33 可以保持或小幅放大到：

```text
26 × 26 / 28 × 28
```

原则：

- 可见性提升。
- 不明显挤压标题文字。
- 不改变标题卡片高度。

### 7.3 可访问性

箭头按钮继续保留：

- `aria-expanded`
- `title`
- 键盘 Enter / Space

母标题主体同样必须能用键盘触发展开 / 收起。

## 8. 母标题点击实现方式

建议抽出统一函数：

```javascript
toggleTitleGroup(groupNode, groupToggle, workspace, group)
```

由：

- `groupHead.onclick`
- `groupToggle.onclick`

共同调用。

统一函数负责：

1. 判断当前是否 collapsed。
2. 切换 `.collapsed`。
3. 更新 `aria-expanded`。
4. 更新箭头 title。
5. 写入 `localStorage`。
6. 刷新常驻备注浮层位置（如果常驻备注模式已开启）。

避免母标题与箭头各自维护一套重复逻辑。

## 9. 母标题右键备注行为

V0.32 当前通过：

```text
contextmenu
```

对：

- `.title-group-head`
- `.session-btn`

执行备注菜单。

V0.33 必须保持：

**右键母标题仍然打开备注菜单，不触发展开/收起。**

也就是说：

- 左键：展开 / 收起。
- 右键：备注操作。

当前 `contextmenu` 已经执行 `preventDefault()` 和 `stopPropagation()`，正式修改时要保留这一行为。

## 12. 备注显示模式定义

V0.33 有两个模式：

### 模式 A：悬浮显示

这是默认模式，也是 V0.32 当前行为。

顶部按钮：

```text

```

表现：

- 标题卡片保持原样。
- 有备注的卡片继续显示右上角小圆点。

- 鼠标悬停有备注标题时，显示当前黄色备注 tooltip。

### 模式 B：常驻显示

点击：

```text

```

后切换为：

```text
[隐藏]
```

表现：

- 标题卡片本身**完全不增加备注正文**。

点击：

```text
[隐藏]
```

后：

- 移除/隐藏所有常驻备注浮层。
- 按钮文字恢复“备注”。
- 恢复鼠标悬停显示单个备注 tooltip 的 V0.32 行为。

## 13. 常驻备注浮层位置

用户已确认：

**每条备注浮层固定显示在对应母标题 / 子会话卡片的右侧，并与卡片顶部对齐。**

概念示意：

```text
标题栏                       主阅读区

┌──────────────┐   ┌─────────────────────┐
│ 母标题 A   ● │ → │ 备注                 │
└──────────────┘   │ 这里是 A 的备注……    │
                   └─────────────────────┘

┌──────────────┐   ┌─────────────────────┐
│ 子会话 A1  ● │ → │ 备注                 │
└──────────────┘   │ 这里是 A1 的备注……   │
                   └─────────────────────┘
```

### 13.1 跟随规则

当标题列表滚动时：

- 备注浮层跟随对应卡片移动。
- 对应卡片滚出标题列表可视区域后，该备注浮层隐藏。
- 对应卡片重新滚入可视区域后，备注浮层重新显示。

### 13.2 页面 resize

浏览器窗口变化时：

- 重新计算所有常驻备注浮层位置。
- 避免继续停留在旧坐标。

### 13.3 侧栏收起

如果标题栏整体被收起：

- 所有常驻备注浮层隐藏。

标题栏重新展开：

- 如果仍处于“常驻备注”模式，重新生成 / 定位浮层。

## 14. 常驻备注浮层与标题折叠的关系

### 14.1 母标题备注

如果母标题本身有备注：

- 无论子会话展开还是收起，母标题备注浮层都继续显示。
- 前提是母标题卡片本身当前可见。

### 14.2 子会话备注

当母标题展开时：

- 当前可见子会话有备注 → 显示对应常驻浮层。

当母标题收起时：

- 子会话卡片隐藏。
- 对应子会话备注浮层同步隐藏。

再次展开：

- 子会话卡片恢复。
- 对应备注浮层重新出现。

因此：

**常驻备注模式不会突破标题折叠状态。**

---

## 15. 搜索与过滤时的常驻备注

当用户执行：

- 工作目录筛选
- 标题筛选
- 全局搜索
- 来源切换

导致标题卡片变化时：

- 只为当前实际显示出来的备注卡片创建常驻浮层。
- 已被过滤掉的标题不显示浮层。
- 过滤取消后重新显示时，再恢复对应浮层。

因此常驻备注是：

**基于当前渲染结果动态生成**

而不是一次性把所有 notes 都渲染到页面。

## 18. 常驻备注的鼠标交互

V0.32 tooltip 当前：

```css
pointer-events: none;
```

因为它只是临时悬浮提示。

V0.33 常驻浮层如果内容很长并需要内部滚动，就必须允许用户：

- 鼠标滚轮滚动浮层内容。
- 选中文字。
- 正常查看长备注。

因此建议：

- 普通 hover tooltip 继续 `pointer-events: none`。
- 常驻备注浮层使用独立 class，例如：
  `note-tooltip-pinned`
- pinned 浮层使用 `pointer-events: auto`。

但 pinned 浮层本身不提供：

- 编辑按钮
- 删除按钮
- 关闭按钮

备注编辑仍通过标题卡片右键完成。

## 19. 多个常驻备注同时显示

用户已确认：

**当前可见区域内可以同时显示多条常驻备注浮层。**

因此 V0.33 不能继续只使用单个 `#noteTooltip` DOM。

建议：

- 保留现有单实例 `#noteTooltip`，专门服务 hover 模式。
- 新增常驻浮层容器：

```html
<div id="pinnedNotesLayer"></div>
```

在常驻模式中，为每个当前可见的有备注卡片创建：

```html
<div class="note-tooltip note-tooltip-pinned" data-note-key="...">
```

这样避免破坏现有 hover 逻辑。

## 20. 多浮层重叠问题

由于备注浮层与各自卡片顶部对齐，如果相邻卡片都有较长备注，浮层可能发生空间重叠。

V0.33 采用以下原则：

1. **首先保证和对应卡片的空间关系明确。**
2. 不把浮层改成固定右侧备注面板。
3. 不把备注塞进标题列表。
4. 浮层保持受限最大宽高。
5. 当前鼠标所在的标题 / 浮层对应备注可提升 z-index，保证正在查看的备注位于最上层。

V0.33 不增加复杂的“自动排队式备注布局引擎”，避免此次小版本扩大成大型布局改造。

如果后续实际使用发现大量备注重叠严重，再单独设计备注侧栏或智能避让。

## 24. 常驻备注刷新时机

常驻备注位置必须在以下操作后刷新：

- `renderSessionList()`
- 标题组展开 / 收起
- 工作目录切换
- 来源切换
- 搜索结果变化
- 标题过滤变化
- 页面 resize
- 标题列表 scroll
- 左侧标题栏收起 / 展开
- 备注新增
- 备注编辑
- 备注删除
- notes 数据重新加载

建议统一入口：

```javascript
refreshPinnedNotes()
```

避免各处自己重复生成逻辑。

## 25. 性能策略

V0.33 常驻模式可能同时显示很多备注。

为了避免每次 scroll 都全量重建 DOM，建议：

### 第一次开启 pinned

- 扫描当前可见标题节点。
- 创建对应浮层。

### 标题列表 scroll

- 使用 `requestAnimationFrame` 节流。
- 只重新计算已有浮层位置。
- 只增删进入/离开可视范围的备注。

### renderSessionList 后

- 允许直接重新生成 pinned 浮层，因为标题 DOM 已经整体重建。

### resize

- 同样通过 `requestAnimationFrame` 节流定位。

不建议：

- 每个 mousemove 都重建 pinned 浮层。
- 使用高频定时器轮询。

## 26. Hover 模式与 Pinned 模式互斥

### hover 模式

允许：

```text
mouseover → showNoteTooltip
mousemove → moveNoteTooltip
mouseout → hideNoteTooltip
```

### pinned 模式

上述 hover tooltip 逻辑应关闭。

原因：

否则同一个备注会同时出现：

- 一个常驻浮层
- 一个鼠标浮层

造成重复。

因此事件处理函数中应增加：

```javascript
if (noteDisplayMode === 'pinned') return;
```

切回 hover 后恢复现有逻辑。

## 33. 副作用与风险

### 33.1 母标题不再快速进入第一条

这是 V0.33 明确要求。

以前：

```text
点击母标题 → 第一条子会话
```

以后：

```text
点击母标题 → 展开 / 收起
```

用户需要明确点击某个子会话才能进入。

这是行为变化，不是 BUG。

---

### 33.2 常驻备注可能遮挡主阅读区域

备注浮层位于标题卡片右侧，因此会悬浮到标题栏之外。

如果备注很多：

- 可能同时出现多个浮层。
- 可能覆盖部分主阅读区。
- 相邻长备注可能互相重叠。

这是本方案最大的 UI 副作用。

控制方式：

- 限制 max-width。
- 限制 max-height。
- 长备注内部滚动。
- hover 当前备注时提高 z-index。

V0.33 不引入复杂侧栏布局。

---

### 33.3 长备注需要额外交互

常驻浮层允许滚动，因此 pinned note 需要 `pointer-events: auto`。

这意味着浮层区域会截获鼠标事件。

需要避免：

- 浮层覆盖标题后导致标题无法点击。
- 浮层盖住顶部控制按钮。
- 浮层超出 viewport。

定位时需做边界约束。

---

### 33.4 多备注增加 DOM 数量

hover 模式只有 1 个 tooltip。

pinned 模式可能创建多个。

实际数量受当前标题可见数限制，通常不会非常大，但仍要：

- 只为当前可见标题生成。
- 不为过滤掉的标题生成。
- scroll 使用 RAF 节流。

---

### 33.5 localStorage 行为变化

用户上次选择 pinned 后，下次进入仍保持 pinned。

因此可能出现：

“为什么一打开就有很多备注浮层？”

这是设计行为。

README 应明确：

**备注显示方式会在当前浏览器中记忆。**

---

### 33.6 云端来源备注展示增加

云端来源虽然不可编辑，但 pinned 模式仍会显示已有备注。

这不会改变权限，但会让远端备注更显眼。

---

## 34. 安全与兼容性

V0.33 不引入新的远程请求。

常驻备注内容来自现有 notes 数据。

要求继续：

- 使用 `textContent`。
- 不用 `innerHTML` 插备注正文。
- 不把备注内容拼入可执行 HTML。
- 不改变 WebDAV 权限。
- 不改变备注 API 权限。

因此本版本安全面变化很小。
