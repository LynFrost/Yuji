# v0.36：标题区大标题元信息显示恢复

## 1. 基本信息

- 目标仓库：`LynFrost/Yuji`
- 目标分支：`feature/v0.36`
- 文档类型：需求与实现说明
- 本次范围：仅记录需求，不在本任务中修改程序代码。

## 2. 需求背景

此前提出的“标题改成一行”仅针对标题列表中的**子标题**。该要求不应导致**大标题下方的时间等小字说明**被隐藏。

当前需要明确区分大标题和子标题的展示规则，恢复大标题的元信息，同时保留子标题单行显示的既有要求。

## 3. 目标效果

### 3.1 大标题

1. 标题列表中的所有大标题都应显示标题文字，并在标题下方显示原有的小字元信息。
2. 此规则不因大标题是否包含多个子会话而改变：只有一个会话的大标题也必须显示元信息。
3. 元信息继续使用现有数据和展示规则，例如时间、用户/回答数量等当前界面已支持的信息；不得为了满足展示要求而虚构数据或改变统计口径。
4. 大标题沿用原有的大标题排版方式，不强制改为单行。标题较长时可以按原有规则换行。
5. 保持现有大标题的视觉层级：标题文字与下方元信息在字号、颜色和间距上继续区分，元信息使用原有的小字样式。

### 3.2 子标题

1. 子标题继续保持单行显示。
2. 当子标题超出可用宽度时，按当前设计使用省略号截断，不因本次修改而换行。
3. 本次不要求为子标题增加时间、用户/回答数量等大标题元信息。

## 4. 关键逻辑要求

需要将以下两项逻辑分别处理，避免相互绑定：

- **是否显示大标题元信息**：由大标题的展示规则决定，不应取决于该标题下是否存在多个子会话。
- **是否显示展开/折叠控件及子标题列表**：继续由现有的会话分组和子会话状态决定，不因恢复元信息而改变。

实现时优先复用现有元信息数据、渲染逻辑和样式，避免重复实现一套元信息生成逻辑。若单会话标题和多子会话标题目前使用不同的渲染分支，应保证两种情况最终都遵循同一套大标题元信息展示规则。

## 5. 修改范围与限制

### 需要修改

- 标题列表中大标题的渲染逻辑，使所有大标题恢复显示下方的小字元信息。
- 如有必要，仅调整相关标题区域的局部样式，确保标题与元信息的层级清晰。

### 不应修改

- 子标题单行显示规则。
- 标题排序、搜索、筛选、选择和点击行为。
- 母标题的展开/折叠行为及其控件。
- 备注、隐藏、会话内容展示和其他无关功能。
- 元信息的数据来源、统计口径及业务含义。
- 标题列表以外的目录栏或其他页面布局。

## 6. 验收标准

- [ ] 只有一个会话的大标题：显示标题文字及下方元信息。
- [ ] 包含多个子会话的大标题：继续显示标题文字及下方元信息。
- [ ] 大标题较长时：沿用大标题原有的换行规则，不强制单行。
- [ ] 子标题：始终单行显示，超出宽度时使用省略号。
- [ ] 展开、折叠、排序、搜索、筛选、选择和点击等原有功能正常。
- [ ] 元信息展示使用现有数据，时间及计数信息没有缺失、错位或重复。
- [ ] 修改仅影响标题列表相关展示，没有意外改变其他区域。

## 7. 可能影响

恢复元信息后，部分大标题卡片会比仅显示一行标题时更高，因此同一屏幕内可见的大标题数量可能减少。这是恢复信息展示带来的预期布局变化。应沿用现有小字样式并控制额外间距，不额外放大卡片高度。
