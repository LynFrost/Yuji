# Open-CodexChatIndex V0.05 修改文档

状态：已实施并验收

日期：2026-05-04

## 1. 修改目标

V0.05 的目标是在 V0.04 的会话阅读动线基础上，继续补齐“当前选中位置”和“键盘可操作状态”的一致性。

本版本重点不是改变数据结构，也不是重新设计整体布局，而是优化标题区选中提示、会话区键盘焦点、三个区回到顶部按钮的一致性，以及刷新时的进度反馈。

完成后，用户点击标题后应能立刻看到当前标题被选中，并且不需要再点击会话正文，就可以直接用键盘上下键切换提问。

## 2. 标题区选中提示

点击标题区任意标题后，标题区需要显示当前选中提示，视觉风格参考目录区当前选中项。

单分支标题：

```text
标题行本身显示 active 状态。
```

多分支标题：

```text
标题组可以显示较弱 active 状态。
具体被选中的分支行显示较强 active 状态。
```

这样既能看出当前属于哪个源头标题，也能看出当前实际打开的是哪个分支。

选中状态应跟随 `selectedSessionKey`，不能只依赖鼠标点击后的临时样式。刷新、重新渲染标题列表、切换目录后，都需要保持正确。

## 3. 点击标题后的键盘焦点

当前 V0.04 已经实现：点击标题后自动选中最后一个用户提问，并滚动到该提问位置。

V0.05 需要继续补齐 DOM 焦点：

```text
点击标题
加载会话详情
选中最后一个用户提问
滚动到最后一个用户提问
将键盘焦点交给会话区 transcript 容器
```

完成后，用户点击标题区某个标题之后，不需要再点击会话区，直接按键盘 `ArrowUp` / `ArrowDown` 就可以切换上一个或下一个提问。

推荐聚焦会话区容器，而不是直接聚焦某一条提问卡片。这样方向键监听逻辑更稳定，也能避免每次跳转时浏览器默认焦点样式在卡片之间闪动。

如果当前会话没有用户提问，则不强行设置提问焦点；只保持正常会话渲染，不报错。

## 4. 回到顶部后的键盘焦点

当前 V0.04 已经实现：点击会话区回到顶部后，自动选中第一个用户提问。

V0.05 需要继续补齐 DOM 焦点：

```text
点击会话区回到顶部
滚动到正文顶部
选中第一个用户提问
将键盘焦点交给会话区 transcript 容器
```

完成后，用户点击会话区回到顶部按钮后，不需要再点击会话区，直接按 `ArrowUp` / `ArrowDown` 就可以继续切换提问。

如果当前会话没有用户提问，则只执行回到顶部，不设置提问焦点，也不影响页面滚动。

## 5. 三个区回到顶部按钮统一

目录区、标题区、会话区的回到顶部按钮保持一致，都使用同一种“圆形按钮 + 向上箭头”的样式。

统一要求：

```text
按钮为圆形。
按钮内只显示向上箭头。
三个区按钮尺寸、边框、背景、阴影、透明度和 hover 效果保持一致。
```

如果某个区因为容器布局导致按钮位置或观感不一致，只调整该区布局适配，不另做一套按钮样式。

## 6. 刷新进度反馈

点击 `刷新` 按钮后，需要出现明确的刷新进度反馈。

推荐采用轻量的非百分比进度：

```text
刷新按钮进入 loading 状态。
按钮文案临时改为“刷新中...”。
刷新期间按钮禁用，防止重复点击。
页面顶部或按钮内部显示一条持续滚动的进度条。
刷新成功后恢复按钮状态，并显示刷新结果。
刷新失败后恢复按钮状态，并显示失败提示。
```

不建议显示百分比。当前刷新流程是一次 `/api/refresh` 请求，后端没有持续推送扫描进度；如果前端显示 10%、50%、90% 这类数字，会变成假进度，容易误导。

进度动画应使用 CSS `transform` 或背景位置变化实现，不使用高频 JS 定时器，不监听滚动，不触发持续布局重排。

刷新逻辑需要使用 `finally` 或等效结构保证无论成功、失败、异常退出，loading 状态都能清理。

## 7. 副作用和风险

点击标题后自动把键盘焦点交给会话区，会改变当前焦点归属。好处是可以直接用上下键切换提问；代价是此时上下键不再用于滚动标题列表。如果用户想继续操作标题区，需要用鼠标重新点击标题区，或通过键盘焦点导航回去。

点击会话区回到顶部后自动聚焦会话区，也会让方向键立即进入“切换提问”语义，而不是浏览器默认滚动语义。这个行为符合本版本目标，但需要保证只在会话区回到顶部按钮触发时发生，不要扩散成全局方向键劫持。

标题区选中提示如果同时高亮标题组和分支行，可能产生视觉噪音。多分支场景建议标题组弱高亮、分支行强高亮，避免用户误以为打开了整个标题组而不是某个具体分支。

刷新期间禁用按钮会阻止用户连续点击刷新。这个限制是有意的，可以避免多个刷新请求并发导致状态覆盖或结果提示混乱。

非百分比进度条不能告诉用户准确剩余时间，但它比假百分比更可靠。刷新慢时用户至少能明确知道软件仍在处理，而不是误以为按钮无响应。

进度条动画会增加极小的渲染开销。实现时必须避免高频 JS、避免滚动监听、避免反复读取布局尺寸，保证页面打开后滚动不能变卡。

本版本不增加会话数据量，不扩大默认渲染范围，不改变懒加载策略，因此不应明显增加打开耗时和内存占用。页面打开速度目标仍保持在 5 秒以内，打开后滚动流畅性不能下降。

## 8. 不采用的方案

不采用全局方向键监听。

原因是全局监听虽然可以让任何位置按上下键都切换提问，但边界风险较高，可能影响输入框、标题列表、目录列表、页面默认滚动和浏览器辅助功能。

本版本采用更稳妥的方式：只在用户明确进入会话阅读状态后，把焦点交给会话区，由现有会话区方向键逻辑处理上下切换。

不采用假百分比刷新进度。

原因是当前后端不提供真实进度，假百分比会造成误导。使用无限滚动进度条更诚实，也更轻量。

## 9. 验收标准

点击标题区单分支标题后，该标题行出现当前选中提示。

点击标题区多分支标题后，当前标题组和当前分支行能明确显示选中关系。

标题区选中提示在切换标题、切换目录、重新渲染列表后仍然准确。

点击标题区某个标题后，会话区自动定位到最后一个用户提问。

点击标题区某个标题后，不需要再点击会话区，直接按 `ArrowUp` / `ArrowDown` 可以切换提问。

点击会话区回到顶部后，会话区自动选中第一个用户提问。

点击会话区回到顶部后，不需要再点击会话区，直接按 `ArrowUp` / `ArrowDown` 可以切换提问。

目录区、标题区、会话区的回到顶部按钮视觉样式一致，都是圆形按钮内显示向上箭头。

点击 `刷新` 后，刷新按钮进入 loading 状态，并显示刷新进度反馈。

刷新期间不能重复触发刷新。

刷新成功后，loading 状态清除，并正常显示刷新结果。

刷新失败后，loading 状态清除，并显示失败提示。

页面打开速度不应明显变慢，目标仍控制在 5 秒以内。

页面打开后滚动不能变卡。

方向键切换提问不能影响输入框、筛选框、搜索框等可输入控件的正常操作。

## 10. 验收流程补充

最终验收必须使用浏览器工具打开页面实际查看效果，不只靠代码阅读或命令输出。

浏览器验收至少需要覆盖：

```text
标题区选中提示
点击标题后直接使用上下键切换提问
会话区回到顶部后直接使用上下键切换提问
三个区回到顶部按钮样式一致
刷新按钮 loading 状态和进度反馈
刷新成功后的状态恢复
刷新失败后的状态恢复
```

浏览器验收完成后，所有为验收临时打开的本地服务端口都必须关闭。

如果后续还需要查看，保留的做法应由用户自己重新打开，不默认常驻占用端口。
