## 1. V0.34 修改目标

V0.34 聚焦两项小范围改动：

1. **第二层“标题”区域新增批量展开 / 收起按钮**
   - 在第二层标题区顶部，“排序”按钮左侧新增一个箭头按钮。
   - 箭头视觉样式与当前母标题右下角的展开 / 收起箭头保持一致。
   - 点击一次，可批量收起当前标题区内所有当前可见的多分支母标题。
   - 当当前可见的多分支母标题已经全部收起时，再点击一次，则全部展开。
   - 只影响当前标题区实际显示出来的多分支母标题。
   - 被筛选 / 搜索隐藏的母标题不改变折叠状态。
   - 如果当前没有任何多分支母标题，则按钮仍保留位置但处于禁用状态。

2. **完善 `.gitignore`**
   - 在现有规则基础上新增：
     ```gitignore
     __pycache__/
     *.pyc
     ```
   - 防止 Python 缓存目录和编译缓存文件进入 Git 未跟踪 / 提交范围。

## 4. V0.33 当前第二层标题区结构

当前第二层标题区域为：

```html
<section class="pane" id="sessionPane">
```

顶部大致结构：

```text
标题      收起                           排序
```

目标布局：


这里新增的是：

**母标题批量展开 / 收起按钮**

不是：

**第二层标题栏整体收起按钮**

## 5. 两类“收起”功能的区别

V0.34 完成后，第二层标题区将同时存在两种完全不同的收起行为。

### 5.1 原有“收起”

当前位置：

```text
标题  [收起]
```

作用：

**把整个第二层标题 Pane 收起来。**

对应现有：

```text
collapseTitlesButton
```

V0.34 不改变此功能。

### 5.2 新增“箭头”

位置：

```text
                               [⌄]  排序
```

作用：

**批量收起 / 展开标题区内的多分支母标题。**

标题 Pane 本身仍然保持显示。

因此：

```text
“收起”按钮 = 收起整个标题栏
“箭头”按钮 = 收起标题栏里面的多分支母标题
```

必须避免用户混淆。

## 8. 样式复用策略

当前母标题箭头类：

```css
.title-group-toggle
```

同时包含：

- 视觉样式；
- 母标题卡片内部专用的绝对定位。

例如：

```css
position: absolute;
right: 8px;
bottom: 8px;
```

因此不建议直接把 `.title-group-toggle` 原样复用到标题栏顶部。

否则新按钮会错误绝对定位。

### 推荐方案

把共同视觉抽出为公共 class，例如：

```css
.title-toggle-button
```

负责：

- width
- height
- border
- border-radius
- background
- color
- font-size
- cursor
- transition
- hover
- focus-visible

然后：

```css
.title-group-toggle
```

只保留母标题内部定位：

```css
position: absolute;
right: 8px;
bottom: 8px;
```

新按钮可使用：

```css
.title-groups-toggle-all
```

只负责标题栏 header 中的布局。

这样实现：

**视觉相同，定位独立。**

## 9. 批量按钮控制范围

用户已确认：

**只控制当前标题区中当前实际显示出来的多分支母标题。**

这里的“当前实际显示”指：

- 当前选中的工作目录；
- 当前来源；
- 当前搜索条件；
- 当前标题筛选条件；
- 最终已经通过 `renderSessionList()` 渲染出来的标题组。

### 9.1 会被控制

满足：

```javascript
group.sessions.length > 1
```

并且：

- 当前实际渲染；
- 当前没有被筛选掉；

的母标题。

### 9.2 不会被控制

以下标题不改变：

- 单会话标题；
- 当前工作目录以外的标题；
- 当前来源以外的标题；
- 被搜索条件过滤掉的标题；
- 被标题筛选条件隐藏的标题；
- 当前未渲染的其他 workspace 标题。

---

## 10. 为什么只控制当前可见标题

这样设计可以避免：

用户只是想整理当前看到的标题列表，却无意中改变了：

- 当前筛选结果之外的标题；
- 其他项目；
- 其他工作目录；
- 其他来源；

的折叠状态。

因此批量按钮是：

**当前视图操作**

而不是：

**全数据库操作。**

---

## 11. 批量按钮的核心状态判断

用户已确认以下逻辑：

### 情况 A：当前可见母标题中至少一个处于展开状态

例如：

```text
A 展开
B 收起
C 展开
```

按钮点击后：

```text
A 收起
B 收起
C 收起
```

即：

**全部收起。**

### 情况 B：当前可见母标题已经全部收起

例如：

```text
A 收起
B 收起
C 收起
```

按钮点击后：

```text
A 展开
B 展开
C 展开
```

即：

**全部展开。**

---

## 12. 不采用“逐项反转”

V0.34 明确不采用：

```text
A 展开 → 收起
B 收起 → 展开
C 展开 → 收起
```

这种逐组反转方式。

原因：

- 这不是真正意义上的“全部收起 / 全部展开”。
- 混合状态点击后仍然是混合状态。
- 用户无法快速把界面整理到统一状态。

因此必须使用：

```text
存在任意展开 → 全部收起
全部已收起 → 全部展开
```

**点击后展开全部母标题。**

```text

aria-expanded="false"
```

## 18. 批量收起后的持久化

例如当前可见：

```text
A
B
C
```

用户点击“全部收起”。

则现有 localStorage 状态中：

- A = collapsed
- B = collapsed
- C = collapsed

刷新网页后：

- A 仍收起
- B 仍收起
- C 仍收起

这是对 V0.33 单项记忆机制的自然复用。

## 19. 批量展开后的持久化

V0.33 当前：

```javascript
setTitleGroupCollapsed(..., false)
```

会删除对应 key。

V0.34 批量展开时继续复用该行为：

- 不额外保存 `false`
- 删除当前可见各母标题的 collapsed key

这样保持：

**默认展开**

的现有模型。

## 21. 切换工作目录

按钮始终只针对：

**当前第二层标题区。**

因此：

1. 工作目录 X 有 A/B/C。
2. 点击全部收起。
3. 切换到工作目录 Y。
4. Y 根据自己已有折叠状态显示。
5. 顶部箭头重新根据 Y 当前可见多分支标题计算状态。

不得把 X 的“全部收起”当成全局模式带到 Y。

## 22. 切换来源

同理：

- 本机 Codex
- 本机 Claude
- 云端来源

之间切换时，按钮状态重新根据当前来源当前标题区计算。

不得保存：

```text
“上一来源的顶部按钮方向”
```

顶部按钮永远是：

**从当前实际 DOM / 当前组状态推导出来。**

## 23. 新增统一的状态同步函数

建议增加：

```javascript
syncTitleGroupsToggleAllButton()
```

职责：

1. 找出当前标题区可见的所有多分支母标题。
2. 判断数量。
3. 如果数量为 0：
   - disabled。
4. 如果全部 collapsed：
   - 设置“展开全部”状态。
5. 如果存在任意展开：
   - 设置“收起全部”状态。
6. 更新：
   - class
   - `aria-expanded`
   - `aria-label`
   - `title`

---

## 24. 新增批量操作函数

建议增加：

```javascript
toggleAllVisibleTitleGroups()
```

执行步骤：

1. 获取当前可见多分支母标题集合。
2. 如果集合为空直接返回。
3. 判断是否全部已收起。
4. 计算目标状态：
   - 全收起 → 展开全部
   - 否则 → 收起全部
5. 批量更新各 group DOM。
6. 批量写入现有 localStorage。
7. 完成后统一：
   - 同步顶部按钮状态
   - 刷新 pinned notes

---

## 25. 不建议循环调用完整单组函数

V0.33 单组函数：

```javascript
toggleTitleGroup(...)
```

每次执行都会：

- 改一个组状态；
- 写 localStorage；
- 调度 pinned notes 刷新。

如果 V0.34 直接循环调用 30 次：

```javascript
toggleTitleGroup(...)
toggleTitleGroup(...)
toggleTitleGroup(...)
...
```

可能造成：

- 反复读写 localStorage；
- 反复 schedule pinned notes；
- 多余 DOM 状态同步。

因此推荐：

**批量函数直接一次计算目标状态，然后统一批量处理。**

---

## 26. localStorage 批量写策略

V0.33 当前单组函数每次读取：

```javascript
readTitleGroupCollapseState()
```

并写回。

V0.34 批量操作建议：

1. 一次读取整个 state。
2. 遍历当前可见 group。
3. 更新所有目标 key。
4. 一次 `localStorage.setItem()`。

这样：

- 更快。
- 减少磁盘 / 浏览器存储调用。
- 不存在中间状态。

---

## 27. 与 V0.33 常驻备注模式的关系

V0.33 已支持：

- hover 备注
- pinned 常驻备注
- 多个 pinned note 同时显示
- 子会话收起后备注同步隐藏

V0.34 批量折叠必须继续遵守该行为。

## 28. 全部收起时的备注

假设：

- 母标题 A 有备注。
- A1 子会话有备注。
- A2 子会话有备注。
- 当前 pinned 模式开启。

点击“全部收起”后：

- A 母标题仍可见。
- A 的 pinned note 保留。
- A1 隐藏。
- A1 pinned note 隐藏。
- A2 隐藏。
- A2 pinned note 隐藏。

其他母标题同理。

---

## 29. 全部展开时的备注

点击“全部展开”后：

- 子会话重新显示。
- 当前可见、有备注的子会话 pinned note 重新显示。
- 位置重新计算。

---

## 30. pinned notes 刷新次数

批量操作时：

**只在所有母标题状态修改完成后刷新一次 pinned notes。**

推荐：

```javascript
schedulePinnedNotesRefresh()
```

只调用一次。

不要每个母标题都调用一次。

这是主要性能保护点。

---

## 31. 与当前选中会话的关系

批量收起 / 展开不得改变：

```text
selectedWorkspaceId
selectedSessionKey
CURRENT_DETAIL
```

例如：

1. 当前正在看 A2。
2. 点击顶部“全部收起”。
3. A 的子会话列表消失。
4. 主阅读区仍显示 A2。
5. A 母标题仍 active。
6. 再“全部展开”。
7. A2 子标题重新出现并保持 active。

这与 V0.33 单个母标题行为保持一致。

---

## 32. 与“排序”按钮的关系

新增按钮只是放在排序左侧。

不得：

- 改变排序菜单打开方式。
- 改变排序字段。
- 改变排序方向。
- 改变排序 localStorage。
- 让箭头按钮点击冒泡到 `details`。

两者必须完全独立。

## 33. 与标题筛选输入框的关系

当前：

```text
筛选标题、摘要、路径...
```

输入后会重新：

```javascript
renderSessionList()
```

因此 V0.34 在每次重新渲染后都要调用：

```javascript
syncTitleGroupsToggleAllButton()
```

保证：

- 按钮 disabled 状态正确。
- 箭头方向正确。
- tooltip 正确。

## 34. 与单个母标题点击的联动

如果用户：

1. 点击顶部全部收起。
2. 然后手动展开其中一个母标题。

此时顶部按钮状态应该立即变成：

**“收起全部”**

因为当前已不再是“全部收起”。

反过来：

1. 当前多个母标题展开。
2. 用户逐个手动收起。
3. 最后一个也收起。

此时顶部按钮应立即切换到：

**“展开全部”**

因此 V0.33 的单组 toggle 完成后，也应调用：

```javascript
syncTitleGroupsToggleAllButton()
```

## 35. DOM 标识建议

建议新增：

## 39. `__pycache__/` 的作用

Python 执行 / 测试时可能产生：

```text
__pycache__/
```

例如：

```text
webdav_sync/__pycache__/
tests/__pycache__/
```

加入：

```gitignore
__pycache__/
```

后，Git 会忽略各层级下匹配的 Python 缓存目录。

---

## 40. `*.pyc` 的作用

Python 可能生成：

```text
module.cpython-xxx.pyc
```

加入：

```gitignore
*.pyc
```

后，所有 Python bytecode 文件不进入 Git 未跟踪列表。

---

## 41. `.gitignore` 不会做什么

加入规则后不会：

- 删除电脑上的 `__pycache__`。
- 删除电脑上的 `.pyc`。
- 删除 Git 已经追踪的文件。
- 忽略任何 `.py` 源文件。
- 影响程序运行。
- 影响 Python import。

它只影响：

**Git 是否将这些未跟踪缓存文件视为可加入版本控制的文件。**

## 59. 副作用与风险

### 59.1 “当前可见”的批量行为可能与用户直觉不同

用户在筛选状态下点击“全部收起”，只会影响当前可见结果。

清除筛选后，未参与批量操作的母标题仍保留原状态。

这是已确认设计，不是 BUG。

---

### 59.2 顶部按钮状态是动态推导，不是独立模式

顶部箭头本身不存储：

```text
allCollapsed=true
```

而是根据当前实际母标题状态计算。

优点：

- 不会和单项折叠状态打架。
- 不需要维护第二套状态。

副作用：

- 用户手动展开一个组后，顶部按钮状态会立即改变。

这是预期行为。

---

### 59.3 标题栏会增加一个小按钮

“排序”左侧多一个约 26px 按钮。

在特别窄的窗口中可能：

- 增加 header actions 横向占用。
- 需要轻微调整 gap。

但不应影响正常桌面布局。

---

### 59.4 批量操作会改变多个 localStorage key

点击一次可能同时修改多个母标题状态。

这是功能本身必需行为。

通过一次批量读写可降低开销。

---

### 59.5 常驻备注模式需要重新定位

V0.34 批量隐藏 / 展开大量子会话时：

- pinned note DOM 可见性会发生较大变化。

如果实现不当，可能出现：

- 备注浮层残留；
- 坐标错位；
- 瞬间反复刷新。

因此要求：

**批量操作完成后统一刷新一次 pinned notes。**

---

### 59.6 `.gitignore` 只影响未跟踪文件

如果未来某个 Python 缓存已经被 Git 提交，新增规则不会自动解除跟踪。

当前未发现该情况，因此 V0.34 暂不额外清理。
