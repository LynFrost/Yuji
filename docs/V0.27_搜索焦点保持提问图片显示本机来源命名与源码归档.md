状态：待确认，未实施

## 1. 修改目标

V0.27 基于当前 V0.26，完成以下四项修改：

```text
1. 搜索时不再自动选中结果中的第一条提问，保持搜索前的提问锚点；只有用户点击搜索结果中的提问后，才改变选中提问。
2. 用户提问带有目标图片时，在对应提问正文下方显示图片缩略图，并支持点击查看大图。
3. 本机 Codex 和本机 Claude 的来源显示名称都增加当前电脑名，例如 XF-本机 Codex、XF-本机 Claude。
4. 实施前新建 软件/CodexChatIndex_V0.26，按源码白名单归档当前 V0.26；原 软件/CodexChatIndex 保持原位并就地升为 V0.27。
```

本版本不改变来源内部 ID，不改变来源数据隔离目录，不递归扫描磁盘寻找图片，不把本地图片批量转成 base64 写入索引，也不重写现有搜索或图片预览系统。

本文档落成后不执行目录复制、源码修改、升版、构建或测试，必须等待用户确认后再实施。

## 4. 搜索时保持原提问焦点

### 4.1 目标行为

进入搜索前假设当前选中提问为 Q5：

```text
输入搜索词后，selectedQuestionKey 仍保持 Q5，不自动改成搜索结果第一条。
如果 Q5 本身在搜索结果中，继续显示 Q5 的选中状态。
如果 Q5 不在搜索结果中，结果列表中不自动显示任何选中提问。
搜索框的 DOM 输入焦点仍留在搜索框，输入过程中不抢焦点。
用户点击某条搜索结果提问 Q2 后，才把 selectedQuestionKey 改为 Q2，并把会话区焦点交给 transcript。
从此可用上下键在当前搜索结果的可见提问集合中，从 Q2 向上或向下切换。
清空搜索后，恢复到最后一次由用户主动选择的提问锚点。
```

“保持焦点”在本节中包含两个不同概念：

```text
阅读锚点：selectedQuestionKey，搜索时必须保持，不得自动改写。
键盘输入焦点：document.activeElement，用户在搜索框输入时必须继续留在搜索框。
```

### 4.2 推荐实现

在 `renderViewer()` 的搜索分支中删除以下行为：

```text
当 selectedQuestionKey 不在 visibleQuestionKeys 中时，自动设置为 visibleQuestionKeys[0]。
把系统自动选择标记为 selectedQuestionKeyIsTemporary。
```

改为：

```text
搜索渲染只计算当前可见提问，不改写 selectedQuestionKey。
highlightCurrentQuestion() 只在 selectedQuestionKey 对应元素确实可见时显示选中样式。
搜索结果没有当前锚点时，不创建“临时选中项”。
用户点击提问框时，沿用 transcript click 事件调用 setSelectedQuestionKey(..., { scroll: false })。
用户点击提问框内的复制按钮、图片按钮或其他交互控件时，不改变选中提问。
```

键盘上下切换规则：

```text
无搜索词时，沿用全部用户提问作为导航集合。
有搜索词时，沿用 DOM 中当前可见提问作为导航集合。
当前 selectedQuestionKey 不在可见集合时，ArrowUp / ArrowDown 不自动从第一条或最后一条起跳，也不改写锚点。
用户必须先点击当前搜索结果中的某个提问，随后上下键才在结果集合中导航。
当前 selectedQuestionKey 已在可见集合时，上下键可直接继续导航。
```

建议让 `jumpQuestion()` 在“当前锚点不属于当前可见搜索结果”时直接返回，不显示反复 toast，避免连续按键产生干扰。

### 4.3 与搜索上下文提问的关系

V0.26 已实现：回答命中时，搜索结果会同时显示对应提问，并标记为“上下文提问”。V0.27 保留该行为。

```text
上下文提问可以由用户点击并成为 selectedQuestionKey。
系统不得因为它位于搜索结果第一条而自动选中。
用户点击后，上下键导航以当前结果中可见提问为范围。
搜索本身不覆盖搜索前锚点；只有用户主动点击才更新进度锚点。
```

## 5. 在提问框下显示目标图片

### 5.1 显示规则

图片显示在所属用户提问的正文下方、提问框内部：

```text
一张图片显示一个缩略图。
多张图片按原始顺序排列，可自动换行。
缩略图不改变提问框正文宽度。
缩略图使用 loading="lazy"，视口外图片不提前解码。
点击缩略图打开现有页内图片预览模态框。
关闭按钮、Esc 和点击模态背景均可关闭预览。
关闭时清空预览 img.src，并把焦点还给原缩略图按钮。
点击图片按钮只打开图片，不改变当前选中提问。
```

继续复用现有：

```text
renderEventImages(event)
openImagePreviewFromButton(button)
openImagePreview(src, alt)
closeImagePreview()
imagePreviewModal
```

不再建设第二套图片查看器。

### 5.2 支持的图片来源及优先级

图片来源按以下顺序解析并去重：

```text
1. JSONL 中用户消息的结构化图片附件。
2. 用户提问正文中的 Markdown 图片：![说明](路径或 URL)。
3. 用户提问正文中明确写出的绝对图片路径或相对图片路径。
4. 只有文件名时，仅尝试 session.cwd 根目录下的同名文件，不递归搜索子目录。
```

Codex 结构化图片至少支持：

```text
content[].type = input_image
image_url / url / data / source
data:image/...;base64,...
明确记录的本地图片路径
```

Claude 结构化图片至少支持用户内容块：

```text
content[].type = image
source.type = base64 时，根据 media_type 和 data 生成单个 data URL。
source.type = url 时读取明确 URL。
来源记录为明确本地路径时，交给本地图片读取接口。
```

限制：

```text
只处理用户提问关联的图片，不把工具输出里的所有图片自动塞进提问框。
支持 png、jpg、jpeg、gif、webp、avif；V0.27 不支持 SVG，避免主动内容和安全边界复杂化。
同一张图片同时出现在结构化附件和正文路径中时，只显示一次。
路径不存在、格式不支持或无法读取时，保留原问题文字，不显示破图占位。
普通文本中只出现“png”等字样不算图片引用。
```

### 5.3 路径解析边界

为了杜绝误判和刷新变慢，不允许按文件名递归搜索整个工作目录或磁盘。

```text
绝对路径：只检查该精确路径。
相对路径：只相对 session.cwd 解析并检查该精确路径。
纯文件名：只检查 Join-Path session.cwd 文件名。
Markdown 路径：按绝对路径或相对路径规则处理。
找不到时立即结束，不继续扫描父目录、兄弟目录、用户目录或所有磁盘。
```

解析时先规范化路径，再检查文件是否存在、是否为普通文件、扩展名是否在允许列表中。图片记录建议保留稳定的 `imageId`、类型和必要元信息，不依赖前端自行猜测 Windows 路径。

### 5.4 本地图片读取方式

不建议把本地图片全部转成 base64 写进会话详情 JSON，原因是会显著增加：

```text
刷新写盘时间。
详情 JSON 体积。
浏览器解析时间。
字符串内存占用。
同一图片在缩略图和预览之间的重复数据。
```

推荐增加受限的本地图片读取接口：

```text
前端使用 sourceId + sessionKey/path + event/image 标识请求图片，不在 URL 查询参数里直接传任意文件路径。
服务端只允许读取已经被当前会话详情记录为图片的文件。
服务端重新规范化并核对记录路径，拒绝任意路径穿越。
只返回允许的图片 MIME 类型，设置 nosniff。
文件不存在、超出限制或类型不符时返回明确的 404/415，不回传其他文件内容。
```

单张本地图片读取上限固定为 30 MiB。服务端采用流式响应，不先把整张图片读入 Python 内存。超过上限时不在页面加载，并显示简短的“图片过大，无法预览”状态；原问题文字和其他图片仍正常显示。

`data:image/...` 继续直接使用现有 `event.images[].src`，不复制为第二份字符串。结构化附件中的明确 `http/https` URL 继续由浏览器按 `loading="lazy"` 直接加载；服务端不下载、不缓存，刷新阶段也不等待远程图片。加载失败时显示简短的“图片无法加载”状态，不反复重试。

### 5.5 图片与复制、导出的关系

```text
复制全文继续复制提问原始文字，不把 base64 图片内容写进剪贴板。
导出 MD 保留原问题文字和原有图片引用；结构化附件没有原始 Markdown 路径时，可输出简短的“[图片附件 N]”说明，不内嵌超长 base64。
图片是否成功加载不影响提问定位、上下键、搜索、复制全文或导出 MD。
图片按钮必须继续被 transcript 的交互控件边界拦截，不能因点击图片而选中提问。
```

## 6. 本机 Codex 与本机 Claude 增加电脑名前缀

### 6.1 最终显示格式

当前电脑名为 `XF`，因此来源下拉应显示：

```text
XF-本机 Codex
XF-本机 Claude
```

统一格式：

```text
<电脑名>-本机 Codex
<电脑名>-本机 Claude
```

电脑名动态读取，不在源码中硬编码 `XF`。在其他电脑运行时自动显示该电脑的实际名称。

### 6.2 内部身份保持不变

只改变显示标签 `label`，以下内部值保持不变：

```text
Codex sourceId = local-codex
Codex sourceType = local-codex
Claude sourceId = local-claude
Claude sourceType = local-claude
运行数据目录 CodexChatIndex.sources/local-codex
运行数据目录 CodexChatIndex.sources/local-claude
备注、搜索索引、缓存、进度锚点中的 sourceId
```

外部来源名称保持用户设置的名称，不自动添加本机名。

### 6.3 动态名称的生成与一致性

建议定义同一条命名规则，在 PowerShell 构建端和 Python 服务端分别实现：

```text
PowerShell 优先使用 [Environment]::MachineName。
Python 优先使用 COMPUTERNAME，缺失时回退 socket.gethostname()。
读取后 Trim；如果仍为空，则回退为“本机 Codex”或“本机 Claude”。
格式固定使用半角连字符“-”，不在连字符两侧加空格。
```

需要同步覆盖：

```text
Build-CodexChatIndex.ps1 中内置来源默认清单。
Build-CodexChatIndex.ps1 中 SourceLabel 为空时的默认值。
CodexChatIndexServer.py 中 local_source() 和 local_claude_source()。
服务端对已有内置来源清单的规范化逻辑。
HTML 模板中的内置来源兜底显示。
tests/Build-CodexChatIndex.Tests.ps1 中对应断言和夹具。
```

已有来源清单可能已经持久化旧标签，因此不能只改“首次创建来源”的默认值。服务端加载或规范化来源清单时，应对 `local-codex` 和 `local-claude` 的显示标签重新按当前电脑名生成；不得覆盖外部来源的自定义标签。

前端最终以来源 API 或当前索引中的 `source.label` 为唯一权威。浏览器本身不猜测电脑名，也不持久化某台电脑的前缀；模板在来源数据到达后立即用权威标签重建选项。无数据或接口失败时使用不带电脑名的通用兜底文字“本机 Codex”“本机 Claude”，不得显示从其他电脑构建时遗留的旧电脑名前缀。

### 6.4 长名称布局

电脑名前缀会增加来源下拉选项长度。来源控件应允许合理扩宽或在极长电脑名时省略显示，但完整内容必须通过原生 `title` 或选择项文本可获得。

V0.27 不因此挤压刷新、全量、收起等按钮；窄屏时优先让顶栏换行，不让控件文字重叠。

## 10. 副作用与规避

### 10.1 搜索结果可能暂时没有选中高亮

副作用：

```text
搜索前的当前提问不命中时，结果中没有任何提问显示为选中。
```

规避与结论：

```text
这是“不得自动更改焦点”的必要结果。
用户点击任意结果提问后立即获得明确选中状态和上下键导航起点。
不使用自动选中第一条来制造表面上的焦点。
```

### 10.2 未点击结果前上下键可能无动作

副作用：

```text
当前锚点不在搜索结果中时，上下键没有可确认的起点。
```

规避：

```text
按键直接返回，不跳到错误位置。
用户点击目标提问后再进行上下导航，符合本次明确需求。
```

### 10.3 图片增加网络、解码和内存成本

副作用：

```text
会话含大量图片时，缩略图解码会增加浏览器内存和绘制成本。
data URL 本身仍会占用会话详情内存。
远程图片可能加载失败或产生外部网络请求。
```

规避：

```text
继续使用 loading="lazy"。
本地图片按需读取，不批量转 base64。
模态框只持有当前一张图，关闭时清空 img.src。
图片去重，不为缩略图和大图各复制一份 base64。
不由刷新流程下载远程图片。
单张本地图片设置大小上限。
```

### 10.4 图片路径误判或找图过慢

副作用：

```text
正文中的图片文件名可能不存在，或同名文件可能位于其他目录。
递归找图会拖慢刷新并产生错误匹配。
```

规避：

```text
只解析明确附件、明确路径和 cwd 根目录下的精确文件名。
不递归、不模糊匹配、不扫描整个磁盘。
找不到即跳过，杜绝为了“尽量找到”而牺牲刷新性能和准确性。
```

### 10.5 本地图片接口扩大文件读取边界

副作用：

```text
如果接口直接接受任意路径，可能被用于读取非图片本地文件。
```

规避：

```text
接口不接受任意裸路径作为读取依据。
只读取当前会话详情已经登记的图片引用。
服务端再次校验规范化路径、扩展名、MIME、文件存在性和大小。
拒绝路径穿越与未登记文件。
服务只绑定本机地址，保持现有本地使用边界。
```

### 10.6 来源名称变长

副作用：

```text
电脑名较长时，来源下拉会占用更多顶栏宽度。
```

规避：

```text
允许来源控件合理扩宽或极长名称视觉省略。
窄屏优先换行，不挤压相邻按钮，不产生重叠。
完整名称保持可查看。
```

### 10.7 内置来源旧标签迁移

副作用：

```text
刷新来源清单后，用户会看到“本机 Codex”变成“XF-本机 Codex”等新标签。
如果错误地把 label 当作数据身份，可能造成重复来源。
```

规避：

```text
所有数据关联继续只使用 sourceId。
只更新内置来源显示标签，不新建新的 sourceId。
外部来源标签不迁移。
```

### 10.8 归档副本造成入口混淆和磁盘占用

副作用：

```text
CodexChatIndex_V0.26 与 CodexChatIndex 同时存在，可能误开旧版。
归档会复制一份源码和小型测试夹具。
```

规避：

```text
唯一当前入口保持 软件/CodexChatIndex/Open-CodexChatIndex.cmd。
归档只按白名单复制，不包含运行数据，因此体积可控。
归档目录只作回滚，不在其中继续开发。
```
