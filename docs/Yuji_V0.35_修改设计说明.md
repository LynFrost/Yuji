## 1. 修改目标

V0.35 包含三个相互关联的改动主题：

1. 将搜索工具栏中的「全部 / 当前」合并为一个可点击切换的按钮。
2. 将阅读区显示模式中的「全部 / 提问」也合并为一个可点击切换的按钮。
3. 为 Codex 与 Claude 会话建立可验证的继承关系，清晰展示分支父子关系和多级继承链；同时修复子会话内容被错误截断的问题。

本版本的核心原则：

- 继承关系由真实的会话关联元数据确定，不根据标题相同、时间接近或文本相似度猜测。
- 继承树只用于说明会话之间的来源关系，不意味着子会话阅读区要重复显示父会话历史。
- 每个会话的阅读区必须完整显示该会话自身实际记录的内容。
- 分叉位置无法可靠确定时，不得因此裁剪子会话内容。
- Codex 与 Claude 遵循一致的产品行为，但各自解析适配必须尊重真实的数据格式。
- 所有开发工作必须在 feature/v0.35 分支进行。

## 2. 代码基线与当前实现

已只读检查 feature/v0.35 分支的下列文件：

- Build-CodexChatIndex.ps1
- templates/CodexChatIndex.template.html
- tests/Build-CodexChatIndex.Tests.ps1
- VERSION_V0.34.txt

当前版本标记为 V0.34。当前界面中，搜索范围使用 data-search-scope 区分 all 与 current；阅读区显示模式使用 data-view-mode 区分 all 与 questions。两组目前均为两个按钮。

现有 HTML 使用 groupSessionsByTitle() 按标题分组，并使用 hasMultipleSessionBranches() 判断同标题会话数量。该方式可以呈现同标题下的多个会话，但仅凭同标题归组不能表达真实的继承关系。

现有 Codex 解析器已对 session_meta 等记录进行处理，测试中也包含分支头会话与后续祖先 session_meta 记录的场景。V0.35 必须在扩展父子关系解析时保留现有的会话 ID 选择、时间、事件解析、图片、备注和缓存行为。

当前 Claude 解析路径包含 Claude JSONL、会话元数据以及 VS Code Claude Code Chat 等来源适配。不同来源结构存在差异，不能假定所有 Claude 数据都拥有相同的父会话字段。

以上是设计基线，不代表已经完成 V0.35 修改。

## 3. 改动一：搜索范围按钮合并

### 3.1 当前行为

搜索范围区域当前有两个按钮：

- 全部：搜索当前来源下的全部会话。
- 当前：只搜索当前打开的会话。

当前由 data-search-scope 属性区分搜索范围。

### 3.2 目标行为

将上述两个按钮合并为一个原生按钮。

- 按钮文本显示当前生效的搜索范围。
- 当前为「全部」时，点击后切换到「当前」。
- 当前为「当前」时，点击后切换到「全部」。
- 切换后立即按新范围执行既有搜索逻辑。
- 不新增下拉菜单，不增加额外确认步骤。
- 搜索范围状态应与现有搜索状态保持一致，不允许出现按钮显示值与实际搜索范围不一致的情况。

### 3.3 可访问性和提示

按钮应保留原生 button 行为，支持鼠标、键盘 Enter 和 Space 操作。

按钮的 title、aria-label 等提示应说明当前状态或点击后的切换目的。由于另一组按钮也可能显示「全部」，必须通过所在工具栏区域、图标或提示文字清晰区分「搜索范围」和「阅读区显示模式」。

### 3.4 明确不修改的内容

- 不改变全部搜索的范围定义。
- 不改变当前会话的判定方式。
- 不改变搜索关键词、搜索历史、搜索字段、结果排序或匹配算法。
- 不改变 data-search-scope 对应的业务语义，只将两个选项改为一个切换入口。
- 不修改 data-search-field="questions" 对应的搜索字段控制；它与阅读区显示模式不是同一项功能。

## 4. 改动二：阅读区显示模式按钮合并

### 4.1 当前行为

阅读区显示模式当前有两个按钮：

- 全部：显示当前会话的全部消息。
- 提问：仅显示当前会话中的用户提问。

当前由 data-view-mode 属性区分 all 与 questions。

### 4.2 目标行为

将上述两个按钮合并为一个原生切换按钮。

- 按钮文本显示当前生效的显示模式。
- 当前为「全部」时，点击后切换到「提问」。
- 当前为「提问」时，点击后切换到「全部」。
- 切换后立即按新模式重新呈现当前会话。
- 两种模式的现有筛选语义、提问导航和选中提问行为保持不变。
- 不增加下拉菜单，不新增第三种模式。

### 4.3 与搜索范围按钮的关系

两个按钮分别管理独立状态：

1. 搜索范围：全部 / 当前。
2. 阅读区显示模式：全部 / 提问。

不能因为两个按钮出现相同文本「全部」就共用状态，也不能让切换其中一组意外改变另一组。

### 4.4 明确不修改的内容

- 不改变当前会话的消息数据。
- 不改变消息解析、Markdown 渲染、图片显示、工具调用显示或提问导航。
- 不改变搜索字段选择按钮。
- 不改变其他会话工具按钮。
- 不将「提问模式」改成搜索字段模式；二者继续保持现有独立语义。

## 5. 改动三：真实会话继承关系

### 5.1 目标

在会话列表中清晰显示真实的父会话、子会话和多级继承关系，让用户可以直观看出分支继承链，而不只是看到同标题会话的数量。

示意：

~~~
会话 A（根会话）
├─ 会话 B（继承自 A）
│  └─ 会话 C（继承自 B）
└─ 会话 D（继承自 A）
~~~

该示意仅用于说明关系。实际父子关系必须以源数据中可验证的会话关联信息为准。

### 5.2 关系数据要求

会话索引需要保存可供界面使用的关系信息。字段命名可以根据现有数据结构决定，但至少应能表达：

- 当前会话的稳定身份。
- 当前会话明确的父会话身份（若源数据提供）。
- 父会话是否已在当前来源数据中找到。
- 关系状态：已确认、父会话缺失或关系未知。
- 可选的根会话或层级信息；若可由父子关系安全推导，则不必重复持久化。

会话身份不能只使用标题。应采用来源范围内稳定的会话 ID，并在必要时组合 sourceId 等信息，避免 Codex、Claude 或不同来源中的 ID 发生冲突。

父子关系的解析和查找应在同一来源的数据范围内进行。不能把另一个来源中恰好拥有相同 ID 的会话误认作父会话。

### 5.3 Codex 关系解析

优先使用 Codex rollout/session_meta 中明确记录的父会话或 fork 关系字段，例如适用记录中的 forked_from_id，以及与关系确认有关的元数据。

实施时必须：

- 保留当前会话自身的正确 ID，不得把祖先 session_meta 中的 ID 错认成当前会话 ID。
- 处理同一 JSONL 文件中出现多个 session_meta 记录的情况。
- 不因解析父会话失败而跳过当前子会话。
- 不以标题相同作为父子关系证据。
- 不以时间先后或消息文本相似度代替明确的父子关联字段。
- 对缺失字段、非法 ID、自引用和循环关系进行防御性处理。

如果源数据明确给出了父会话 ID，但父会话文件不在当前索引中，仍保留该关系信息，并将节点标为「父会话未找到」或等效状态。

### 5.4 Claude 关系解析

Claude 会话使用与 Codex 一致的产品规则：有明确关系时显示父子树；无法确认时不虚构关系；子会话自身内容必须完整显示。

但解析实现必须按各类 Claude 数据源的真实格式分别适配：

- 检查当前支持的 Claude JSONL、会话元数据和 VS Code Claude Code Chat 等数据结构。
- 优先使用明确表示会话之间继承关系的原生字段。
- 只有当字段的实际语义经代码和真实/测试样例确认确实指向父会话时，才允许用它建立会话级父子关系。
- 不得直接把消息级 parentUuid 等字段当作父会话 ID，除非相应来源格式明确证明该字段的语义是会话级关联。
- 不同 Claude 来源之间不得仅凭相同标题、相近时间或相似内容自动连成继承链。

如果某一种 Claude 来源没有可验证的会话级关系信息，则该来源的会话仍正常显示，但关系状态应为「关系未知」或等效状态。不能为了外观统一而制造错误的继承关系。

### 5.5 树形展示规则

- 父会话与子会话使用缩进、连接线、分支箭头或等效视觉元素体现层级。
- 同一父会话的多个子会话应显示为同级分支。
- 多级继承必须体现真实层级，不能只显示「分支 N」。
- 每个会话节点应保留标题、现有会话摘要/统计和点击打开会话的能力。
- 单击节点打开该节点对应的会话，不应误打开父会话或根会话。
- 根会话正常显示；存在已确认父节点的会话不应仅因为标题不同就被当成互不相关的会话。
- 父会话缺失时，保留子节点并显示关系缺失状态。
- 关系未知的会话不能被静默挂到错误的父节点下。
- 检测并阻止循环关系导致无限递归或页面卡死。
- 对没有可验证继承关系的普通会话，保留现有的标题分组/列表展示能力，避免把所有普通会话错误地串成一棵树。

### 5.6 与现有标题分组、备注和折叠的关系

当前界面以标题分组，并支持母标题折叠、备注和 pinned notes 等能力。V0.35 引入真实继承树时，必须明确真实关系与标题分组的优先级：

- 已确认的父子关系优先用于呈现继承层级。
- 不能为了继续按标题分组而丢失跨标题的真实父子关系。
- 没有明确继承关系的会话继续使用现有标题分组方式。
- 不因改造列表结构而清除或重置现有备注、隐藏状态、标题折叠状态或 pinned notes 数据。
- 继续使用稳定的会话身份和现有备注目标机制；若树形节点需要调整 DOM 结构，必须保证既有备注仍能绑定到原来的正确对象。
- 对于同时存在标题分组和继承关系的会话，视觉层级应优先表达真实继承链；不能显示互相矛盾的两套关系。
- 保留现有排序、筛选、工作目录切换和来源切换能力，并明确这些操作与树形节点的交互规则。

### 5.7 排序与过滤规则

- 搜索和筛选不得修改源会话的父子关系数据。
- 当过滤条件隐藏父节点但保留子节点时，子节点不能因此被删除或改认成其他会话的子节点；应保留必要的父节点引用信息或显示父节点被过滤的提示。
- 排序可以改变同级节点的展示顺序，但不能改变父子关系和层级。
- 工作目录或来源切换后，应按当前来源重新解析/查找关系，不能沿用上一来源的父子索引。
- 若父子会话位于不同工作目录，关系查找仍应基于同一来源内的稳定会话身份；界面应清楚标明跨工作目录关联，不应悄悄丢弃关系。

## 6. 修复子会话内容截断

### 6.1 用户报告的问题

用户提供的截图中，Codex 里的「所以第二次修改后的同步和变基是一起做的对吧」之前还有大量历史，但语迹中该会话从这句话开始显示，导致此前属于该会话自身的内容没有显示。

V0.35 必须区分两件事：

1. 会话之间的继承关系。
2. 单个会话文件中实际记录的消息内容。

二者不能混为一谈。

### 6.2 最终产品行为

用户已明确选择：继承关系清晰展示后，每个对话可以不重复显示父会话的所有内容。

因此：

- 打开父会话时，显示父会话自身的内容。
- 打开子会话时，只显示子会话自身记录的完整内容。
- 阅读区不自动把父会话历史拼接到子会话前面。
- 阅读区不因为父会话已有相同消息，就删除子会话自身记录的消息。
- 不根据分叉点裁剪子会话自己的消息。
- 不把其他兄弟分支的消息混入当前子会话。
- 继承关系通过树形列表、父节点引用或等效 UI 呈现，而不是通过重复消息实现。
- 如果子会话文件中包含其自身记录的前置消息，即使它们早于某个可推断的分叉时间，也必须按该会话真实记录保留；不得只显示从某个猜测位置开始的消息。

### 6.3 无法可靠确定分叉位置时

用户已明确确认以下规则：

**如果找不到可靠的分叉位置，就显示继承关系，并且显示子会话所有内容，不得截断。**

因此：

- 精确分叉位置不是显示子会话完整内容的前提。
- 不得因为缺少 fork ordinal、时间戳或其他边界字段而丢弃子会话开头的事件。
- 不得按父会话与子会话的时间相似性来估算裁剪边界。
- 不得把父会话全文拼接到子会话中作为补救。
- 如果父会话 ID 明确而分叉位置未知，仍然可以显示父子关系，并标注分叉位置未知。
- 如果连父会话 ID 也无法可靠确认，只能显示关系未知，不得伪造父子链。
- 子会话自身的消息事件应保留原始记录顺序，并继续遵守现有的合法事件归一化、去重和渲染规则。

### 6.4 不应误判为内容截断的情况

Codex 解析器已有事件归一化、重复包装去重和上下文过滤等逻辑。V0.35 不应简单删除这些既有逻辑。

修复时必须区分：

- 正确过滤内部上下文、重复包装或无效记录。
- 错误地因继承关系、父会话元数据或分叉边界推断而删除子会话自己的有效消息。

仅修复第二类问题；不能把现有有效的消息去重与规范化逻辑整体撤销。

## 7. 索引结构与缓存要求

新增父子关系信息后，应同步更新索引构建、详情数据和前端读取逻辑。

要求：

- 新增字段应有明确的缺省值和兼容策略。
- 老索引缺少关系字段时，不能导致页面脚本异常或会话列表为空。
- 根据当前项目已有缓存版本机制，提升必要的构建器/解析器版本或缓存版本，使旧缓存不会被误认为已包含新关系字段。
- 需要时执行一次全量重建，确保旧缓存中的会话关系字段完整。
- 不改变原始 Codex 或 Claude 日志文件。
- 不将父会话全文复制到子会话详情文件。
- 不把父子关系错误写成源日志内容。
- 详情文件仍应保存当前会话自身的事件。
- 关系数据应尽量在索引层集中构建，避免每次打开会话时重复扫描全部原始日志。
- 对大量会话、深层继承链和异常关系进行性能保护；树形构建不得造成明显卡顿或无限循环。

## 8. 兼容性和明确不做的事情

V0.35 不包含以下工作：

- 不修改 Codex 或 Claude 原始会话文件。
- 不修改 WebDAV 聊天同步协议。
- 不修改 WebDAV 图片 sidecar 格式。
- 不改变现有来源的同步方式。
- 不将父会话历史复制到子会话中。
- 不以时间或文本相似度自动猜测父子关系。
- 不改变用户提问、助手回答、工具输出、图片和 Markdown 的既有内容语义。
- 不删除现有搜索历史、备注、隐藏状态、pinned notes 或排序偏好。
- 不因引入继承树而取消普通会话的标题分组。
- 不进行与本次需求无关的代码重构。
- 不修改其他 GitHub 仓库。
- 不修改本地目录或本地文件。
- 在用户审核文档并再次明确确认之前，不实施任何代码改动。
