# Open-CodexChatIndex V0.12 标题区点击零抖动与修改文档命名优化

状态：已实现并验收

日期：2026-05-08

## 1. 修改目标

V0.12 的目标是解决 V0.11 中点击标题区标题或分支时出现的可见轻微跳动问题，并从本版本开始让修改文档文件名体现主要修改内容，方便后续回溯。

本版本重点优化：

```text
点击标题区标题或分支时，标题区画面应保持静止，不出现先轻微上跳再回位的视觉抖动。
标题区点击后仍然要更新选中提示。
标题区点击后仍然要自动聚焦会话区，使上下键切换提问立即可用。
修改文档命名从单纯版本号改为“版本号 + 主要修改内容”。
```

本版本不改变以下既有能力：

```text
目录区点击路径后的切换行为。
标题区筛选和排序。
会话区全库搜索。
提问定位。
上下键切换提问。
回到顶部后自动聚焦。
只看提问。
过程懒渲染。
复制全文。
导出 MD。
复制路径。
复制 SESSION。
快刷和全量重建。
回复框和复制发送命令。
```

## 2. 已确认的根因

V0.11 已经能保证点击标题后标题区最终滚动位置保持不变，但是用户仍然能看到轻微跳动。

经过代码对比和浏览器采样，当前现象不是简单的 `scrollTop` 保存失败，而是标题区在点击标题时发生了整块 DOM 重建。

V0.11 当前链路为：

```text
点击标题区标题或分支
preserveSessionListScroll(...)
selectSession(...)
renderWorkspaceList(true)
renderSessionList(...)
sessionList.innerHTML = ''
重新创建所有标题分组和分支按钮
加载会话详情
renderViewer(...)
恢复 sessionList.scrollTop
```

浏览器采样中，标题点击前后 `sessionList.scrollTop` 可以保持一致，例如：

```text
beforeScroll: 700
afterScroll: 700
```

但同一次点击中 `#sessionList` 会发生整列表替换，例如：

```text
removed: 7
added: 7
```

所以 V0.11 解决的是“最终位置正确”，没有解决“中间不要重建和闪动”。

## 3. 为什么点路径不明显，点标题明显

点路径和点标题的用户预期不同。

点路径时：

```text
用户是在切换第一层目录。
标题区内容本来就应该整体变化。
标题区重建符合用户预期。
即使标题区变化，也会被理解为目录切换后的正常刷新。
```

点标题时：

```text
用户仍然停留在同一个标题列表中。
用户预期只是当前标题或分支的选中状态变化。
当前实现却清空并重建整个标题区。
同一视野里的内容被替换一次，就会被感知为抖动或回弹。
```

因此，点路径当前状态可以作为目标参照，但不能直接照搬其内部实现。路径点击的关键是“变化合理”，标题点击的关键是“同一列表不要重建”。

## 4. 正式实现方向

### 4.1 标题点击走轻量选择路径

V0.12 应为标题区点击增加轻量选择路径。

目标链路为：

```text
点击标题区标题或分支
只更新 selectedSessionKey 和必要的当前详情状态
只更新标题区已有 DOM 的 active class
不调用 renderWorkspaceList(true)
不调用 renderSessionList()
加载会话详情
renderViewer(...)
focusTranscriptForQuestionNavigation()
```

标题区点击时应避免：

```text
不要清空 sessionList.innerHTML。
不要整块重建标题区分组。
不要依赖事后恢复 scrollTop 来掩盖重绘。
不要调用 scrollIntoView 修正标题区位置。
```

### 4.2 保留完整重绘路径给真正需要重绘的场景

以下场景仍然可以走现有完整重绘：

```text
点击目录区路径。
目录区筛选。
标题区筛选。
标题区排序。
全库搜索结果变化。
刷新后 APP 数据变化。
全量重建后数据变化。
```

这些场景的列表内容确实可能变化，重绘是合理的。

V0.12 只要求标题区内部选择标题或分支时，不再重绘标题区。

### 4.3 选中态同步方式

建议增加一个小函数负责同步标题区选中态，例如：

```text
syncSessionListSelection()
```

该函数只做：

```text
遍历 .title-group-head 和 .session-btn。
根据元素绑定的 session key 或 group session keys 判断是否 active。
添加或移除 active class。
不修改 innerHTML。
不改变 scrollTop。
不改变 DOM 顺序。
```

为了支持这个函数，渲染标题区时应给标题按钮和分支按钮写入稳定标识，例如：

```text
data-session-key
data-group-session-keys
```

或使用更简单的映射表保存 DOM 节点与 session key 的关系。

### 4.4 鼠标点击不抢标题按钮焦点

标题点击后最终焦点应给到会话区，以支持上下键切换提问。

为减少浏览器默认按钮聚焦引发的滚动干扰，建议：

```text
标题按钮和分支按钮的 pointerdown/mousedown 中 preventDefault。
键盘触发仍然保留默认可访问性。
点击处理完成后，使用 transcript.focus({ preventScroll: true })。
```

注意不要阻止键盘用户操作：

```text
Tab 仍应可以聚焦标题按钮。
Enter 或 Space 仍应可以选择标题或分支。
鼠标点击才避免按钮抢焦点。
```

### 4.5 会话详情加载与标题区独立

标题区选中态更新和会话详情加载应分离。

推荐顺序：

```text
先同步 selectedSessionKey。
立即同步标题区 active class。
立即在会话区显示加载状态。
异步加载详情。
详情加载完成后只渲染会话区。
会话区聚焦和提问定位只影响 transcript。
```

这样即使详情加载较慢，标题区也不会被重建或回弹。

## 5. 修改文档命名规范

从 V0.12 开始，修改文档文件名采用：

```text
V版本号_主要修改内容.md
```

本版本文档名为：

```text
V0.12_标题区点击零抖动与修改文档命名优化.md
```

后续示例：

```text
V0.13_搜索索引体积优化.md
V0.14_会话区快捷键与焦点优化.md
V0.15_导出功能稳定性优化.md
```

旧文档建议暂时不批量改名：

```text
V0.02修改文档.md
V0.03修改文档.md
...
V0.11修改文档.md
```

原因：

```text
避免破坏旧记录中的引用。
避免把本次小版本变成文档迁移任务。
从 V0.12 开始新文档更清晰即可。
```

## 6. 副作用和风险

### 6.1 标题区选中态同步复杂度增加

从整列表重绘改成只更新 active class 后，代码会多一个局部同步逻辑。

可能风险：

```text
某些标题或分支的 active 状态没有及时更新。
同一个标题分组下多个分支时，标题组 active 和分支 active 不一致。
搜索或排序后旧 DOM 引用失效。
```

应对：

```text
完整重绘场景仍然重新生成 DOM。
轻量同步函数只在标题区内部点击时使用。
自动化测试覆盖标题组、单分支、多分支、归档分支。
```

### 6.2 鼠标和键盘交互需要区分

如果粗暴阻止标题按钮默认行为，可能影响键盘可访问性。

可能风险：

```text
Tab 聚焦标题按钮后按 Enter 无法选择。
Space 键行为异常。
焦点样式不符合预期。
```

应对：

```text
只在 pointerdown 或 mousedown 中针对鼠标点击 preventDefault。
click 事件仍执行选择逻辑。
键盘触发 click 时不阻止默认焦点链路。
```

### 6.3 详情加载慢时的状态一致性

标题区不重绘后，选中态会立即变化，但会话详情可能稍后才加载完成。

可能风险：

```text
用户快速连续点击多个标题时，旧请求晚返回覆盖新会话。
会话区短暂显示旧内容或错误加载状态。
```

当前代码已有 `selectedSessionKey` 校验，应继续保留：

```text
详情返回时必须确认返回内容仍属于当前 selectedSessionKey。
不匹配则丢弃旧返回。
```

### 6.4 性能影响

预期性能影响是正向的。

可能改善：

```text
标题点击少一次标题区整块 DOM 重建。
减少布局重排。
减少视觉抖动。
减少低端设备上的点击延迟。
```

可能新增成本：

```text
每次标题点击需要遍历标题按钮更新 active class。
```

该成本远小于整列表重建，通常可以忽略。

### 6.5 观看体验影响

预期观看体验改善：

```text
标题区点击时不再闪动。
连续查看相邻标题时更稳定。
用户视觉焦点不会被标题区抖动打断。
```

可能变化：

```text
标题按钮被鼠标点击后不会短暂停留焦点样式。
焦点会更快转移到会话区。
```

这符合当前需求，因为点击标题后用户希望直接用上下键切换提问。
