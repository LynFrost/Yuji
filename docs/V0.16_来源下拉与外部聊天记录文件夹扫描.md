# Open-CodexChatIndex V0.16 来源下拉与外部聊天记录文件夹扫描

状态：已实现并验收

日期：2026-06-04

## 1. 修改目标

V0.16 的目标是在刷新按钮左边新增“来源”下拉菜单，让用户可以在当前本机 Codex 会话来源和外部复制来的 Codex JSONL 聊天记录来源之间切换。

本版本重点优化：

```text
在刷新按钮左边新增“来源”下拉菜单。
默认来源为“本机 Codex”，行为与当前 V0.15 完全一致。
新增固定外部来源总目录：软件\外部聊天记录\。
软件\外部聊天记录\ 下的每一个一级子文件夹视为一个独立外部来源。
选择某个外部来源时，只递归扫描该子文件夹中的 Codex JSONL 聊天记录文件。
不提供“全部来源”。
来源切换影响显示范围：目录区、标题区、会话区、搜索结果都只显示当前来源的数据。
不同来源的数据、缓存、详情文件、搜索索引、备注绑定必须互相隔离。
```

本版本不支持：

```text
扫描全电脑。
扫描所有聊天软件。
解析 ChatGPT、Claude、Cursor、Gemini 等非 Codex JSONL 格式。
多个来源合并显示。
跨来源搜索。
跨来源备注共享。
```

## 2. 当前 V0.15 扫描逻辑确认

V0.15 当前扫描来源写在：

```text
软件版本_V0.15\Build-CodexChatIndex.ps1
```

脚本参数：

```powershell
[string]$CodexHome = "$HOME\.codex"
```

实际扫描目录：

```powershell
$sessionRoot = Join-Path $CodexHome "sessions"
$archiveRoot = Join-Path $CodexHome "archived_sessions"
```

也就是默认扫描：

```text
$HOME\.codex\sessions
$HOME\.codex\archived_sessions
```

在当前 Windows 机器上通常是：

```text
C:\Users\Administrator\.codex\sessions
C:\Users\Administrator\.codex\archived_sessions
```

V0.15 的 server 调用构建脚本时没有传入 `-CodexHome`，所以使用上述默认路径。

V0.16 中，“本机 Codex”来源必须保持这套行为不变。

## 3. 来源定义

### 3.1 本机 Codex 来源

来源名称：

```text
本机 Codex
```

来源类型：

```text
local-codex
```

扫描目录：

```text
$HOME\.codex\sessions
$HOME\.codex\archived_sessions
```

行为：

```text
刷新、快刷、全量重建与 V0.15 保持一致。
归档识别与 V0.15 保持一致。
复制路径、复制 SESSION、回复框复制发送命令与 V0.15 保持一致。
```

### 3.2 外部来源总目录

新增固定目录：

```text
软件\外部聊天记录\
```

该目录不是缓存，也不是临时文件。

它是用户放置外部聊天记录文件的共享资料目录：

```text
不随软件版本复制。
不放进 软件版本_V0.16。
不放进 临时文件_可清理。
用户可以手动新增、删除或重命名其下的一级子文件夹。
```

建议目录结构：

```text
软件
  外部聊天记录
    旧电脑Codex
      sessions\
      archived_sessions\

    朋友电脑复制
      2026\
        05\
          xxx.jsonl

    项目A备份
      xxx.jsonl
```

### 3.3 外部来源识别规则

`软件\外部聊天记录\` 下的每一个一级子文件夹就是一个独立外部来源。

示例：

```text
软件\外部聊天记录\旧电脑Codex
软件\外部聊天记录\朋友电脑复制
软件\外部聊天记录\项目A备份
```

下拉菜单显示：

```text
本机 Codex
旧电脑Codex
朋友电脑复制
项目A备份
```

选择：

```text
来源：旧电脑Codex
```

则只扫描：

```text
软件\外部聊天记录\旧电脑Codex\
```

不扫描：

```text
本机 Codex
朋友电脑复制
项目A备份
```

## 4. 外部来源扫描规则

### 4.1 文件格式限制

外部来源只扫描：

```text
*.jsonl
```

并且只按 Codex JSONL 聊天记录格式解析。

非 Codex JSONL 文件：

```text
不能纳入正常会话。
应记录解析失败数量。
不应导致整个来源扫描失败。
```

V0.16 不做其他聊天软件格式适配。

### 4.2 递归扫描

选择某个外部来源时，应递归扫描该来源文件夹下的所有 `.jsonl` 文件。

例如：

```text
软件\外部聊天记录\旧电脑Codex\sessions\2026\05\a.jsonl
软件\外部聊天记录\旧电脑Codex\archived_sessions\2026\04\b.jsonl
```

都属于：

```text
旧电脑Codex
```

### 4.3 归档识别

外部来源中，归档识别按路径判断。

规则：

```text
如果 jsonl 路径中包含 archived_sessions，则标记为归档。
否则标记为普通会话。
```

这样用户复制完整 Codex 结构时：

```text
旧电脑Codex\sessions\
旧电脑Codex\archived_sessions\
```

软件可以自然识别归档。

如果用户只是放一堆 jsonl：

```text
朋友电脑复制\xxx.jsonl
```

则默认作为普通会话。

## 5. 来源下拉菜单设计

来源下拉菜单放在刷新按钮左边。

建议顶部顺序：

```text
来源：[本机 Codex v]  刷新  全量重建
```

下拉项：

```text
本机 Codex
外部来源 1
外部来源 2
外部来源 3
```

如果没有外部来源子文件夹：

```text
下拉中只显示 本机 Codex。
```

来源切换后：

```text
目录区重新显示当前来源的工作目录。
标题区重新显示当前来源的标题。
会话区显示当前来源下选中的会话。
搜索只搜索当前来源。
统计数字只统计当前来源。
```

不需要“全部来源”。

## 6. 刷新、快刷、全量重建行为

### 6.1 本机 Codex

当前来源为：

```text
本机 Codex
```

刷新：

```text
扫描 $HOME\.codex\sessions
扫描 $HOME\.codex\archived_sessions
复用本机 Codex 来源缓存。
```

全量重建：

```text
重新扫描和解析本机 Codex 的全部 jsonl。
```

快刷：

```text
只刷新当前选中的本机 Codex session path。
```

### 6.2 外部来源

当前来源为：

```text
某个外部来源
```

刷新：

```text
只递归扫描该外部来源文件夹。
复用该外部来源自己的缓存。
```

全量重建：

```text
只重新扫描和解析该外部来源文件夹下的全部 Codex JSONL。
```

快刷：

```text
只重新读取当前选中的外部来源 jsonl 文件。
```

快刷对外部来源是“重新读取这个文件”，不是“继续对话”。

## 7. 数据隔离设计

不同来源必须彻底隔离。

隔离范围包括：

```text
data.json
search.json
cache.json
detail shard
session key
备注 key
当前选中会话
搜索结果
刷新和快刷请求
```

建议新增 per-source 运行数据目录：

```text
软件\运行数据\CodexChatIndex.sources\
  local-codex\
    CodexChatIndex.data.json
    CodexChatIndex.search.json
    CodexChatIndex.cache.json
    CodexChatIndex.sessions\

  external-旧电脑Codex-xxxxxx\
    CodexChatIndex.data.json
    CodexChatIndex.search.json
    CodexChatIndex.cache.json
    CodexChatIndex.sessions\

  external-朋友电脑复制-yyyyyy\
    CodexChatIndex.data.json
    CodexChatIndex.search.json
    CodexChatIndex.cache.json
    CodexChatIndex.sessions\
```

建议新增来源清单：

```text
软件\运行数据\CodexChatIndex.sources.json
```

示例：

```json
{
  "version": 1,
  "selectedSourceId": "local-codex",
  "sources": [
    {
      "id": "local-codex",
      "label": "本机 Codex",
      "type": "local-codex",
      "roots": [
        "$HOME\\.codex\\sessions",
        "$HOME\\.codex\\archived_sessions"
      ]
    },
    {
      "id": "external-old-codex-a1b2c3",
      "label": "旧电脑Codex",
      "type": "external-codex-jsonl",
      "root": "软件\\外部聊天记录\\旧电脑Codex"
    }
  ]
}
```

来源 id 建议：

```text
本机 Codex 固定为 local-codex。
外部来源使用 external-文件夹名-路径hash。
```

这样即使两个外部来源文件夹同名，也能区分。

## 8. 备注隔离和兼容

V0.13/V0.14/V0.15 已有备注文件：

```text
软件\运行数据\CodexChatIndex.notes.json
```

V0.16 必须避免不同来源之间串备注。

建议做法：

```text
备注 key 增加 sourceId 维度。
旧备注如果没有 sourceId，默认视为 local-codex。
保存新备注时写入 sourceId。
读取备注时只匹配当前来源 sourceId。
```

兼容规则：

```text
V0.15 以前已有备注不应丢失。
旧备注默认归属 本机 Codex。
外部来源不会继承本机 Codex 的备注。
不同外部来源之间也不会共享备注。
```

## 9. 外部来源的 SESSION 和回复框限制

本机 Codex 来源中：

```text
路径
SESSION
快刷
回复框复制发送
```

保持 V0.15 行为。

外部来源中需要谨慎处理：

```text
外部 jsonl 可能只是复制来的历史记录。
session id 不一定存在于当前机器的 Codex 会话库中。
codex resume <session-id> 不一定能成功。
```

建议 V0.16 对外部来源采用“浏览来源”策略：

```text
路径：保留，可复制外部 jsonl 路径。
快刷：保留，只重新读取当前外部 jsonl 文件。
SESSION：禁用或点击时提示“外部来源不保证支持 codex resume”。
回复框复制发送：禁用或显示同类提示。
```

推荐优先实现：

```text
外部来源禁用 SESSION 和回复框复制发送。
保留路径复制。
保留快刷作为文件重新读取。
```

这样不会给用户一个看似可用但实际可能失败的继续对话命令。

## 10. 服务接口和前端加载建议

V0.16 建议新增或调整 server API。

建议接口：

```text
GET /api/sources
GET /api/source-data?sourceId=...
GET /api/search?sourceId=...&q=...
POST /api/refresh
POST /api/rebuild
POST /api/refresh-current
```

刷新类请求 body 应包含：

```text
sourceId

```

页面启动时：

```text
读取来源清单。
选择上次 selectedSourceId，若不存在则回到 local-codex。
加载当前来源的数据。
渲染目录区、标题区、会话区。
```

来源切换时：

```text
保存 selectedSourceId。
加载该来源数据。
如果该来源还没有构建过，可提示用户刷新或自动做一次增量构建。
```

推荐行为：

```text
首次进入某个外部来源时，如果没有 data.json，显示“这个来源尚未扫描，请点击刷新”。
不自动全量扫描，避免用户切换来源时突然长时间等待。
```

## 12. 副作用和风险

### 12.1 架构复杂度增加

从单一来源变成多来源后，代码需要管理：

```text
来源清单。
当前来源。
每个来源自己的 data/search/cache/detail。
每个来源自己的刷新状态。
每个来源自己的搜索范围。
```

应对：

```text
V0.16 不做“全部来源”。
每次只显示一个来源。
先把来源切换边界做清楚，避免复杂度失控。
```

### 12.2 磁盘占用增加

每个来源都有独立缓存和详情 shard。

可能影响：

```text
外部来源越多，运行数据目录越大。
```

应对：

```text
这是来源隔离的必要成本。
后续可以增加“清理某个来源缓存”的功能，但 V0.16 先不做。
```

### 12.3 首次扫描外部来源可能较慢

外部来源可能包含大量 jsonl。

可能影响：

```text
第一次刷新或全量重建某个外部来源会耗时较长。
```

应对：

```text
只扫描当前选中的来源。
不提供全部来源扫描。
刷新按钮需要显示当前来源名称或进度提示。
```

### 12.4 非 Codex JSONL 解析失败

用户可能把其他格式文件放进外部来源。

可能影响：

```text
解析失败。
会话数量少于用户预期。
```

应对：

```text
只支持 Codex JSONL 写入文档和界面提示。
解析失败文件跳过并统计数量。
不因单个坏文件导致整个来源失败。
```

### 12.5 外部来源重命名可能改变 sourceId

如果外部来源 id 基于文件夹名和路径 hash，重命名文件夹后可能被视为新来源。

可能影响：

```text
旧缓存不再匹配。
旧备注不再自动匹配。
```

应对：

```text
V0.16 文档中明确：重命名外部来源文件夹可能视为新来源。
后续如有需要，可在来源文件夹中写入稳定 source id 文件，但 V0.16 先不做。
```

### 12.6 外部来源不适合继续对话

外部复制来的会话 id 不一定能被当前 Codex CLI resume。

可能影响：

```text
SESSION 或回复框复制发送命令可能不可用。
```

应对：

```text
外部来源默认作为浏览来源。
禁用或提示 SESSION 和回复框复制发送。
保留路径复制和快刷重新读取文件。
```

### 12.7 来源切换可能造成用户理解成本

来源切换会改变显示范围。

可能影响：

```text
用户可能以为某些会话消失了。
```

应对：

```text
下拉菜单必须明确当前来源。
统计数字只显示当前来源。
空状态提示应说明“当前来源没有匹配会话”。
```
