## 6. Codex 任务时间上下文

### 6.1 总体原则

V0.31 采用“可靠显式时间优先、任务范围校验、可靠备用字段回退、无法确认则留空”的方案。

明确禁止：

```text
不因为看到多个相同时间就机械递增秒数。
不按事件数量在任务起止之间平均插值。
不无条件用 UUIDv7 覆盖正常 timestamp。
不把文件修改时间复制给每条消息。
不修改原始 JSONL。
```

### 6.2 任务时间表

`Read-CodexSession` 在解析每个会话时建立仅存在于当前解析过程的任务时间表：

```text
key：turn_id
startedUtc：task_started.started_at 解析出的 UTC 时间
completedUtc：task_complete.completed_at 解析出的 UTC 时间
turnUuidUtc：turn_id 为合法 UUIDv7 时解出的 UTC 时间
lastAgentMessage：task_complete.last_agent_message
```

任务时间表只在解析当前会话期间存在，解析完成后释放，不写入 HTML、会话详情或长期缓存。

### 6.3 Unix 时间解析

新增统一 Unix 时间解析辅助函数，必须支持：

```text
10 位左右的 Unix 秒。
13 位左右的 Unix 毫秒。
数值类型和纯数字字符串。
超出合理 DateTimeOffset 范围时返回无效，不抛出导致整个会话失败。
```

实机样本：

```text
1784386425 -> 2026-07-18T14:53:45Z -> 本地 2026-07-18 22:53:45
1784386839 -> 2026-07-18T15:00:39Z -> 本地 2026-07-18 23:00:39
```

### 6.4 UUIDv7 时间解析

新增 UUIDv7 时间辅助函数：

```text
只接受标准 UUID 结构，允许用户消息 id 带 msg_ 前缀。
校验版本位确实为 7。
读取 UUIDv7 前 48 位 Unix 毫秒。
解析结果必须落在合理年份范围内。
普通 UUID、turn-v008、call_xxx 和其他非 UUIDv7 字符串不得误解析。
```

UUIDv7 只作为已经确认来源的辅助时间，不作为所有字符串的通用日期识别器。

### 6.5 临时事件时间信息

为了在读取到 `task_complete` 后再校验同一轮早先事件，可在内存中的事件对象暂存：

```text
原始顶层时间候选。
用户 response_item 的 payload.id。
事件所属 turnId。
事件来源类型和 phase。
item_completed 的 item.id、item.type，以及外层 payload.started_at_ms 和 payload.completed_at_ms。
entry.payload.internal_chat_message_metadata_passthrough.turn_id 和 create_time。
原始 JSONL 行序号 rawLineOrdinal。
消息包装来源，例如 legacy_agent_message、response_item_message 或 completed_item_message。
```

完成时间解析后，必须移除所有临时诊断字段，再生成正式会话详情，避免扩大长期 JSON 和浏览器内存。

### 6.6 新版记录 turnId 和包装时间来源

所有 JSONL 记录统一通过 `Get-EntryTurnId` 取得轮次，不得只依赖当前解析游标：

```text
1. 顶层 entry.turn_id。
2. entry.payload.turn_id。
3. entry.payload.item.turn_id。
4. entry.payload.internal_chat_message_metadata_passthrough.turn_id。
5. 仅对严格按 JSONL 顺序位于有效 task_started 与 task_complete 之间、且没有显式轮次的旧式 event_msg，才允许回退当前 currentTurnId。
6. response_item、custom_tool_call 和 custom_tool_call_output 缺少显式轮次时，不得盲目回退 currentTurnId；保留 turnId 为空并计入未归属记录统计。
```

优先级按记录自身证据从强到弱执行。metadata 中的 `turn_id` 必须和已知任务表交叉验证；如果它与当前游标不同，以记录自身的显式值为准，不得因当前游标覆盖它。

`entry.payload.internal_chat_message_metadata_passthrough.create_time` 是该包装记录自己的时间候选，格式支持带小数的 Unix 秒、Unix 毫秒和数值字符串：

```text
custom_tool_call 和 custom_tool_call_output 各自使用自己的 create_time，不能共享或复制时间。
item_completed 外层 payload.started_at_ms/completed_at_ms 优先于 create_time。
对 response_item、custom_tool_call 和 custom_tool_call_output，若顶层 timestamp 不可信，经过任务范围校验的 create_time 可作为该记录的独立时间候选。
create_time 不能回填同一 turn 的其他消息，也不能覆盖更精确且通过校验的消息级时间。
无有效 turnId 的 create_time 不得用于建立问答配对，只能作为未归属事件的诊断时间候选。
```

## 7. 单条事件时间选择规则

### 7.1 顶层时间可信条件

先使用现有 UTC 语义安全的时间解析函数解析顶层 `timestamp`。

如果事件存在完整任务起止时间，顶层时间只有在以下范围内才可信：

```text
startedUtc - 5 秒
到
completedUtc + 5 秒
```

前后各 5 秒的容差只用于吸收记录顺序和写盘差异，不允许按会话时长动态放大，也不得接受相差数小时或数天的会话创建时间。

如果存在通过校验的事件级独立时间，顶层 timestamp 还必须与该事件级时间相差不超过固定 5 秒；即使顶层 timestamp 落在任务起止范围内，只要超过该差值，也必须判为异常，不能因为范围校验通过而优先使用。

时间选择总原则：

```text
事件级独立时间优先于顶层 timestamp。
顶层 timestamp 只有在没有有效事件级时间，或与事件级时间差不超过 5 秒时，才可作为候选。
事件级时间与顶层时间相差超过 5 秒时，保留事件级时间，顶层时间标记为异常候选并丢弃。
没有事件级时间的旧格式记录，继续按任务范围、UUIDv7 和既有回退规则处理。
```

如果同时存在可靠的用户消息 UUIDv7 时间，而顶层时间与 UUIDv7、事件级时间或任务范围明显矛盾，则顶层时间判为异常。

没有任务上下文的普通事件继续使用可解析的顶层时间，不因 V0.31 被批量清空。

### 7.2 用户提问

用户提问时间优先级：

```text
1. item_completed / UserMessage 外层 payload.started_at_ms。
2. item_completed / UserMessage 外层 payload.completed_at_ms。
3. 位于任务有效范围内的用户 response_item payload.id UUIDv7 时间。
4. 通过事件级一致性校验和任务范围校验的顶层 timestamp。
5. task_started.started_at。
6. 合法 turn_id UUIDv7 时间。
7. 无可靠候选时留空。
```

事件级时间必须先满足：Unix 时间格式有效、位于合理日期范围、任务边界有效，并且在同时存在起止时间时满足 `started_at_ms <= completed_at_ms`。事件级时间有效时，顶层 timestamp 不能越过第 7.1 节的 5 秒一致性容差。

`response_item/message/user` 与相邻的 `event_msg/user_message` 仍需合并为一个提问。去重判断应使用已经解析的可靠候选，不能因为两个错误顶层时间相同而产生额外提问。

### 7.3 最终回答

最终回答时间优先级：

```text
1. item_completed / AgentMessage 外层 payload.completed_at_ms。
2. item_completed / AgentMessage 外层 payload.started_at_ms。
3. 通过事件级一致性校验和任务范围校验的顶层 timestamp。
4. 对应 task_complete.completed_at。
5. 无可靠候选时留空。
```

`item_completed` 外层 payload 的消息级 `completed_at_ms` 与具体 `item.id` 直接绑定，经过 Unix 毫秒合法性和任务范围校验后，优先级高于整轮 `task_complete.completed_at`。

只有满足以下任一条件时，才将 `completed_at` 赋给最终回答：

```text
最终回答正文与 task_complete.last_agent_message 一致。
或该 turn 中只有一条 assistant_final，可唯一确定对应关系。
```

如果同一 turn 有多条最终回答且无法确认哪一条对应 `last_agent_message`，不得把同一个完成时间猜测性地写给全部回答。

### 7.4 过程、工具和普通系统事件

```text
item_completed 外层 payload 提供与具体可见过程或工具项绑定的 started_at_ms/completed_at_ms：通过任务范围校验后可作为该事件的独立可靠时间。
事件级独立时间有效：优先使用事件级时间；顶层 timestamp 仅在 5 秒一致性容差内作为辅助候选。
没有有效事件级独立时间时，顶层 timestamp 位于任务有效范围内才可保留。
顶层 timestamp 明显异常且没有该事件独立的可靠时间：时间留空。
不得把 task started 或 completed 时间复制给整组 commentary、tool 或 system 事件。
```

页面渲染时间为空时，不生成空白占位文本，也不显示虚假的“时间未知 00:00:00”；消息正文和过程摘要保持正常。

### 7.5 task_started 和 task_complete

```text
task_started 优先使用 payload.started_at。
task_complete 优先使用 payload.completed_at。
内部字段无效时，才考虑通过任务范围校验的顶层 timestamp。
```

### 7.6 中断和不完整任务

```text
只有 started_at、没有 completed_at：用户提问可使用 UUIDv7 或 started_at；item_completed 独立时间不得早于 started_at - 5 秒。如能识别下一轮 started_at，还不得晚于下一轮 started_at + 5 秒。
只有 completed_at、没有 started_at：最终回答可以按唯一对应规则使用 completed_at；item_completed 独立时间不得晚于 completed_at + 5 秒。如能识别上一轮 completed_at，还不得早于上一轮 completed_at - 5 秒。
item_completed 外层 payload 同时具有 started_at_ms 和 completed_at_ms：两者都必须合法且 started_at_ms <= completed_at_ms；否则该 item 的整组独立时间无效。
item_completed 只有一个合法独立时间：按已知单侧任务边界校验，通过后可以用于该 item，不能因为任务缺少另一侧边界而直接丢弃。
任务 started_at > completed_at：该任务范围整体无效，不使用它校验或回填其他事件；具体 item 自身合法且满足可用邻接边界的独立时间仍可保留。
任务或 item 时间执行前后 5 秒运算时必须防止 DateTimeOffset 范围溢出；溢出候选直接判为无效，不得导致整个会话解析失败。
任务被中断且没有最终回答：不得生成不存在的最终回答时间。
无法识别 turnId：保持当前事件顺序，只使用事件自身可靠时间。
```

## 8. 新旧 Codex 事件兼容和既有功能边界

### 8.1 会话创建时间

页面顶部“创建”继续表示当前 rollout/session 容器的创建时间：

```text
优先 session_meta.payload.timestamp。
其次现有文件和会话兜底逻辑。
```

续接进来的历史消息可能早于当前 rollout 创建时间。这是正确数据语义，不将会话创建时间改成最早历史消息时间。

### 8.2 会话更新时间和排序

本次截图证明的是消息事件时间错误，尚未证明当前会话更新时间或标题排序错误。因此 V0.31 不无依据地重定义全部会话更新时间。

要求：

```text
保持现有 UpdatedAt 和标题、目录排序语义。
仅在现有 UpdatedAt 来源本身为空或不可解析时沿用当前文件兜底。
不得用最早导入历史时间覆盖当前会话最新更新时间。
```

### 8.3 不改变事件结构

时间修复不得改变既有有效事件的：

```text
事件原始顺序。
user/assistant/process/tool/system 的类型。
questionKey 和 eventIndex。
thread_rolled_back 有效分支处理。
提问上下键、回到顶部和 Progress Anchor。
搜索、复制全文、导出 MD、路径、SESSION 和回复框。
不得把 Reasoning、ContextCompaction、developer 上下文或内部 handoff summary 转换成用户可见消息。
```

新版格式兼容只补回原始 JSONL 中已经存在、并由可见消息完成记录明确确认的事件。恢复此前漏掉的真实 `AgentMessage` 和工具完成项后，会话的回答数、过程数、工具数和分组数会按原始记录增加，这是纠错后的预期结果，不视为事件结构回归。

### 8.4 可见消息适配规则

Codex 消息适配层只接受以下用户可见来源：

```text
旧格式：event_msg / agent_message。
新格式：event_msg / item_completed，且 payload.item.type = AgentMessage。
用户消息继续兼容 response_item / message / user；同时允许 item_completed / UserMessage 作为缺失时的可见来源。
```

新版 `AgentMessage` 映射：

```text
item.phase = commentary -> assistant_commentary。
item.phase = final_answer -> assistant_final。
item.content 中的 Text 文本 -> rawText。
payload.turn_id -> turnId。
item.id -> 可见消息稳定 ID 和去重候选。
外层 payload.started_at_ms/completed_at_ms -> 事件独立时间候选。
```

未知 phase 不得默认当作最终回答。空文本消息不生成空回答卡片。

用户消息的合并规则：

```text
response_item / message / user 继续作为正文和图片数据的主来源，必须保留其 input_image 解析结果。
item_completed / UserMessage 主要补充可见完成状态、稳定 item.id、client_id 和外层 payload.started_at_ms/completed_at_ms。
两种用户包装没有共同 ID 时，只允许在同一 turn、完整规范化正文一致且原始行序相邻的跨包装候选之间合并。
两条 item_completed / UserMessage 只要稳定 ID 不同就必须分别保留，即使正文相同。
合并后采用最早 rawLineOrdinal 作为逻辑位置，正文和图片使用 response_item 的完整数据，时间和稳定 ID 使用通过校验的 item_completed 元数据。
```

### 8.5 新旧消息去重

同一会话可能跨越 Codex 客户端升级，必须允许旧格式、新格式和过渡格式混合出现。

去重规则：

```text
1. 相同 item.id 或明确消息 ID 的旧、新包装属于同一消息。
2. 两条权威 item_completed 记录只要稳定 ID 不同就绝不合并，即使 turnId、phase 和正文完全相同。
3. turnId + phase/kind + 规范化完整正文签名只能作为 legacy agent_message 与 item_completed AgentMessage 的候选条件，不能单独完成跨包装去重。
4. 没有共同稳定 ID 时，候选还必须位于同一个紧邻包装簇中：两条记录之间只能有与该消息对应的 response_item/message/assistant 包装，不能出现用户、工具、task_started、task_complete、thread_rolled_back 或其他可见 Assistant 消息。
5. 如果无法证明两条记录属于同一个包装簇，宁可保留两条，不得因正文相同而删除一条。
6. response_item / assistant 与 item_completed / AgentMessage 具有相同消息 ID时直接关联；没有对应 item_completed 的 response_item 不能单独生成可见回答。
7. 任何正文签名去重都限定在同一 turn，不跨轮次合并相同回答。
```

同一可见消息同时存在旧 `agent_message` 和新 `item_completed / AgentMessage` 时，只有在共同稳定 ID或上述紧邻包装簇均成立时才输出一次。解析时暂存每条记录的 `rawLineOrdinal`；合并后保留最早原始行序对应的逻辑位置，同时采用新版稳定 ID和通过校验的独立时间。临时行序和包装来源字段必须在生成正式详情前移除。

独立的 `response_item / message / assistant` 不作为可见性凭据；只有在被明确的可见完成记录关联时才可作为内容补充，不能单独生成回答。

### 8.6 新版工具记录

V0.31 同时恢复新版可见工具过程，避免过程组继续只显示系统统计。

`CommandExecution` 字段映射：

```text
toolName：固定为 exec_command；摘要中的命令优先使用 command 数组，再使用 parsed_cmd。
status：优先 item.status；为空时根据 exit_code，0 为 completed，非 0 为 failed。
summary：命令摘要 + 状态 + exit_code/duration；结果短摘要依次取 formatted_output、aggregated_output、stdout、stderr 的首段非空文本。
rawText：先收集 aggregated_output，再补充其中尚未包含的 stdout 和 stderr 非空段，避免丢失分散输出且不重复同一正文；三者都为空时才使用 formatted_output。
cwd、process_id、exit_code 和 duration 只作为工具元信息，不重复拼接进多份完整输出。
```

`DynamicToolCall` 字段映射：

```text
toolName：namespace 和 tool 都存在时使用 namespace.tool；其次使用 tool；最后回退 dynamic_tool。
status：优先 item.status；为空时由 success 布尔值映射为 completed/failed。
summary：工具名、状态和 arguments 的安全短摘要。
rawText：先保留完整 arguments，再按原顺序展开 content_items；inputText、text 和 outputText 读取 text，其他未知内容转为安全 JSON 文本，不执行其中 HTML。arguments 与输出使用明确分段，复制和导出时不能丢失任一侧。
```

`ImageView` 字段映射：

```text
toolName：固定为 view_image。
status：item_completed 记录视为 completed。
summary/rawText：使用 path；空路径仍保留工具完成状态，但不生成伪路径。
```

`custom_tool_call` 和 `custom_tool_call_output` 只作为外层包装和缺失权威项时的回退来源：

```text
通过相同 call_id 配对开始和结束记录，并要求属于同一 turn。
暂存开始、结束 rawLineOrdinal，检查该闭区间内的权威 item_completed / CommandExecution、DynamicToolCall 或 ImageView。
一个区间内可能有多个权威工具项，必须逐条保留，不能合并成一个，也不能假设 item.id 与 call_id 相同。
存在嵌套或重叠区间时，每个权威 item 归属包含它的最小匹配区间，防止同一 item 抑制多个外层包装。
区间内存在至少一个权威工具项时，抑制该 custom 外层包装，避免重复显示。
区间内没有权威工具项时，才使用 custom pair 生成一个回退工具事件：toolName 取 name，输入取 input，输出按 output 内容数组顺序提取 input_text/text/output_text 的 text，未知项安全序列化。
只有 custom_tool_call、没有对应 output 时，可生成 status=unknown 的回退摘要，但不得伪造成功结果；只有孤立 output 时安全跳过并计入未识别统计。
```

权威工具项之间只按相同稳定 `item.id` 去重；不同 ID 的工具必须分别保留。页面仍默认只显示工具名称、状态和简短摘要；用户展开后可查看完整内容，复制全文和导出 MD 不得丢失原始输出。

明确排除：

```text
Reasoning 不显示原始内部推理，只保留已明确面向用户的 commentary。
ContextCompaction 不显示为过程或回答。
Developer、system 注入上下文不显示为用户提问。
未知 item.type 不猜测映射，保留为未识别记录统计或安全跳过。
```

## 10. 最近搜索历史数据设计

### 10.1 保存位置和隐私边界

搜索历史只保存在当前浏览器的 `localStorage`：

```text
不写入源码。
不写入 软件/运行数据。
不写入原始聊天记录。
不通过 WebDAV 同步。
不按来源拆分。
同一浏览器中的所有来源共用一份历史。
```

建议存储键：

```text
yuji-search-history-v1
```

建议数据结构：

```json
{
  "version": 1,
  "items": [
    "最近一次搜索",
    "上一条搜索"
  ]
}
```

只保存按最近使用顺序排列的搜索词，不保存：

```text
来源 ID。
全部/当前状态。
全文/提问状态。
命中结果。
打开的会话、提问位置或时间。
```

点击历史时使用当前来源和当前搜索状态执行，不自动切换来源或按钮状态。

### 10.2 数量和去重

```text
最多保存 20 条。
新确认的搜索放到第一位。
超过 20 条时删除最旧记录。
保存前去除首尾空白，并将连续空格、Tab、换行规范为单个空格。
去重键不区分英文大小写，保留最近一次输入的原始大小写。
相同搜索再次使用时移动到第一位，不生成重复项。
空字符串不保存。
清空搜索框不保存。
从 localStorage 加载时也执行同一套空白规范化、空项过滤和英文大小写不敏感去重，按原存储顺序保留第一条。
加载完成后截取前 20 条；旧数据超过 20 条不能全部带入内存或 DOM。
加载结果发生清洗且存储可写时只回写一次规范化结果，不能形成读取与写入循环。
```

不主动截断单条搜索词。若单条异常过大导致存储失败，按第 15 节降级处理。

## 11. 搜索历史保存触发

实时输入过程中不能每输入一个字符就保存，否则会形成大量半成品历史。

只有以下动作确认一次搜索：

```text
1. 搜索框中按 Enter，且不处于中文输入法组合状态。
2. 输入搜索词后点击某个命中的标题或提问。
3. 输入搜索词后切换 全部/当前。
4. 输入搜索词后切换 全文/提问搜索字段。
5. 输入搜索词后，焦点真正离开搜索框和搜索历史浮层。
```

规则：

```text
搜索是否有命中不影响保存；无结果搜索也可以保存，便于以后调整或复用。
点击历史项本身视为再次使用该搜索，并移动到第一位。
点击单条删除、清空按钮不把当前输入误保存为新历史。
中文输入法 compositionstart 到 compositionend 期间不执行 Enter 保存。
```

## 15. localStorage 异常和资源清理

所有搜索历史存储操作必须使用 `try/catch`：

```text
存储键不存在：返回空历史。
JSON 损坏或版本不支持：忽略损坏内容并使用空历史，不能阻止页面打开。
items 不是字符串数组：过滤非法项；合法字符串仍需按第 10.2 节重新规范化、去重并限制为 20 条。
浏览器禁用存储、隐私模式拒绝写入或抛出 SecurityError：停止本次持久化重试，保留当前页面内存历史，搜索继续正常执行。
明确为 QuotaExceededError 或兼容浏览器等价配额错误：逐步删除最旧历史后重试。
SecurityError、未知异常和普通 TypeError 不得误按配额不足处理，也不得通过反复删除历史重试。
只剩当前搜索仍无法写入：放弃本次保存并显示短暂提示，不截断搜索词。
同一次保存动作最多完成一轮按最旧项递减的有限重试；事件监听和定时器不能触发无限重试。
```

性能和资源要求：

```text
内存中最多维护 20 条字符串和一个高亮索引。
不得为历史项复制会话正文或搜索结果。
浮层关闭时清理 5 秒确认计时器和临时键盘状态。
```

## 19. 副作用与规避

### 19.1 首次刷新耗时增加

副作用：

```text
V0.31 第一次刷新需要重新解析全部会话，可能明显慢于普通增量刷新。
```

规避：

```text
这是批量修正历史时间的一次性必要成本。
全量完成后保存 V0.31 缓存，第二次无变化刷新必须恢复增量速度。
不在每次刷新重复执行额外全库迁移。
```

### 19.2 历史消息早于会话创建时间

副作用：

```text
续接进来的真实历史消息可能早于当前 rollout 创建时间，视觉上看似时间倒退。
```

规避：

```text
顶部“创建”继续表示当前 rollout 容器创建时间。
消息时间表示被续接的原始轮次时间。
事件仍按原始记录顺序展示，不按时间重新排序。
```

### 19.3 部分过程和工具不显示时间

副作用：

```text
没有可靠独立时间的过程、工具事件会不显示时间，同一过程组中时间信息可能不完全一致。
```

规避：

```text
优先保证不展示错误时间。
正文、过程摘要、工具状态和顺序不受影响。
未来若源格式新增可靠事件时间，可再补充候选字段。
```

### 19.4 completed_at 精度

副作用：

```text
部分 completed_at 只有秒级精度，可能比原本可用的毫秒时间粗。
```

规避：

```text
只有顶层时间异常时才回退 completed_at。
当前页面本来只显示到秒，因此不损失可见精度。
```

### 19.5 时间来源误判风险

副作用：

```text
如果只校验任务范围而不比较事件级时间，错误固定的任务开始时间即使落在任务范围内也可能继续被接受；范围过窄则可能清空正常的边界事件。
```

规避：

```text
使用事件级 started_at_ms/completed_at_ms、任务 started/completed 和 UUIDv7 多证据交叉校验。
容差固定为任务开始前 5 秒至完成后 5 秒，只覆盖少量记录和写盘顺序差异。
事件级时间与顶层 timestamp 的一致性容差固定为 5 秒；超过时优先保留事件级时间。
正常、异常、不完整任务和无 turnId 均设独立测试。
无法确认时留空，不猜测。
```

### 19.6 会话详情和搜索索引增大

副作用：

```text
此前漏掉的真实回答、commentary 和工具事件恢复后，会话详情、Assistant 统计和搜索索引会变大。
大型会话首次打开需要处理更多真实回答正文。
```

规避：

```text
最终回答必须完整显示，不能为了性能再次丢弃。
commentary 和工具继续默认摘要、按需展开，不把完整工具输出复制到多个 DOM 节点。
保持现有大型会话保护、content-visibility 和搜索索引按需加载策略。
复制全文和导出 MD 从完整事件数据生成，不依赖页面是否展开。
实机检查打开时间、滚动帧稳定性和浏览器内存，滚动出现可感知卡顿不得验收通过。
```

### 19.7 混合格式误判和重复风险

副作用：

```text
如果直接把全部 response_item 当成可见回答，会出现重复回答或暴露内部续接摘要。
如果只按正文全局去重，不同轮次内容相同的合法回答可能被误删。
如果未来 Codex 增加未知 item.type，猜测映射可能产生错误工具或回答。
```

规避：

```text
只接受明确的旧 agent_message 和新版 item_completed / AgentMessage 可见边界。
当前实机观察到旧格式约 2085 个文件、含新版 AgentMessage 的文件约 17 个，同时混合两种格式的文件约 3 个；混合格式是少数场景，但文件可能继续追加，不能把该观测当成永久比例保证。
去重优先稳定消息 ID和明确包装簇；正文签名只能作为包装簇内的辅助条件。无法证明是同一消息时保留两条，优先避免误删真实回答。
response_item 只作已确认可见记录的内容补充，不单独证明可见性。
Reasoning、ContextCompaction、developer 上下文和 handoff summary 明确排除。
未知类型安全跳过并由脱敏夹具覆盖，不默认归类为 final_answer。
```

### 19.8 搜索历史隐私

副作用：

```text
共享电脑上的其他浏览器使用者可能看到最近搜索关键词，其中可能含项目名、路径或敏感术语。
```

规避：

```text
只保存在当前浏览器，不上传 WebDAV。
支持单条删除和清空全部。
README 说明搜索历史保存位置和清除方法。
```

### 19.9 搜索历史可能丢失

副作用：

```text
清理站点数据、换浏览器、换电脑、隐私模式或浏览器拒绝 localStorage 后，历史不会保留。
```

规避：

```text
明确其定位是便捷历史，不是同步数据或备份。
存储失败不影响实际搜索。
```

### 19.10 失焦保存无结果搜索

副作用：

```text
用户输入后点击其他区域，即使没有命中，也会保存该搜索。
```

规避：

```text
这是已确认的“输入完成后离开搜索框即确认”规则。
最多 20 条并支持单删，错误记录处理成本低。
```

### 19.11 浮层遮挡正文

副作用：

```text
历史浮层最大可占视口 50% 高度，打开时会临时遮挡部分正文。
```

规避：

```text
浮层不推动布局、不改变滚动位置。
点击外部或按 Escape 可立即关闭。
内容过多只在浮层内部滚动。
```

### 19.12 正常刷新更新共享运行数据

副作用：

```text
实机验收会更新 软件/运行数据 中的 V0.31 索引、详情和缓存。
```

规避：

```text
这是用户明确允许的正常刷新例外。
只通过正式构建流程更新，不手工改写运行数据。
原始 JSONL 不修改。
```

### 19.13 归档副本占用空间

副作用：

```text
软件/CodexChatIndex_V0.30 增加一份源码，误开归档 CMD 会运行旧版。
```

规避：

```text
只归档 21 文件白名单，不复制运行数据和生成 HTML。
当前入口始终为 软件/CodexChatIndex/Open-CodexChatIndex.cmd。
```
