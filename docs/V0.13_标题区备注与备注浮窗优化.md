# Open-CodexChatIndex V0.13 标题区备注与备注浮窗优化

状态：已实现并验收

日期：2026-05-13

## 1. 修改目标

V0.13 的目标是在标题区增加备注能力，让用户可以给标题区里的每一个标题或分支补充自己的说明，并在鼠标悬停时优先看到备注内容。

本版本重点优化：

```text
标题区的问题类大标题支持右键新建、编辑、删除备注。
标题区重复子标题或分支标题支持右键新建、编辑、删除备注。
一个标题项只能有一个备注。
如果标题项设置了备注，鼠标悬停浮窗显示备注内容。
如果标题项没有设置备注，鼠标悬停浮窗保持当前默认内容。
备注浮窗要和原来的浏览器默认浮窗有明显区别。
备注浮窗尽量显示全文内容，只有实在显示不下时才出现滚动条。
```

本版本不改变以下既有能力：

```text
目录区选择。
标题区筛选和排序。
标题区点击零抖动。
会话区全库搜索。
提问定位和上下键切换。
回到顶部后自动聚焦。
只看提问。
过程懒渲染。
复制全文。
导出 MD。
复制路径。
复制 SESSION。
快刷、刷新、全量重建。
回复框和复制发送命令。
```

## 2. 备注绑定规则

备注必须避免串到错误标题上，所以不建议只按标题显示文字绑定。

V0.13 推荐使用两类稳定备注 key。

### 2.1 问题类大标题备注

问题类大标题按以下信息绑定：

```text
工作目录 cwd + 标题全文 title
```

原因：

```text
当前标题区本来就是在同一个工作目录下按标题全文聚合。
同一工作目录里的同一标题组应该共享一个大标题备注。
不同工作目录即使标题文字一样，也不应该共享备注。
```

建议 key 形式：

```text
group:<workspaceId 或 cwd hash>:<title hash>
```

实际保存时应同时保留可读字段，便于以后排查：

```json
{
  "type": "group",
  "workspace": "M:\\WORK\\...",
  "title": "用户问题全文",
  "note": "用户写的备注"
}
```

### 2.2 重复子标题或分支备注

重复子标题或分支标题按具体会话绑定：

```text
session path 优先；没有 path 时使用 session key；再没有时使用 session id
```

原因：

```text
重复子标题对应的是具体 jsonl 文件或具体会话分支。
即使多个分支标题文字一样，也应允许分别备注。
用户在子标题上写的备注通常是在标记某一个具体分支。
```

建议 key 形式：

```text
session:<session path hash 或 session key>
```

### 2.3 大标题备注和子标题备注不互相继承

大标题备注和子标题备注互相独立。

```text
大标题有备注，不代表下面所有子标题都自动有备注。
子标题没有备注时，仍显示原来的 jsonl 路径浮窗。
子标题有备注时，才显示子标题自己的备注浮窗。
```

这样可以避免用户误以为某个具体分支被备注过。

## 3. 备注存储设计

备注应作为用户运行数据保存，不应写入原始 JSONL，也不应写入构建缓存。

建议新增文件：

```text
软件\运行数据\CodexChatIndex.notes.json
```

该文件属于运行数据：

```text
不随软件版本复制。
不放进 软件版本_V0.13。
不放进 临时文件_可清理。
刷新、快刷、全量重建时都应保留。
```

建议结构：

```json
{
  "version": 1,
  "updatedAt": "2026-05-13T00:00:00+08:00",
  "notes": {
    "group:...": {
      "type": "group",
      "workspace": "M:\\WORK\\...",
      "title": "标题全文",
      "note": "备注内容",
      "createdAt": "2026-05-13T00:00:00+08:00",
      "updatedAt": "2026-05-13T00:00:00+08:00"
    },
    "session:...": {
      "type": "session",
      "workspace": "M:\\WORK\\...",
      "title": "标题全文",
      "path": "M:\\...\\session.jsonl",
      "sessionId": "019...",
      "note": "备注内容",
      "createdAt": "2026-05-13T00:00:00+08:00",
      "updatedAt": "2026-05-13T00:00:00+08:00"
    }
  }
}
```

备注内容建议限制：

```text
允许多行文本。
保留换行。
前后空白保存时 trim。
空内容不能保存；如果用户清空备注并保存，应提示使用“删除备注”。
单条备注建议限制在 5000 到 10000 字以内，防止误粘贴超大内容。
```

## 4. 右键菜单设计

标题区每个可备注项都支持右键菜单。

可备注项包括：

```text
.title-group-head 问题类大标题。
.session-btn 重复子标题或分支标题。
```

菜单内容：

```text
没有备注时：新建备注
已有备注时：编辑备注、删除备注
```

交互要求：

```text
右键只影响备注菜单，不改变当前选中会话。
右键菜单出现后，点击页面其他位置或按 Esc 关闭。
右键菜单不能导致标题区滚动条跳动。
右键菜单不能触发标题点击和会话切换。
```

删除备注建议：

```text
删除前给一个轻量确认。
确认后删除对应 note key。
删除成功后 toast 提示“备注已删除”。
```

原因：

```text
备注是用户手写数据，误删比误关菜单更难恢复。
轻量确认可以降低误删风险。
```

## 5. 新建和编辑备注弹窗设计

新建和编辑备注使用同一个轻量弹窗。

弹窗内容建议：

```text
标题：新建备注 或 编辑备注
只读上下文：当前标题或当前会话路径的简短显示
多行输入框：备注内容
按钮：保存、取消
```

输入框要求：

```text
支持多行。
默认聚焦到输入框。
编辑备注时自动填入原备注内容。
Ctrl+Enter 可以保存。
Esc 可以取消。
```

保存成功后：

```text
写入 CodexChatIndex.notes.json。
更新内存中的 notes。
立即更新对应标题项的备注状态。
关闭弹窗。
toast 提示“备注已保存”。
```

保存失败时：

```text
保持弹窗打开。
toast 或弹窗内提示失败原因。
不要丢失用户已输入内容。
```

## 6. 悬停浮窗设计

当前标题区使用浏览器原生 `title` 属性：

```text
问题类大标题：title 是问题全文。
重复子标题或分支标题：title 是 jsonl 文件路径或标题。
```

V0.13 应在“有备注”时改用自定义备注浮窗。

### 6.1 没有备注时保持原样

没有备注的标题项保持当前行为：

```text
问题类大标题悬停显示问题全文。
重复子标题或分支标题悬停显示 jsonl 路径。
```

这可以继续使用原生 `title`。

### 6.2 有备注时显示备注浮窗

有备注的标题项：

```text
不要再把原始 title 暴露给浏览器默认浮窗。
鼠标悬停时显示自定义备注浮窗。
浮窗内容为备注全文。
```

备注浮窗视觉建议：

```text
暖黄色或纸张感背景。
深色细边框。
明显阴影。
左上角可显示“备注”标签。
正文使用 pre-wrap，保留换行。
字体略大于原生 title 的默认效果。
```

浮窗尺寸建议：

```text
宽度根据内容自动适配。
最小宽度约 260px。
最大宽度不超过视口宽度的 70%。
高度根据内容自动适配。
最大高度不超过视口高度的 70%。
内容实在显示不下时才启用滚动条。
```

定位建议：

```text
优先显示在鼠标右下方。
如果右侧空间不够，向左翻转。
如果下方空间不够，向上翻转。
允许浮窗盖住其他区域。
浮窗不参与页面布局，不应推挤标题区或会话区。
```

## 7. 服务接口设计

备注需要写入本地文件，所以必须通过本地 server 提供接口。

建议新增接口：

```text
GET /api/notes
POST /api/notes
DELETE /api/notes
```

### 7.1 GET /api/notes

用途：

```text
页面加载后读取全部备注。
如果 notes 文件不存在，返回空 notes。
```

返回示例：

```json
{
  "ok": true,
  "version": 1,
  "notes": {}
}
```

### 7.2 POST /api/notes

用途：

```text
新建或编辑备注。
```

请求字段：

```text
key
type
workspace
title
path
sessionId
note
```

服务端校验：

```text
key 不能为空。
type 必须是 group 或 session。
note trim 后不能为空。
note 不能超过长度上限。
```

### 7.3 DELETE /api/notes

用途：

```text
删除备注。
```

请求字段：

```text
key
```

删除不存在的 key 可以返回成功，保持幂等。

### 7.4 静态打开页面时的处理

如果用户直接双击 HTML，而不是通过 `Open-CodexChatIndex.cmd` 打开：

```text
GET /api/notes 会失败。
POST /api/notes 会失败。
DELETE /api/notes 会失败。
```

页面应处理为：

```text
备注读取失败时，不影响主页面浏览。
右键尝试保存备注时提示：请通过 Open-CodexChatIndex.cmd 打开以编辑备注。
不能因为备注接口失败导致会话无法打开。
```

## 8. 性能和内存考虑

备注功能应避免影响打开速度和滚动流畅度。

设计原则：

```text
notes.json 独立加载，不阻塞主索引渲染。
备注一般体积很小，加载后保存在内存 Map 中。
标题区渲染时只判断当前标题项是否有备注，不渲染所有备注浮窗。
浮窗 DOM 全局只保留一个，hover 时复用。
右键菜单 DOM 全局只保留一个，右键时复用。
备注弹窗 DOM 全局只保留一个，打开时复用。
```

预期性能影响：

```text
页面打开会多一次 GET /api/notes。
如果备注数量正常，影响可以忽略。
滚动时不会额外渲染大量隐藏 DOM。
标题区 hover 时才更新浮窗内容。
```

备注很多时的处理：

```text
即使有几千条备注，notes.json 也应远小于 search.json 和 cache.json。
如果未来 notes.json 变大，再考虑按工作目录分片。
V0.13 暂不做分片，避免过度设计。
```

## 9. 副作用和风险

### 9.1 右键默认菜单被替换

标题区标题项右键后会出现软件自己的备注菜单，而不是浏览器默认菜单。

可能影响：

```text
用户不能在标题项上直接右键使用浏览器默认复制菜单。
```

应对：

```text
只在标题项上拦截右键。
页面其他区域仍保留浏览器默认右键。
如后续需要，可以在备注菜单里增加“复制标题”或“复制路径”。
V0.13 先不增加，避免扩大范围。
```

### 9.2 新增用户数据文件

V0.13 会新增：

```text
软件\运行数据\CodexChatIndex.notes.json
```

可能影响：

```text
用户清理运行数据时如果误删 notes 文件，会丢失备注。
迁移软件时如果只复制版本目录而不复制运行数据，会漏掉备注。
```

应对：

```text
文档明确 notes 文件属于运行数据。
不要把 notes 文件放进临时文件_可清理。
后续如果做备份功能，应把 notes 文件纳入备份。
```

### 9.3 标题 key 变化导致备注匹配不到

大标题备注按“工作目录 + 标题全文”绑定。

可能影响：

```text
如果同一个会话的标题提取规则以后改变，旧备注可能匹配不到新标题。
如果用户移动工作目录，旧备注也可能匹配不到。
```

应对：

```text
V0.13 保存备注时保留 workspace、title、path 等可读字段，便于未来迁移。
子标题备注优先按 session path 或 session key 绑定，稳定性更高。
如果未来标题提取规则大改，再设计 notes 迁移工具。
```

### 9.4 大标题备注可能覆盖同组多个分支

同一工作目录下相同标题会被聚合成一个大标题。

可能影响：

```text
给大标题写备注时，备注代表整个标题组，不代表某一个具体分支。
```

应对：

```text
这是当前标题区聚合逻辑的自然结果。
如果要标记具体分支，应在子标题或分支标题上写备注。
```

### 9.5 自定义浮窗可能遮挡内容

备注浮窗允许盖住其他区域。

可能影响：

```text
备注较长时可能挡住目录区、标题区或会话区。
```

应对：

```text
这是用户明确可接受的方向。
浮窗离开 hover 项后自动消失。
超过视口最大尺寸时才出现滚动条。
```

### 9.6 备注保存失败需要明确提示

备注写入依赖本地 server。

可能影响：

```text
直接打开 HTML 时无法保存备注。
文件被占用或权限异常时保存失败。
```

应对：

```text
读取失败不阻塞浏览。
保存失败不关闭弹窗。
toast 或弹窗内显示可理解的失败原因。
```

## 14. 修复记录：备注弹窗初始误显示

修复日期：2026-05-13

问题现象：

```text
打开 V0.13 页面后，新建备注弹窗会一直显示在页面前面。
```

根因：

```text
noteModal 元素本身带有 hidden 属性，但 .note-modal CSS 中设置了 display: flex。
作者样式覆盖了浏览器默认的 [hidden] { display: none; } 行为，导致 hidden 属性存在但弹窗仍被显示。
同类风险也存在于 noteContextMenu 和 noteTooltip。
```

修复：

```text
为 .note-menu[hidden]、.note-modal[hidden]、.note-tooltip[hidden] 增加 display: none !important。
新增自动化回归测试，防止后续再次被 display:flex 覆盖。
重新生成 V0.13 HTML。
```

复核：

